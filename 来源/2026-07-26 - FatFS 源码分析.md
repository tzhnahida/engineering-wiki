## 核心结构体（源码精确，`ff.h:150-240`）

### FATFS — 文件系统卷

```c
typedef struct {
    BYTE  fs_type;      // 文件系统类型 (0:未挂载)
    BYTE  pdrv;         // 物理驱动器号
    BYTE  ldrv;         // 逻辑驱动器号 (FF_FS_REENTRANT)
    BYTE  n_fats;       // FAT 表数量 (1 或 2)
    BYTE  wflag;        // win[] 脏标志 (b0:dirty)
    BYTE  fsi_flag;     // FSINFO 脏标志 (b7:disabled, b0:dirty)
    WORD  id;           // 卷挂载 ID（每次 mount 递增，反损坏校验）
    WORD  n_rootdir;    // 根目录项数 (FAT12/16)
    WORD  csize;        // 簇大小 [扇区]
#if FF_MAX_SS != FF_MIN_SS
    WORD  ssize;        // 扇区大小 (512/1024/2048/4096)
#endif
    WCHAR* lfnbuf;      // LFN 工作缓冲区 (FF_USE_LFN)
    DWORD last_clst;    // 上次分配簇（分配提示，invalid if >= n_fatent）
    DWORD free_clst;    // 空闲簇数 (invalid if >= n_fatent-2)
    DWORD cdir;         // 当前目录起始簇 (FF_FS_RPATH, 0:root)
    DWORD n_fatent;     // FAT 表项总数 (= 簇数 + 2)
    DWORD fsize;        // 每 FAT 扇区数
    LBA_t winsect;      // win[] 中当前缓存的扇区号
    LBA_t volbase;      // 卷起始扇区
    LBA_t fatbase;      // FAT 表起始扇区
    LBA_t dirbase;      // 根目录起始 (FAT12/16:扇区, FAT32/exFAT:簇)
    LBA_t database;     // 数据区起始扇区
#if FF_FS_EXFAT
    LBA_t bitbase;      // 分配位图起始扇区
    BYTE* dirbuf;       // 目录项块缓冲区
#endif
    BYTE  win[FF_MAX_SS]; // ⭐ 单扇区窗口 — FatFS 最核心的设计决策
} FATFS;
```

### FFOBJID — 对象基类（`ff.h:195-212`）

```c
typedef struct {
    FATFS* fs;          // 所属卷指针
    WORD   id;          // 打开时的卷挂载 ID（值与 FATFS::id 匹配时有效）
    BYTE   attr;        // 对象属性 (AM_DIR/AM_ARC/...)
    BYTE   stat;        // 链状态 (exFAT: b1-0 连续/碎片化, b2 子目录拉伸)
    DWORD  sclust;      // 数据起始簇 (0:无数据或根目录)
    FSIZE_t objsize;    // 对象大小 (sclust != 0 时有效)
#if FF_FS_EXFAT
    DWORD n_cont;       // 首段连续大小-1 (stat==3 时有效)
    DWORD n_frag;       // 末段待写入 FAT 的大小
    DWORD c_scl;        // 所在目录的簇号
    DWORD c_size;       // 所在目录的大小
    DWORD c_ofs;        // 条目在目录中的偏移
#endif
} FFOBJID;
```

**`FIL` 和 `DIR` 均以 `FFOBJID` 为第一个成员** → C 结构体继承。`f_open` 通过 `fp->obj.id == fp->obj.fs->id` 检查文件对象是否仍有效（卷是否被卸载重挂载）。

### FIL — 文件对象（`ff.h:218-240`）

```c
typedef struct {
    FFOBJID obj;        // ⬅ 第一个成员，实现继承
    BYTE   flag;        // 文件状态标志 (FA_READ/FA_WRITE/FA_DIRTY/...)
    BYTE   err;         // 异常中止标志
    DWORD  fptr;        // 文件读写指针（字节偏移）
    DWORD  clust;       // 当前簇号 (fptr 所在簇, invalid when fptr=0)

#endif

} FIL;
```

## `create_chain()` 真身（`ff.c:1539-1598`）— 修正验证

```c
static DWORD create_chain (FFOBJID* obj, DWORD clst)
{
    // 返回值: 0=无空闲簇, 1=内部错误, 0xFFFFFFFF=磁盘错误, ≥2=新簇号

    if (clst == 0) {                    // 创建新链
        scl = fs->last_clst;            // 从上次分配位置搜索（空间局部性优化）
        if (scl == 0 || scl >= fs->n_fatent) scl = 1;
    } else {                            // 延伸已有链
        cs = get_fat(obj, clst);        // 读 FAT[clst]
        if (cs < 2) return 1;           // ❌ 0或1 → insanity（不应出现）
        if (cs == 0xFFFFFFFF) return cs; // ❌ 磁盘错误
        if (cs < fs->n_fatent) return cs; // ✅ 链已续接，返回下一簇号
        scl = clst;                      // EOC → 需要延伸链
    }
    if (fs->free_clst == 0) return 0;    // 无空闲簇

    // FAT32 上：尝试 clst+1 是否为连续空闲簇
    if (scl == clst) {
        ncl = scl + 1;
        if (ncl >= fs->n_fatent) ncl = 2;
        cs = get_fat(obj, ncl);
        if (cs == 1 || cs == 0xFFFFFFFF) return cs;
        if (cs != 0) { ncl = 0; }        // 不连续，回退到线性搜索
    }
    // 线性搜索空闲簇 ...
}
```

**关键理解**：
- 判断"需要延伸链"的核心条件是 `cs >= fs->n_fatent`（即 cs 是 EOC 标记如 0x0FFFFFFF）
- 原 Web 研究页面的 `ncl < 2 → EOF` **完全错误**：< 2 是"insanity"错误返回，不是 EOF
- 函数还尝试**顺序分配优化**：先检查 `clst+1` 是否空闲，避免 FAT 碎片化

## `f_open()` 核心流程（`ff.c:3978-4120`，~140行）

```
f_open(fp, path, mode)
  → find_volume(&path)    // 解析 "0:/" 前缀，挂载卷
  → follow_path(dj, path)  // 沿目录树遍历
      → create_name()     //   LFN → SFN + 校验和
      → dir_find()        //   在当前目录中查找名称
      → dir_next()        //   遍历目录项
  → dir_register()        // 如需创建，分配空目录项
  → ld_clust(fs, dir)     // 加载文件簇链到 FIL
  → sync_window()         // 回写脏扇区
```

## 与 Web 研究页面的差异总览

| 原页面声明 | 源码真相 (R0.16) |
|-----------|-----------------|
| `create_chain` 中 `ncl < 2 → EOF` | ❌ `cs < 2 → return 1 (insanity error)`；EOF 由 `cs >= n_fatent` 判断 |
| FATFS 无 `id` 字段 | ❌ 有 `WORD id`，每次 mount 递增，用于反损坏校验 |
| FATFS 无 `ssize` | ❌ 条件编译 `#if FF_MAX_SS != FF_MIN_SS` |
| `FFOBJID` 未提及 | ❌ 核心基类，含 `id` 校验字段和 exFAT 碎片跟踪 |
| 单扇区为固定 512B | ⚠️ 实际为 `FF_MAX_SS`（默认512，可配 1024/2048/4096） |
| `~6000 行` | ⚠️ R0.16 实际 7,249 行 |
| `DIR`/`FIL` 结构体独立 | ⚠️ 均嵌入 `FFOBJID` 作为第一个成员（C 继承模式） |
