# LittleFS 源码分析

## 基本信息

| 项目 | 内容 |
|------|------|
| **名称** | LittleFS |
| **仓库** | `littlefs-project/littlefs` (GitHub) |
| **语言** | C99 |
| **版本** | v2.11 (`LFS_VERSION = 0x0002000b`) |
| **磁盘版本** | v2.1 (`LFS_DISK_VERSION = 0x00020001`) |
| **许可** | BSD-3-Clause |
| **定位** | 专为 NOR Flash 设计的嵌入式文件系统：断电韧性、磨损均衡、有界 RAM |

## 源码验证发现

### 修正的错误

| 原声明 | 修正 |
|--------|------|
| `lfs_t` 包含内联 `struct lfs_global { uint8_t moving[2]; }` | 实际为 `lfs_gstate_t gstate, gdisk, gdelta` 三个字段，通过 XOR 组合进行跨元数据对的原子状态传播 |
| 前瞻缓冲区与超级块一起序列化 | 错误 — 挂载时丢弃，首次分配时通过 `lfs_fs_traverse_` 重建 |
| 标签有效位固定为 1 | 实际为 XOR 编码：`lfs_tobe32((tag & 0x7fffffff) ^ ptag)` |

### 确认的设计

| 声明 | 源码验证 |
|------|---------|
| 双块原子提交 + CRC 验证 | ✅ `lfs_dir_fetchmatch` (280 行) |
| CTZ skip-list O(log n) 查找 | ✅ `lfs_ctz_find` 使用 `lfs_ctz` + `lfs_npw2` |
| COW 有界连锁 | ✅ COW 止于一个元数据对 |
| `block_cycles` 迁移 | ✅ `lfs_dir_needsrelocation` 检查 `(rev % (block_cycles+1)\|1)` |

### 关键遗漏

- **`compact_thresh`**（v2.11 新增）：元数据压缩阈值，默认 ~88% block_size
- **`metadata_max`**：限制压缩后元数据对大小，控制压缩延迟
- **`lfs_ctz_index` 公式**：`i = (size - 4*(lfs_popc(i-1)+2)) / (block_size - 8)` 实现偏移量到块索引的转换
- **文件刷新的两阶段提交**：`lfs_bd_sync` → `lfs_dir_commit`，数据先落盘再更新元数据
- **目录分裂机制**：`lfs_dir_split` + `lfs_dir_splittingcompact`，元数据对满时触发

## 总体评估

现有 4 页 LittleFS 知识页面整体质量良好，DESIGN.md 和 SPEC.md 本身已提供丰富的文档。主要差异在于：
- 部分结构体定义与源码不完全一致（已修正）
- 前瞻缓冲区持久化声明有误（已修正）
- 缺少 v2.11 新增的配置参数 `compact_thresh`/`metadata_max`
- CTZ 查找方向和目录分裂机制值得补充
