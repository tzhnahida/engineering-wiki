# LVGL 源码分析

## 基本信息

| 项目 | 内容 |
|------|------|
| **名称** | LVGL (Light and Versatile Graphics Library) |
| **仓库** | `lvgl/lvgl` (GitHub) |
| **语言** | C99 |
| **版本** | v9.x (development) |
| **许可** | MIT |
| **定位** | 嵌入式 GUI 框架：纯 C OOP 对象系统 + 脏矩形渲染管道 + 可插拔绘制后端 |

## 源码验证要点

对比 Web 研究页面与实际源码：

| 声明 | 源码验证 |
|------|---------|
| `lv_obj_class_t` 含 `dispatch_event_cb` | ❌ 不存在 — 事件通过 `event_cb` + `LV_EVENT_*` 处理 |
| `lv_obj_class_t` 含 `create_obj` | ❌ 不存在 — 创建通过 `lv_obj_class_create_obj()` 通用工厂 |
| `instance_size` 类型为 `size_t` | ❌ 实际为 `uint32_t : 16` 位域 |
| `lv_obj_t` 含 `lv_flag_t flags` / `lv_state_t state` | ❌ 实际使用独立位域成员（hidden/clickable/scrollable 等） |
| Draw Unit 优先级架构 | ✅ 确认：`unit_head` 链表 + `supported_score` |
| 脏区合并引擎 `lv_refr_join_area()` | ✅ 确认：静态函数在 `lv_refr.c` 中 |

## 架构关键设计

1. **对象系统**：每个 widget 以 `lv_obj_t` 为第一个成员实现 C 继承，`class_p` → `base_class` 链模拟虚函数表
2. **渲染管道**：`lv_obj_invalidate()` → `lv_refr_join_area()` 合并脏区 → Tile 拆分 → Draw Unit 调度 → flush_cb
3. **Draw Unit**：插件化绘制后端，通过优先级竞争获取任务，默认软件渲染器优先级最低
4. **样式系统**：多级级联（本地 → 对象 → 父继承 → 主题），状态匹配优先于添加顺序
