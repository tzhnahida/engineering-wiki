# 2026-08-28 - STM32L4 双存储固件逆向

> 用户自有 Reverse Engineering 战役 #2 的完整产物摘要(报告完成于 2026-08-24)。盲逆向(无设备背景、无原理图)。原始报告与全部分析工件已归档于 `_llm/raw/stm32l4-re/`(自 `Clippings/逆向2/` 迁移)。

## 对象与结论速览

| 项目 | 结论 |
|------|------|
| 对象 | 一台带 4MB 外部 SPI NOR 的 **STM32L4 系列**设备(Cortex-M4),固件 = bootloader(11.5KB)+ app(126.5KB)两段式,无可读字符串 |
| 镜像 | `Clippings.bin` 256 KiB(内部 flash)+ `fmtOK2.bin` 4 MiB(外部 NOR) |
| 家族判定链(全部已确认) | M4 指令 `mls`;GPIO@0x48000000;RCC+0x4C=AHB2ENR;RCC+0x58=APB1ENR1(bit25=CAN1EN);PLLCFGR 复位值 0x1000;bxCAN@0x40006400 → **STM32L4 锁定**(F3/GD32/G4 均排除);⚠️ 精确型号存疑 |
| 通信 | CAN1(PA11/PA12,AF9,IRQ20)+ RTC + 5 组 EXTI + TIM1(主循环 tick)+ SPI2 |
| 内部布局 | boot 0x0–0x2E0;app 0x5000–0x24A00(链接基址 0x08005000);记录区 0x38800–0x3C000(5×256B);数据块 0x3C000–0x3DE00(尾 0xAAAAAAAA 标记) |
| NOR 布局 | 升级头 @0x32000 = `{u32 size 大端, u16 crc 大端}` = `00 02 58 00 BD D5`;载荷 @0x32100 与内部 app **逐字节一致**(0 差异);记录 @0x64000(9 字节非 FF);数据块 @0x66000 |
| 序列号 | 内部 0x803A800:`BBEC921050905776`(16 字符 ASCII,已确认) |

## 升级/备份机制(数值级实锤)

- **升级例程 0x246C**:读 NOR 头 → size 校验(合法值 ≤0x40 / 0x25800 / 0x25840)→ 擦内部 2KB 页(0x640)→ NOR→内部复制 → 对内部副本重算 **MODBUS CRC16** → 与头 CRC 比对(失败返回 1,状态机不推进)
- **备份例程 0x20C**:boot 状态字 @0x803B000 > 4 时,擦 NOR 50×4KB 扇区,把内部 app(150KB)带 CRC 头整体备份到 NOR 0x32000/0x32100
- **CRC 还原(实锤)**:poly 0x8005,init 0xFFFF;**逐字节 RBIT(0x21AA)→ MSB-first 位循环(0x2FC)→ 16 位 RBIT(0x2182)** = 标准 MODBUS CRC16(反射 poly 0xA001);对 dump 计算得 **0xBDD5** == NOR 头 ✓(这就是 RE#1 时代"CRC 语义难还原"的坑:反射输入用 RBIT 显式实现)
- app 侧特性:RLE 压缩 .data + 16B 初始化表执行器;64 位软件除法;事件分发框架(RAM 函数指针表)

## 锁死机制(2026-08-24 实测)

- 设备存在"锁死"状态(表现不开机,非固件损坏);**实测两种解锁均成功**:① 向外部 NOR 刷入好镜像;② 直接换一片正常 NOR 芯片
- 锁存在 **NOR 内容**而非内部 flash(boot 状态字 = 1 且 state=1 时 boot 不读 NOR → 由 app 层检查);MCU 与 NOR **不绑定**
- 锁标志候选:NOR 0x64000 `{u32 60, u32 48, u8 108}`(60+48=108 校验和模式,⚠️ 推测:使用次数/信用耗尽型);0x66000 7.5KB 数据块(⚠️ 语义存疑)
- 与逆向1 同架构:锁存持久化在外部 flash,重刷/换片即解锁;⚠️ 同样安全前提——真实故障未排除则解锁后会再锁
