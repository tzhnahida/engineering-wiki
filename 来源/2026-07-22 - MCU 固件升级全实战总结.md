# 嵌入式 MCU 固件升级全实战总结

> 来源：微信公众号，2026-07-22 抓取

## 概述

本文是 MCU 固件升级（IAP/OTA）的全实战复盘，从架构选型、协议适配、校验安全、分区落地、异常排查全维度系统梳理。摒弃碎片化知识点，覆盖从"能用"到"量产可靠"的完整知识体系。

定义：**IAP** = 本地协议直连升级（串口/I2C/SPI/CAN）；**OTA** = 无线远程升级（WiFi/蓝牙/4G/NB-IoT）。

## 五架构对比

| 架构 | 收固件 | 擦写搬运 | 安全性 | 适用场景 |
|------|--------|----------|--------|----------|
| 思路一：Boot 全包 | Boot | Boot | ❌ 断电变砖 | 仅产线串口调试 |
| 思路二：Boot 收+备份区搬 | Boot | Boot | ✅ 备份区保护 | 串口 IAP，不推荐 OTA |
| 思路三：A/B 双分区 | Boot | Boot | ✅ 无损回滚 | IAP+OTA，工业/车载首选 |
| 思路四：APP 收+Boot 搬 | APP | Boot | ✅ 职责分离 | 全场景通用，最主流 |
| 思路五：APP 直写 A/B | APP | APP | ✅ 引导极简 | Flash 充足设备首选 |

## 核心要点

### 传输协议
- **串口 + Ymodem**：本地 IAP 首选，上位机原生支持，零开发成本
- **I2C/SPI**：板内短距升级，自研私有帧格式
- **CAN**：工业/车载组网批量升级，抗干扰极强
- **无线 OTA**：全自定义协议 + 加密 + 断点续传

### 三层校验体系
1. **包级 CRC**：传输过程实时拦截错误包
2. **整包 CRC32 + 魔数 + 长度**：接收完成全局兜底
3. **RSA 签名验签**：防篡改、防非法刷机（高安全量产标配）

### 分区方案（512KB Flash 基准）
- **单备份区**：Boot(32K) + APP(416K) + Backup(32K) + Flag(8K) + DCD(8K)
- **A/B 双分区**：Boot(32K) + APP_A(192K) + APP_B(192K) + Flag(16K) + DCD(8K)
- **差分升级**：基于 A/B 双分区扩展独立补丁缓存区

### 跳转方式
- **系统复位**：最稳定，通用推荐
- **内核复位**：保留外设状态，风险高——DMA/定时器残留易引发异常
- **直接地址跳转**：需手动清理全部环境，风险最高

### 防变砖准则
- 禁止边接收边擦写运行分区
- APP 校验 + Boot 二次校验双层兜底
- 升级状态存独立 Flash 扇区，断电不丢失
- 高可靠产品优先 A/B 双分区
