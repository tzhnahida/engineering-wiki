# 函数指针，嵌入式状态机的灵魂

> 来源：微信公众号「学嵌入式的长路」，2026-07-23 抓取

## 概述

本文从函数指针的声明语法讲起，到 HAL 库回调注册的实战模式，再到用函数指针表替代 switch-case 实现数据帧接收状态机。核心观点：**函数指针的威力不在语法，在于调用方和实现方在编译时解耦、在运行时组合**——这是从「写代码」到「设计代码」的分水岭。

## 核心要点

### 声明口诀
把函数声明中的函数名换成 `(*p)` → `void (*pFunc)(uint32_t ms);`

### typedef 简化
`typedef void (*Handler)(int);` → 之后声明函数指针变量跟声明 `int` 一样简单

### HAL 库回调机制
- STM32 HAL 通过 weak 函数提供默认回调，用户覆盖实现
- 更灵活的方式：函数指针表注册——多个定时器绑定不同回调 + 传自定义参数

### 函数指针表状态机
- 状态枚举值直接作为数组索引：`state = state_table[state](byte, &ctx);`
- 一条语句替代整个 switch-case——查表 → 调用 → 更新状态
- 必须加 `const` 让表放 Flash 而非 RAM

### 四个坑
1. 中断回调只做标记不放耗时操作
2. 不要对函数指针强制类型转换（栈帧错乱 → HardFault）
3. 函数指针表不加 const → 浪费 RAM
4. 函数指针大小平台相关（M0: 2B, M3/4: 4B, AArch64: 8B）
