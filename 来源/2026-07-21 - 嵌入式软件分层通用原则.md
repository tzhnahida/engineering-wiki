# 嵌入式软件分层通用原则

> 来源：微信公众号「崔工漫谈嵌入式」，2026-07-21 抓取

## 概述

本文讨论嵌入式软件分层的通用原则，以 MCU 裸机或 RTOS 项目为例，介绍一套可落地的六层架构。适用于 STM32、GD32、NXP、ESP32 等平台。

## 核心观点

**分层的本质**：通过明确职责边界和依赖方向，隔离变化传播，降低维护成本。

嵌入式项目面临四类变化：平台变化（MCU 更换、HAL 升级）、板级变化（GPIO 调整、DMA 通道）、设备变化（传感器更换）、业务变化（控制策略升级）。不分层的后果是变化无序蔓延。

## 六层架构

| 层 | 职责 | 一句话 |
|---|---|---|
| **app** | 业务流程/状态机/命令处理 | "做什么" |
| **service** | 通用服务：协议/日志/参数管理 | 可复用能力层 |
| **device** | 抽象外部器件：传感器/Flash/电机 | 屏蔽总线细节 |
| **bsp** | 封装 MCU 片上资源：GPIO/UART/SPI | "这块板子怎么用" |
| **platform** | HAL/CMSIS/RTOS/启动文件 | 尽量少改 |
| **component** | 横向复用：RingBuffer/CRC/PID/状态机 | 与业务和硬件无关 |

## 七条核心原则

1. **单一职责** — 设备驱动只做设备访问，不混业务
2. **高内聚低耦合** — 改内部实现不影响上层
3. **接口清晰** — 禁止 extern 全局变量穿透
4. **隐藏实现细节** — 上层只关心"是否成功"而非 I2C 还是 SPI
5. **禁止越层访问** — app 不能直接调 HAL
6. **可替换** — 换传感器业务逻辑不动
7. **面向接口编程** — 依赖稳定抽象，不依赖具体实现

## 关键区分

**初始化关系 ≠ 运行期调用关系**。初始化由 `main` 统一编排（`bsp_board_init → device_init_all → service_init_all → app_init → app_start`），`app_init()` 不应直接调用 `bsp_board_init()`。
