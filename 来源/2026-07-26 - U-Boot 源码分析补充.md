# U-Boot 源码分析

| 项目 | 内容 |
|------|------|
| **名称** | Das U-Boot (Universal Boot Loader) |

| **定位** | 通用嵌入式引导加载程序，支持 SPL → U-Boot → Kernel 三级启动 |

## 关键源文件（shallow clone 分析）

### 核心初始化序列

| 文件 | 行数 | 功能 |
|------|------|------|
| `common/board_f.c` | 1,142 | 前重定位初始化（init_sequence_f）：时钟/内存/串口 |
| `common/board_r.c` | 810 | 后重定位初始化（init_sequence_r）：MMC/网络/PCIe |
| `common/main.c` | 89 | 主循环：preboot → bootdelay → autoboot → CLI |

### 主循环源码（`common/main.c`）

```c
void main_loop(void) {
    cli_init();                              // CLI 子系统初始化
    run_preboot_environment_command();       // 执行 $preboot 环境变量
    bootdelay_process();                     // 倒计时 → autoboot
    autoboot_command(s);                     // 自动引导（$bootcmd）
    if (CONFIG_BOOTSTD_PROG)                 // 标准引导程序
        bootstd_prog_boot();
    cli_loop();                              // 交互式 CLI（Hush Shell）
    panic("No CLI available");
}
```

每个阶段通过 `IS_ENABLED(CONFIG_*)` 条件编译，不使用的功能完全移除。

### Driver Model (`include/dm/device.h`)

| 标志位 | 含义 |
|--------|------|
| `DM_FLAG_ACTIVATED` (0) | 设备已探测（probe 完成） |
| `DM_FLAG_PRE_RELOC` (2) | 重定位前就需初始化的设备 |
| `DM_FLAG_BOUND` (6) | 设备已绑定（bind 完成） |
| `DM_FLAG_OF_PLATDATA` (8) | 使用 of-platdata（无 DTB 模式） |
| `DM_FLAG_OS_PREPARE` (10) | OS 启动前需执行 remove() 清理 |

14 个标志位精细控制设备从 bind → probe → remove → OS prepare 的完整生命周期。

## 总体代码规模

`common/` 目录含 59 个 .c 文件，是 U-Boot 最核心的目录。`drivers/` 目录包含数百个设备驱动。完整源码仓库 > 500MB，shallow clone 选取 common/drivers 核心目录即可满足分析需求。
