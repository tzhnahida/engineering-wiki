# SlimeVR VQF 姿态解算

## 一句话

> SlimeVR 固件选择 VQF（非 Madgwick）作为融合引擎——解耦式三模块架构天然支持 6D/9D 切换，内置陀螺偏置估计和静止检测。

## 为什么选 VQF

SlimeVR 社区在 2023 年从 Madgwick 迁移到 VQF，核心原因：

| 维度 | Madgwick | VQF |
|------|----------|-----|
| 架构 | 单步梯度下降 | 三模块解耦（Tilt → Gyro → Mag） |
| 偏置估计 | 需要额外逻辑 | 内置陀螺偏置在线估计 |
| 磁干扰处理 | 依赖参数 β | 独立磁校正模块，可启用/禁用 |
| 6D/9D 切换 | 需重新初始化 | 运行时无缝切换（`magExist` 标志） |
| 静止检测 | 无 | 内置 `getRestDetected()` |
| 静态精度 | ~0.6° RMS | ~0.011° (典型) |
| 计算量 | 109 标量运算/更新 | 相当 |

> 详见 [[姿态解算/VQF 姿态解算滤波器]] 对 VQF 算法原理的深度分析。

## SlimeVR 中的 VQF 参数

```cpp
// SensorFusion.h — 默认 VQF 参数
constexpr VQFParams DefaultVQFParams = VQFParams{
    .tauAcc    = 2.0f,    // 加速度低通时间常数 (s)
    .restMinT  = 2.0f,    // 静止检测最小持续时间 (s)
    .restThGyr = 0.6f,    // 静止检测陀螺阈值 (dps)
    .restThAcc = 0.06f,   // 静止检测加速度阈值 (g)
};
```

| 参数 | 值 | 作用 |
|------|-----|------|
| `tauAcc` | 2.0s | 加速度计 LPF 时间常数——更大=更平滑但响应慢 |
| `restMinT` | 2.0s | 连续静止 2s 才触发静止检测 |
| `restThGyr` | 0.6 dps | 陀螺幅值低于此阈值判定为静止 |
| `restThAcc` | 0.06g | 加速度幅值变化低于此阈值辅助静止判定 |

`tauAcc=2.0s` 是激进滤波——VRChat 动捕不需要亚度级精度，但需要输出稳定（抖动会被骨骼解算放大）。对比学术场景（`tauAcc=0.5s`），SlimeVR 牺牲响应速度换稳定性。

## 6D vs 9D 融合模式

```cpp
// 6D 模式（无磁力计）
void SensorFusion::update6D(Axyz[3], Gxyz[3], deltat) {
    vqf.updateAcc(Axyz);       // 倾斜校正（重力向量 = 俯仰+横滚）
    vqf.updateGyr(Gxyz, deltat); // 陀螺积分（偏航+俯仰+横滚）
    // 偏航角靠陀螺积分 → 会漂移，但无需磁力计
}

// 9D 模式（有磁力计）
void SensorFusion::update9D(Axyz[3], Gxyz[3], Mxyz[3], deltat) {
    vqf.updateMag(Mxyz);       // 磁偏校正（稳定偏航角）
    vqf.updateAcc(Axyz);       // 倾斜校正
    vqf.updateGyr(Gxyz, deltat); // 陀螺积分
    // 偏航角有绝对参考 → 不漂移，但受磁场干扰
}
```

**磁力计自动检测**：`magExist` 标志在首次读到非零磁力计数据后自动切换 9D 模式。SlimeVR Server 也可以通过 `SensorToggles` 远程启用/禁用磁力计。

## 四元数输出

```cpp
// SensorFusion.cpp
sensor_real_t const* SensorFusion::getQuaternion() {
    if (magExist) {
        vqf.getQuat9D(qwxyz);  // [w, x, y, z] — 含磁校正
    } else {
        vqf.getQuat6D(qwxyz);  // [w, x, y, z] — 仅倾角
    }
    return qwxyz;
}

// 包装为 SlimeVR Quat 类型（x, y, z, w 顺序）
Quat SensorFusion::getQuaternionQuat() {
    getQuaternion();
    return Quat(qwxyz[1], qwxyz[2], qwxyz[3], qwxyz[0]);
}
```

> ⚠️ VQF 内部存储为 `[w, x, y, z]`，SlimeVR 包格式为 `[x, y, z, w]`（大端序 float），发送前做重排。

## 重力向量提取与线性加速度分离

```cpp
// 重力向量：从四元数旋转全局重力到传感器坐标系
void calcGravityVec(const qwxyz[4], gravVec[3]) {
    gravVec[0] = 2*(q1*q3 - q0*q2);  // x 分量
    gravVec[1] = 2*(q0*q1 + q2*q3);  // y 分量
    gravVec[2] = q0² - q1² - q2² + q3²;  // z 分量
}

// 线性加速度 = 原始加速度 - 重力分量 × g
void calcLinearAcc(const accin[3], gravVec[3], accout[3]) {
    accout[i] = accin[i] - gravVec[i] * CONST_EARTH_GRAVITY;
}
```

这个线性加速度提取用于 Accel 包（type 4），可选发送给 SlimeVR Server 做辅助追踪。

## 数据发送时机

```cpp
// Sensor::sendData() — 默认实现
void Sensor::sendData() {
    if (newFusedRotation) {
        networkConnection.sendRotationData(
            sensorId, &fusedRotation,
            DATA_TYPE_NORMAL,  // 或 DATA_TYPE_CORRECTION
            calibrationAccuracy
        );
        newFusedRotation = false;
    }
    if (newAcceleration) {
        networkConnection.sendSensorAcceleration(sensorId, acceleration);
        newAcceleration = false;
    }
}
```

> ⚠️ 代码观察：`sendRotationData` 每次发一个传感器的数据到独立 UDP 包（无 Bundle 时）。多传感器场景用 Bundle 合并为一个 UDP 数据报减少开销。
