# SlimeVR 固件概述与架构

## 一句话

> 裸机主循环顺序调度 7 个子系统：传感器读取 → VQF 融合 → UDP 发包，µs 级定时保证稳定帧率。

## 系统架构图

![[SlimeVR 固件系统架构.excalidraw]]

## 7 个子系统

| 顺序 | 子系统 | 全局对象 | 职责 |
|------|--------|----------|------|
| 1 | **TPSCounter** | `tpsCounter` | 帧率统计，计算平均 TPS |
| 2 | **GlobalTimer** | `globalTimer` | 全局时钟 tick，驱动定时器回调 |
| 3 | **SerialCommands** | — | 串口命令解析（调试/配置） |
| 4 | **OTA** | — | 无线固件升级 |
| 5 | **NetworkManager** | `networkManager` | UDP 服务器发现、连接维护、数据收发 |
| 6 | **SensorManager** | `sensorManager` | 传感器读取 → VQF 融合 → 四元数输出 |
| 7 | **BatteryMonitor** | `battery` | 电池电压/百分比监测 |

> 子系统按频率分组：传感器和网络每帧执行，电池/LED/串口命令可以降频。

## 主循环时序控制

```cpp
// main.cpp loop() — 微秒级软实时
loopTime = micros();
// ... 所有子系统执行 ...
long elapsed = micros() - loopTime;
if (elapsed < TARGET_LOOPTIME_MICROS) {
    long sleepus = TARGET_LOOPTIME_MICROS - elapsed - 100;
    delay(sleepms);        // ms 级 sleep（省电）
    delayMicroseconds(sleepus);  // µs 级精确补偿
}
```

`TARGET_LOOPTIME_MICROS` 由板级配置定义，典型值对应 100-200Hz 的传感器更新率。

## 启动流程

```cpp
// setup() steps in order:
ledManager.setup();                // LED 初始化
configuration.setup();             // 加载持久化配置（传感器位置、校准数据）
SerialCommands::setUp();           // 串口协议初始化
I2CSCAN::clearBus();              // I2C 总线恢复（防死锁）
Wire.begin(SDA, SCL);             // I2C 总线初始化
Wire.setTimeOut(150);             // I2C 超时 150ms
Wire.setClock(I2C_SPEED);         // I2C 时钟设置
delay(500);                       // 等待 IMU 启动
sensorManager.setup();            // 扫描 I2C → 创建传感器实例 → motionSetup()
networkManager.setup();           // 初始化 WiFi → 开始 UDP 广播搜索服务器
OTA::otaSetup();                  // OTA 服务启动
battery.Setup();                  // 电池 ADC 初始化
sensorManager.postSetup();        // 传感器后初始化（温度校准恢复等）
```

## 数据流：从传感器到四元数

Data flow stages:
1. I2C reads raw data
2. Sensor::motionLoop():
   - Read accelerometer (int16 → float, range conversion)
   - Read gyroscope (int16 → float, range conversion)
   - Read magnetometer (optional, int16 → float)
3. SensorFusion::update6D() or update9D():
   - vqf.updateAcc() → tilt correction
   - vqf.updateMag() → magnetic distortion correction (9D only)
   - vqf.updateGyr() → gyro integration + bias estimation
4. SensorFusion::getQuaternion() → [w, x, y, z]
5. Sensor::sendData():
   - networkConnection.sendRotationData(sensorId, quat, dataType, accuracy)
   - UDP → SlimeVR Server

## 与 FreeRTOS 架构的关键区别

| 维度 | SlimeVR 固件 | FreeRTOS 内核 |
|------|-------------|--------------|
| 调度 | 裸机顺序循环 | 抢占式优先级调度 |
| 并发 | 单线程，中断驱动 I2C | 多任务，PendSV 上下文切换 |
| 实时性 | µs 级 delay 软实时 | 硬件定时器 + 优先级继承 |
| 复杂度 | ~5000 行应用层 | ~20000 行内核层 |

SlimeVR 不需要 RTOS：它只有一个硬实时需求（IMU 定时采样），用 `delayMicroseconds()` 补偿循环时间足以满足 100-200Hz 的传感器更新率。
