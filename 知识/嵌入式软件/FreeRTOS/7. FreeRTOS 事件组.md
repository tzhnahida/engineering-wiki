# FreeRTOS 事件组

## 概述

事件组（Event Groups）是 FreeRTOS 提供的 **位掩码同步原语**。每个事件组维护一个 `EventBits_t` 位域（通常为 `uint32_t`），应用可将各位赋予特定含义（如"CAN 消息已收到"、"待发送消息已就绪"）。任务可以等待一个或多个位被置起，并可选择在满足条件退出时自动清除这些位。

该实现内置了原子性保护，消除了使用简单变量可能产生的竞态条件，尤其适用于 **多任务同步屏障**（rendezvous）。

## 数据结构

```c
typedef struct EventGroupDef_t
{
    EventBits_t uxEventBits;                    /* 当前事件位值 */
    List_t xTasksWaitingForBits;                /* 等待位的任务链表 */

    #if ( configUSE_TRACE_FACILITY == 1 )
        UBaseType_t uxEventGroupNumber;
    #endif

    #if ( ( configSUPPORT_STATIC_ALLOCATION == 1 ) && ( configSUPPORT_DYNAMIC_ALLOCATION == 1 ) )
        uint8_t ucStaticallyAllocated;          /* 标记是否为静态分配 */
    #endif
} EventGroup_t;
```

- **`EventBits_t`**：定义为 `TickType_t`。
  - `configUSE_16_BIT_TICKS == 0`（32 位 tick） → 24 个可用位（bit 0 ~ bit 23）
  - `configUSE_16_BIT_TICKS == 1`（16 位 tick） → 8 个可用位（bit 0 ~ bit 7）
  - 高字节（bit 24~31 或 bit 8~15）由内核用于控制位，**不允许用户操作**
- **`xTasksWaitingForBits`**：标准 FreeRTOS 链表，存放阻塞于此事件组的任务
- 控制位常量（以 32 位系统为例）：
  - `eventCLEAR_EVENTS_ON_EXIT_BIT = 0x01000000UL`
  - `eventUNBLOCKED_DUE_TO_BIT_SET = 0x02000000UL`
  - `eventWAIT_FOR_ALL_BITS = 0x04000000UL`
  - `eventEVENT_BITS_CONTROL_BYTES = 0xff000000UL`

控制位存入任务的事件列表项（`xEventListItem`）的值字段中，与等待的位一起编码。

## 创建与销毁

### xEventGroupCreate — 动态分配

```c
EventGroupHandle_t xEventGroupCreate(void);
```

- 调用 `pvPortMalloc` 分配 `EventGroup_t`
- 初始化 `uxEventBits = 0`
- 调用 `vListInitialise(&(pxEventBits->xTasksWaitingForBits))`
- 返回句柄，失败返回 `NULL`

### xEventGroupCreateStatic — 静态分配

```c
EventGroupHandle_t xEventGroupCreateStatic(StaticEventGroup_t *pxEventGroupBuffer);
```

- 用户提供预分配好的 `StaticEventGroup_t` 缓冲区（编译期分配）
- `StaticEventGroup_t` 和 `EventGroup_t` 大小相同（通过 `configASSERT` 验证）
- 初始化方式同动态版本

### vEventGroupDelete

```c
void vEventGroupDelete(EventGroupHandle_t xEventGroup);
```

- 遍历 `xTasksWaitingForBits` 链表，对所有阻塞任务调用 `vTaskRemoveFromUnorderedEventList`（返回 event 值 0）
- 根据 `ucStaticallyAllocated` 标记决定是否调用 `vPortFree`

## 核心 API

### xEventGroupWaitBits — 阻塞等待位

```c
EventBits_t xEventGroupWaitBits(EventGroupHandle_t xEventGroup,
                                 const EventBits_t uxBitsToWaitFor,
                                 const BaseType_t xClearOnExit,
                                 const BaseType_t xWaitForAllBits,
                                 TickType_t xTicksToWait);
```

**执行流程**：

1. 暂停调度器（`vTaskSuspendAll`）
2. 调用 `prvTestWaitCondition` 检测当前位是否满足条件
   - `xWaitForAllBits == pdFALSE`：ANY 模式 — `(current & waited) != 0`
   - `xWaitForAllBits == pdTRUE`：ALL 模式 — `(current & waited) == waited`
3. **条件已满足** → 若 `xClearOnExit` 则清除位，设 `xTicksToWait = 0`，直接返回
4. **条件未满足且 `xTicksToWait == 0`** → 立即返回当前位值
5. **条件未满足且 `xTicksToWait > 0`** → 进入阻塞：
   - 将 `xClearOnExit` 和 `xWaitForAllBits` 编码为控制位
   - 调用 `vTaskPlaceOnUnorderedEventList(&pxEventBits->xTasksWaitingForBits, uxBitsToWaitFor | uxControlBits, xTicksToWait)`
   - 恢复调度器；如需则调用 `portYIELD_WITHIN_API`
6. **唤醒后**：
   - 调用 `uxTaskResetEventItemValue()` 获取存储的事件值
   - 若 `eventUNBLOCKED_DUE_TO_BIT_SET` 置位 → 因位满足条件而唤醒
   - 若未置位 → 超时唤醒：
     - 进入临界区读取当前事件值
     - 如果位恰好刚刚满足条件，仍执行 `xClearOnExit` 清除
   - 返回前剥离控制字节：`uxReturn &= ~eventEVENT_BITS_CONTROL_BYTES`

**返回值**：返回事件组在唤醒/超时时刻的位值（不含控制位）。允许测试具体哪些位被设置。

### xEventGroupSetBits — 设置位并唤醒

```c
EventBits_t xEventGroupSetBits(EventGroupHandle_t xEventGroup,
                                const EventBits_t uxBitsToSet);
```

**执行流程**：

1. 暂停调度器
2. `pxEventBits->uxEventBits |= uxBitsToSet` — 原子置位
3. 遍历 `xTasksWaitingForBits` 链表：
   - 对每个任务项，提取 `uxBitsWaitedFor`（期待的位）和 `uxControlBits`（控制位）
   - **ANY 模式** (`eventWAIT_FOR_ALL_BITS` 未置位)：`(uxBitsWaitedFor & uxEventBits) != 0` 即匹配
   - **ALL 模式** (`eventWAIT_FOR_ALL_BITS` 置位)：`(uxBitsWaitedFor & uxEventBits) == uxBitsWaitedFor` 才匹配
   - 匹配后：
     - 如果 `eventCLEAR_EVENTS_ON_EXIT_BIT` 置位，将等待的位记录到 `uxBitsToClear`
     - 调用 `vTaskRemoveFromUnorderedEventList(pxListItem, pxEventBits->uxEventBits | eventUNBLOCKED_DUE_TO_BIT_SET)`
     - 注意：传递给 `vTaskRemoveFromUnorderedEventList` 的第二个参数包含 `eventUNBLOCKED_DUE_TO_BIT_SET` 标志，使任务知道它是因为位满足条件而非超时被唤醒
4. 循环结束后清除 `uxBitsToClear`：`pxEventBits->uxEventBits &= ~uxBitsToClear`
5. 恢复调度器

**返回值**：返回设置完成后的事件组位值（可能已被 `CLEAR_ON_EXIT` 机制和其它高优先级任务修改）。

### xEventGroupSetBitsFromISR — ISR 中的设置位

```c
BaseType_t xEventGroupSetBitsFromISR(EventGroupHandle_t xEventGroup,
                                      const EventBits_t uxBitsToSet,
                                      BaseType_t *pxHigherPriorityTaskWoken);
```

**注意**：设置事件位是 **非确定性操作**（不确定有多少任务正在等待）。FreeRTOS 不允许在中断或临界区中执行非确定性操作。因此：

- **默认实现**（`configUSE_TRACE_FACILITY == 0`）是一个宏，调用 `xTimerPendFunctionCallFromISR(vEventGroupSetBitsCallback, ...)`
- 实际置位操作被 **推迟到 Timer 守护任务** 的上下文中执行
- `vEventGroupSetBitsCallback` 只是一个包装，内部调用 `xEventGroupSetBits`
- 此机制保证了置位在调度器锁保护下执行

### xEventGroupClearBits

```c
EventBits_t xEventGroupClearBits(EventGroupHandle_t xEventGroup,
                                  const EventBits_t uxBitsToClear);
```

- 使用 `taskENTER_CRITICAL` / `taskEXIT_CRITICAL` 保护
- 返回清除前的位值，然后执行 `uxEventBits &= ~uxBitsToClear`

### xEventGroupClearBitsFromISR

- 同 `xEventGroupSetBitsFromISR`，通过 Timer 守护任务推迟执行
- 调用 `xTimerPendFunctionCallFromISR(vEventGroupClearBitsCallback, ...)`

### xEventGroupGetBits

```c
#define xEventGroupGetBits(xEventGroup) xEventGroupClearBits(xEventGroup, 0)
```

- 巧妙的实现：调用 `xEventGroupClearBits` 但并不清除任何位（`uxBitsToClear = 0`），从而返回当前值

### xEventGroupSync — 同步屏障

```c
EventBits_t xEventGroupSync(EventGroupHandle_t xEventGroup,
                             const EventBits_t uxBitsToSet,
                             const EventBits_t uxBitsToWaitFor,
                             TickType_t xTicksToWait);
```

**说明**：原子性地先设位、再等待其他任务到达同步点。这是多任务 **集合屏障/栅栏**（rendezvous/barrier）模式的实现。

**流程**：

1. 暂停调度器
2. 记录原始位值，调用 `xEventGroupSetBits` 设置自己的位
3. 检查所有同步位是否已全被置起：
   - **是** → 清除所有同步位，设 `xTicksToWait = 0`，返回
   - **否** → 将任务置于 `xTasksWaitingForBits` 链表，编码 `eventCLEAR_EVENTS_ON_EXIT_BIT | eventWAIT_FOR_ALL_BITS`
4. 阻塞等待；唤醒后：
   - 若 `eventUNBLOCKED_DUE_TO_BIT_SET` → 正常唤醒
   - 若超时 → 检查位是否已设置，若已设置仍执行清除
5. 剥离控制字节后返回

**关键特性**：
- 同步的位 **总是清除**（无论 `xClearOnExit` 参数）——这是 rendezvous 语义的硬性要求
- `xEventGroupSync` 等价于 `xEventGroupSetBits + xEventGroupWaitBits(xWaitForAllBits=pdTRUE, xClearOnExit=pdTRUE)`

## 阻塞/唤醒机制详解

### 任务的阻塞

`vTaskPlaceOnUnorderedEventList` 将任务放入事件组的等待链表。链表项的值编码了两类信息：

- **低字节**：任务等待的位（`uxBitsToWaitFor`）
- **高字节**：控制位（是否在退出时清除、是否等待全部位）

该函数同时将任务从就绪链表移出，放入阻塞链表。

### 任务的唤醒

`xEventGroupSetBits` 遍历等待链表，逐项检查 `prvTestWaitCondition`：

```
等待链表遍历逻辑:
  pxListItem = listGET_HEAD_ENTRY(pxList)
  pxListEnd  = listGET_END_MARKER(pxList)

  while (pxListItem != pxListEnd) {
      pxNext = listGET_NEXT(pxListItem);  // 先保存下一个节点（当前节点可能被移除）
      uxBitsWaitedFor = listGET_LIST_ITEM_VALUE(pxListItem);
      uxControlBits   = uxBitsWaitedFor & eventEVENT_BITS_CONTROL_BYTES;
      uxBitsWaitedFor &= ~eventEVENT_BITS_CONTROL_BYTES;

      if (match_found) {
          vTaskRemoveFromUnorderedEventList(pxListItem,
              uxEventBits | eventUNBLOCKED_DUE_TO_BIT_SET);
      }
      pxListItem = pxNext;
  }
```

`vTaskRemoveFromUnorderedEventList` 将任务移回就绪链表，其第二个参数的值存储在任务的事件列表项中，唤醒后由 `uxTaskResetEventItemValue()` 读取。

### `prvTestWaitCondition` — 纯位测试函数

```c
static BaseType_t prvTestWaitCondition(const EventBits_t uxCurrentEventBits,
                                        const EventBits_t uxBitsToWaitFor,
                                        const BaseType_t xWaitForAllBits)
{
    if (xWaitForAllBits == pdFALSE) {
        /* ANY 模式：任一目标位置位即满足 */
        return (uxCurrentEventBits & uxBitsToWaitFor) != 0;
    } else {
        /* ALL 模式：所有目标位都置位才满足 */
        return (uxCurrentEventBits & uxBitsToWaitFor) == uxBitsToWaitFor;
    }
}
```

## ISR 处理与 Daemon 任务

### 为什么 ISR 不能直接操作事件组？

事件组使用 `vTaskSuspendAll`（暂停调度器）而非关中断来保护临界区。这是因为设置位可能唤醒多个任务，操作时间不可预知。在 ISR 中不能暂停调度器，因此：

- **`xEventGroupSetBitsFromISR`** 通过 Timer 服务将操作推迟到守护任务上下文
- **`xEventGroupClearBitsFromISR`** 同理
- **`xEventGroupGetBitsFromISR`** 例外：只读操作，仅需关中断保护

### Timer 守护任务回调

```c
void vEventGroupSetBitsCallback(void *pvEventGroup, const uint32_t ulBitsToSet)
{
    (void)xEventGroupSetBits(pvEventGroup, (EventBits_t)ulBitsToSet);
}

void vEventGroupClearBitsCallback(void *pvEventGroup, const uint32_t ulBitsToClear)
{
    (void)xEventGroupClearBits(pvEventGroup, (EventBits_t)ulBitsToClear);
}
```

`xTimerPendFunctionCallFromISR` 将函数指针和参数压入 Timer 命令队列，Timer 守护任务在处理队列时执行回调，此时可以安全地暂停调度器。

## 典型使用模式

### 多事件等待（ANY）

```c
#define BIT_0 (1 << 0)
#define BIT_4 (1 << 4)

EventBits_t uxBits = xEventGroupWaitBits(
    xEventGroup, BIT_0 | BIT_4,  /* 等待位 */
    pdFALSE,                      /* 不清除 */
    pdFALSE,                      /* 任一即可 */
    pdMS_TO_TICKS(100));

if (uxBits & BIT_0) { /* BIT_0 被设置 */ }
if (uxBits & BIT_4) { /* BIT_4 被设置 */ }
```

### 多任务同步屏障

```c
#define TASK_0_BIT (1 << 0)
#define TASK_1_BIT (1 << 1)
#define TASK_2_BIT (1 << 2)
#define ALL_SYNC_BITS (TASK_0_BIT | TASK_1_BIT | TASK_2_BIT)

/* 每个任务在同步点调用：*/
uxReturn = xEventGroupSync(xEventBits, TASK_0_BIT, ALL_SYNC_BITS, portMAX_DELAY);

/* 所有三个任务都到达后，同步位自动清除，所有任务同时继续执行 */
```

### 生产者-消费者事件通知

```c
/* ISR：数据就绪 */
xEventGroupSetBitsFromISR(xEventGroup, DATA_READY_BIT, &xHigherPriorityTaskWoken);
portYIELD_FROM_ISR(xHigherPriorityTaskWoken);

/* 任务：等待并处理 */
xEventGroupWaitBits(xEventGroup, DATA_READY_BIT, pdTRUE, pdFALSE, portMAX_DELAY);
```

## 设计要点与约束

- **非确定性保护**：设置/清除事件位不是确定性操作（需遍历未知数量的等待任务），因此 ISR 变体必须通过 Timer 守护任务推迟执行
- **最大等待任务数**：仅受可用堆内存限制（链表节点在任务控制块中预分配）
- **无双关性**：控制位（高字节）永远不应被用户操作触及
- **与队列的比较**：事件组是位掩码原语，不传输数据，只传输状态；队列传输数据负载
- **性能**：事件组操作（设置/等待）时间复杂度取决于等待链表中任务数 O(n)
