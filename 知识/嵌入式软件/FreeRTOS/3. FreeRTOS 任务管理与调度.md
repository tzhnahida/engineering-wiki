## 一、核心数据结构

### 1.1 TCB — Task Control Block

```c
typedef struct tskTaskControlBlock
{
    volatile StackType_t * pxTopOfStack;  /* 必须为第一个成员：栈顶指针 */
    #if ( portUSING_MPU_WRAPPERS == 1 )
        xMPU_SETTINGS xMPUSettings;      /* 必须为第二个成员：MPU 设置 */
    #endif
    ListItem_t xStateListItem;            /* 状态链表项：标记 Ready/Blocked/Suspended */
    ListItem_t xEventListItem;            /* 事件链表项：用于事件等待 */
    UBaseType_t uxPriority;               /* 当前优先级（可能被优先级继承修改） */
    StackType_t * pxStack;                /* 栈底指针（分配基地址） */
    char pcTaskName[ configMAX_TASK_NAME_LEN ];

    #if ( portSTACK_GROWTH > 0 ) || ( configRECORD_STACK_HIGH_ADDRESS == 1 )
        StackType_t * pxEndOfStack;       /* 栈的高地址边界 */
    #endif

    #if ( configUSE_MUTEXES == 1 )
        UBaseType_t uxBasePriority;       /* 基础优先级（未继承时的原始值） */
        UBaseType_t uxMutexesHeld;        /* 持有的互斥量计数 */
    #endif

    #if ( configGENERATE_RUN_TIME_STATS == 1 )
        configRUN_TIME_COUNTER_TYPE ulRunTimeCounter;
    #endif

    #if ( configUSE_TASK_NOTIFICATIONS == 1 )
        volatile uint32_t ulNotifiedValue[ configTASK_NOTIFICATION_ARRAY_ENTRIES ];
        volatile uint8_t ucNotifyState[ configTASK_NOTIFICATION_ARRAY_ENTRIES ];
    #endif

    #if ( tskSTATIC_AND_DYNAMIC_ALLOCATION_POSSIBLE != 0 )
        uint8_t ucStaticallyAllocated;     /* 标记是否静态分配 */
    #endif
    /* ... 更多条件编译字段 ... */
} tskTCB;
typedef tskTCB TCB_t;
```

**关键设计要点**：

- `pxTopOfStack` 必须是 TCB **第一个成员**：PendSV 汇编代码通过 `ldr r0, [r2]` 直接读取第一个字作为栈顶指针，不依赖 C 结构体偏移计算。
- `xStateListItem` 用于将 TCB 挂入各种状态链表（Ready/Blocked/Suspended/Termination）。一个 TCB 同时只能出现在一个状态链表中。
- `xEventListItem` 用于将 TCB 挂入事件链表（如队列等待队列）。允许同时出现在状态链表和事件链表中（当任务 Blocked 在某个对象上时）。
- `xItemValue` 在两个列表中的含义不同：状态链表中存储唤醒时间（tick count），事件链表中存储优先级（`configMAX_PRIORITIES - uxPriority`，倒序）。
- `uxBasePriority` 仅在 `configUSE_MUTEXES==1` 时存在，用于优先级继承协议。

### 1.2 List_t — 调度器双向链表

```c
typedef struct xLIST
{
    volatile UBaseType_t uxNumberOfItems;
    ListItem_t * configLIST_VOLATILE pxIndex;  /* 轮转调度索引指针 */
    MiniListItem_t xListEnd;                    /* 哨兵节点，xItemValue = 最大可能值 */
} List_t;
```

```c
struct xLIST_ITEM
{
    configLIST_VOLATILE TickType_t xItemValue;  /* 排序键值 */
    struct xLIST_ITEM * pxNext;
    struct xLIST_ITEM * pxPrevious;
    void * pvOwner;            /* 指向包含本项的对象（TCB） */
    struct xLIST * pxContainer; /* 指向所属的列表 */
};
```

**设计要点**：

- 列表是环形双向链表，`xListEnd` 作为哨兵节点始终在逻辑尾部（其 `xItemValue` 为最大值）。
- `pxIndex` 用于轮转调度：`listGET_OWNER_OF_NEXT_ENTRY()` 每次调用都将 `pxIndex` 前进一个节点，跳过哨兵回到头部，实现 round-robin。
- 列表按 `xItemValue` **升序排序**。插入位置由 `vListInsert()` 保证。

定义在 `tasks.c` 文件作用域（均有 `PRIVILEGED_DATA static`）：

## 二、任务状态机

**States:**
- **Created** — TCB allocated, not yet in ready list
- **Ready** — awaiting CPU; TCB in `pxReadyTasksLists[priority]`
- **Running** — currently executing; `pxCurrentTCB` points here
- **Blocked** — waiting for event/timeout; TCB in `pxDelayedTaskList` or event list
- **Suspended** — explicitly suspended; TCB in `xSuspendedTaskList` (no pending event)
- **Suspended (indefinite block)** — blocked indefinitely; TCB in `xSuspendedTaskList` (with pending event)

**Transitions:**
- Created → Ready: `prvAddNewTaskToReadyList()`
- Ready → Running: `taskSELECT_HIGHEST_PRIORITY_TASK()`
- Running → Ready: scheduler preemption or yield
- Running → Blocked: `prvAddCurrentTaskToDelayedList()` (blocking API call)
- Blocked → Ready: timeout expiry or `xTaskRemoveFromEventList()` (condition satisfied)
- Running/Suspended → Suspended: `vTaskSuspend()`
- Suspended → Ready: `vTaskResume()` (or `xTaskResumeAll()` for indefinite block)

### 各状态的链表表示

| 状态 | 所在链表 | 判定方法 |
|------|---------|---------|
| **Running** | `pxReadyTasksLists[priority]` | `pxTCB == pxCurrentTCB` |
| **Ready** | `pxReadyTasksLists[priority]` | `xStateListItem` 在任一 Ready 列表中 |
| **Blocked** | `pxDelayedTaskList` 或 `pxOverflowDelayedTaskList` | `xStateListItem` 在延时列表中 |
| **Blocked (indefinite)** | `xSuspendedTaskList` + `xEventListItem` 不为 NULL | 在 `xSuspendedTaskList` 中且有事件项 |
| **Suspended** | `xSuspendedTaskList` + `xEventListItem` 为 NULL | 在 `xSuspendedTaskList` 中且无事件项 |
| **Deleted** | `xTasksWaitingTermination` | TCB 尚未释放，等待 idle 清理 |

> **注意**：`eTaskState` 枚举在 task.h 中定义了 `eRunning=0, eReady, eBlocked, eSuspended, eDeleted, eInvalid`。实际判定通过检查 `xStateListItem` 所在的链表指针实现（`eTaskGetState()` 函数）。

## 三、就绪列表结构：优先级映射

### 3.1 通用 C 实现（`configUSE_PORT_OPTIMISED_TASK_SELECTION == 0`）

```c
PRIVILEGED_DATA static List_t pxReadyTasksLists[ configMAX_PRIORITIES ];
```

- 每个优先级一个独立链表，优先级 0（idle）到 `configMAX_PRIORITIES-1`（最高）。
- `uxTopReadyPriority` 记录当前**最高有就绪任务的优先级**，作为搜索起点。
- 查找最高优先级就绪任务时，从 `uxTopReadyPriority` 向下扫描直到找到非空链表。

**宏展开**：

```c
#define taskRECORD_READY_PRIORITY( uxPriority )
    if( ( uxPriority ) > uxTopReadyPriority )
        uxTopReadyPriority = ( uxPriority );

#define taskSELECT_HIGHEST_PRIORITY_TASK()
    UBaseType_t uxTopPriority = uxTopReadyPriority;
    while( listLIST_IS_EMPTY( &( pxReadyTasksLists[ uxTopPriority ] ) ) )
        --uxTopPriority;
    listGET_OWNER_OF_NEXT_ENTRY( pxCurrentTCB, &( pxReadyTasksLists[ uxTopPriority ] ) );
    uxTopReadyPriority = uxTopPriority;
```

### 3.2 位图优化实现（`configUSE_PORT_OPTIMISED_TASK_SELECTION == 1`，ARM Cortex-M3 默认）

ARM CM3 的 `portmacro.h` 定义：

```c
/* 要求 configMAX_PRIORITIES <= 32 */
#define portRECORD_READY_PRIORITY( uxPriority, uxReadyPriorities )
    ( uxReadyPriorities ) |= ( 1UL << ( uxPriority ) )

#define portRESET_READY_PRIORITY( uxPriority, uxReadyPriorities )
    ( uxReadyPriorities ) &= ~( 1UL << ( uxPriority ) )

#define portGET_HIGHEST_PRIORITY( uxTopPriority, uxReadyPriorities )
    uxTopPriority = ( 31UL - ( uint32_t ) ucPortCountLeadingZeros( ( uxReadyPriorities ) ) )
```

- `uxTopReadyPriority` 用作位图，bit N 表示优先级 N 的链表非空。
- 使用 ARM `CLZ`（Count Leading Zeros）指令一次计算最高优先级，O(1) 而非 O(n)。
- `configMAX_PRIORITIES > 32` 时报错。

### 3.3 `configMAX_PRIORITIES` 的影响

| 配置 | 就绪链表数组大小 | 查找算法 | 典型场景 |
|------|-----------------|----------|---------|
| ≤ 32 + 位图优化 | `List_t[configMAX_PRIORITIES]` | CLZ 位图 O(1) | Cortex-M3/M4/M7 |
| > 32 或通用模式 | `List_t[configMAX_PRIORITIES]` | 向下扫描 O(n) | 其他架构 |
| 推荐范围 | 5-32 | — | 官方建议，超过罕见 |

## 四、关键函数逐函数分析

### 4.1 任务创建：`xTaskCreate()` / `xTaskCreateStatic()`

**位置**：`tasks.c:728`（动态）/ `tasks.c:575`（静态）

**流程图**：

1. `pvPortMalloc( TCB )` — 分配 TCB（栈向下生长时先分配 TCB）
2. `pvPortMalloc( stack )` — 分配栈空间
3. `prvInitialiseNewTask()` — 初始化 TCB 字段：
   - `memset( stack, 0xa5 )` — 栈填充已知值（用于水位检测）
   - 计算 `pxTopOfStack`（根据 `portSTACK_GROWTH` 方向）
   - 复制任务名到 `pcTaskName`
   - 限制优先级 <= `configMAX_PRIORITIES - 1`
   - `vListInitialiseItem()` 初始化两个列表项
   - `listSET_LIST_ITEM_OWNER()` 设置 TCB 反向指针
   - 事件列表键值 = `configMAX_PRIORITIES - uxPriority`
   - `pxPortInitialiseStack()` — 初始化栈帧，模拟已中断状态
   - 写入 `pxCreatedTask` 句柄
4. `prvAddNewTaskToReadyList()`

**`pxPortInitialiseStack()` 的作用**：在栈上构造一个与中断退出时完全一致的寄存器布局（xPSR, PC, LR, R12, R3-R0 等），使首次上下文切换时 PendSV 通过加载这些寄存器即可开始执行任务入口函数。

**栈填充字节**：`tskSTACK_FILL_BYTE = 0xa5`，用于 `uxTaskGetStackHighWaterMark()` 检测栈实际使用量。

### 4.2 `prvAddNewTaskToReadyList()` — 将新任务加入调度

**位置**：`tasks.c:1071`

```c
static void prvAddNewTaskToReadyList( TCB_t * pxNewTCB )
{
    taskENTER_CRITICAL();
    uxCurrentNumberOfTasks++;

    if( pxCurrentTCB == NULL )           /* 第一个任务 */
    {
        pxCurrentTCB = pxNewTCB;
        if( uxCurrentNumberOfTasks == 1 )
            prvInitialiseTaskLists();    /* ← 初始化所有全局列表 */
    }
    else if( xSchedulerRunning == pdFALSE )  /* 调度器未启动 */
    {
        if( pxCurrentTCB->uxPriority <= pxNewTCB->uxPriority )
            pxCurrentTCB = pxNewTCB;     /* 最高优先级的成为当前任务 */
    }
    /* 如果调度器已运行，不修改 pxCurrentTCB */

    uxTaskNumber++;
    prvAddTaskToReadyList( pxNewTCB );   /* 加入就绪链表 + 更新 uxTopReadyPriority */
    portSETUP_TCB( pxNewTCB );
    taskEXIT_CRITICAL();

    if( xSchedulerRunning != pdFALSE )
    {
        if( pxCurrentTCB->uxPriority < pxNewTCB->uxPriority )
            taskYIELD_IF_USING_PREEMPTION();  /* 更高优先级 → 立即抢占 */
    }
}
```

**关键逻辑**：

- 临界区保护链表操作，防止中断竞争。
- **第一个任务创建时**调用 `prvInitialiseTaskLists()` 一次性初始化所有全局链表。
- 在调度器未启动前，`pxCurrentTCB` 始终指向**已创建的最高优先级任务**；调度器启动时由此确定第一个运行的任务。
- 调度器运行后创建高优先级任务立即触发抢占。

### 4.3 `vTaskStartScheduler()` — 启动调度器

**位置**：`tasks.c:1997`

**执行流程**：

1. 创建空闲任务 `prvIdleTask`（优先级 0，携带 `portPRIVILEGE_BIT` 在 MPU 系统中运行在特权模式）。
2. （可选）创建定时器服务任务 `xTimerCreateTimerTask()`。
3. `portDISABLE_INTERRUPTS()` — 启动前关中断，防止 SysTick 提前触发。
4. 设置全局状态：
   - `xNextTaskUnblockTime = portMAX_DELAY`
   - `xSchedulerRunning = pdTRUE`
   - `xTickCount = configINITIAL_TICK_COUNT`
5. `xPortStartScheduler()` — 移植层函数，配置 SysTick、使能 PendSV/SVC、然后**触发 SVC 0**启动第一个任务。

> 第一个任务如何开始执行：SVC 处理程序从 `pxCurrentTCB`（即最高优先级任务）恢复上下文，如同从 PendSV 中断返回一样弹出寄存器，`bx r14` 跳转到任务入口。

### 4.4 空闲任务 `prvIdleTask()`

**位置**：`tasks.c:3441`

```c
static portTASK_FUNCTION( prvIdleTask, pvParameters )
{
    portALLOCATE_SECURE_CONTEXT( configMINIMAL_SECURE_STACK_SIZE );
    for( ; ; )
    {
        prvCheckTasksWaitingTermination();  /* 释放已删除任务的内存 */

        #if ( configUSE_PREEMPTION == 0 )
            taskYIELD();                    /* 协作式：主动让出 CPU */
        #endif

        #if ( configUSE_PREEMPTION == 1 ) && ( configIDLE_SHOULD_YIELD == 1 )
            if( 同一优先级有其他任务就绪 ) taskYIELD();
        #endif

        #if ( configUSE_IDLE_HOOK == 1 )
            vApplicationIdleHook();         /* 用户空闲钩子 */
        #endif

        #if ( configUSE_TICKLESS_IDLE != 0 )
            /* 计算预期空闲时间，进入低功耗模式 */
            prvGetExpectedIdleTime() → portSUPPRESS_TICKS_AND_SLEEP()
        #endif
    }
}
```

**空闲任务的责任**：

1. **回收已删除任务的 TCB 和栈内存** — 调用 `prvCheckTasksWaitingTermination()` 遍历 `xTasksWaitingTermination`。
2. **提供 CPU 占位** — 无用户任务就绪时运行，保证至少有可运行任务。
3. **用户空闲钩子** — 可在此执行低优先级后台操作，**不可阻塞**。
4. **Tickless 低功耗模式** — 计算可休眠时间，停止 SysTick 进入睡眠。

### 4.5 `prvAddCurrentTaskToDelayedList()` — 任务进入阻塞态

**位置**：`tasks.c:5310`

```c
static void prvAddCurrentTaskToDelayedList( TickType_t xTicksToWait,
                                            const BaseType_t xCanBlockIndefinitely )
{
    TickType_t xTimeToWake = xTickCount + xTicksToWait;

    /* 1. 从就绪链表中移除当前任务 */
    uxListRemove( &( pxCurrentTCB->xStateListItem ) );

    /* 2. 如果 xTicksToWait == portMAX_DELAY 且允许无限阻塞 */
    #if ( INCLUDE_vTaskSuspend == 1 )
        if( ( xTicksToWait == portMAX_DELAY ) && ( xCanBlockIndefinitely != pdFALSE ) )
        {
            listINSERT_END( &xSuspendedTaskList, &( pxCurrentTCB->xStateListItem ) );
            return;
        }
    #endif

    /* 3. 计算唤醒时间，写入 xStateListItem.xItemValue */
    listSET_LIST_ITEM_VALUE( &( pxCurrentTCB->xStateListItem ), xTimeToWake );

    /* 4. 根据 tick 溢出选择延时链表 */
    if( xTimeToWake < xTickCount )        /* 唤醒时间溢出 */
        vListInsert( pxOverflowDelayedTaskList, ... );
    else
        vListInsert( pxDelayedTaskList, ... );  /* 按唤醒时间升序插入 */

    /* 5. 更新 xNextTaskUnblockTime */
    if( xTimeToWake < xNextTaskUnblockTime )
        xNextTaskUnblockTime = xTimeToWake;
}
```

**关键点**：

- 延时链表按唤醒时间**升序排序**，头部是最快到期任务。
- `xNextTaskUnblockTime` 缓存头部任务的唤醒时间，避免每次 tick 都检查链表。
- **无限阻塞**（`portMAX_DELAY` + `xCanBlockIndefinitely==pdTRUE`）的任务放入 `xSuspendedTaskList`，而非延时链表，不会因时间到期被唤醒。
- Tick 计数器溢出时（唤醒时间 < 当前时间），任务放入 Overflow 延时链表，由 `xTaskIncrementTick` 在溢出时切换链表。

### 4.6 `vTaskDelay()` — 任务延时

**位置**：`tasks.c:1346`

```c
void vTaskDelay( const TickType_t xTicksToDelay )
{
    if( xTicksToDelay > 0 )
    {
        vTaskSuspendAll();
        {
            prvAddCurrentTaskToDelayedList( xTicksToDelay, pdFALSE );
        }
        xAlreadyYielded = xTaskResumeAll();
    }

    if( xAlreadyYielded == pdFALSE )
        portYIELD_WITHIN_API();  /* 强制上下文切换 */
}
```

**执行流程**：

1. 挂起调度器 → 防止 ISR 在此期间干扰链表操作。
2. 将当前任务从就绪链表移除，按唤醒时间加入延时链表。
3. 恢复调度器 → `xTaskResumeAll()` 内处理 pend 任务和 pend tick。
4. 如果恢复时尚未触发切换，手动发起一次上下文切换（yield 到其他就绪任务）。

### 4.7 `xTaskIncrementTick()` — Tick 中断处理

**位置**：`tasks.c:2736`

这是 SysTick 中断中调用的核心函数，返回值决定是否需要上下文切换。

```c
BaseType_t xTaskIncrementTick( void )
{
    BaseType_t xSwitchRequired = pdFALSE;

    if( uxSchedulerSuspended == pdFALSE )       /* 调度器未挂起 */
    {
        xTickCount++;                            /* 递增 tick */
        if( xTickCount == 0 )                    /* tick 溢出 */
            taskSWITCH_DELAYED_LISTS();          /* 交换 pxDelayedTaskList <-> pxOverflowDelayedTaskList */

        if( xTickCount >= xNextTaskUnblockTime ) /* 有任务到期 */
        {
            for( ; ; )
            {
                if( 延时链表为空 )
                {
                    xNextTaskUnblockTime = portMAX_DELAY;
                    break;
                }
                pxTCB = 延时链表头部任务;
                if( 当前 tick < 头部任务的唤醒时间 )
                {
                    xNextTaskUnblockTime = 头部任务的唤醒时间;
                    break;                       /* 后续任务都未到期 */
                }
                /* 到期：从延时链表移除 */
                listREMOVE_ITEM( &pxTCB->xStateListItem );
                if( pxTCB 在事件链表中 )
                    listREMOVE_ITEM( &pxTCB->xEventListItem );   /* 超时：也从事件链表移除 */
                prvAddTaskToReadyList( pxTCB );  /* 放回就绪链表 */

                #if ( configUSE_PREEMPTION == 1 )
                    if( pxTCB->uxPriority >= pxCurrentTCB->uxPriority )
                        xSwitchRequired = pdTRUE;
                #endif
            }
        }

        /* 时间片轮转：如果同一优先级有多个就绪任务 */
        #if ( ( configUSE_PREEMPTION == 1 ) && ( configUSE_TIME_SLICING == 1 ) )
            if( pxReadyTasksLists[ pxCurrentTCB->uxPriority ] 有 > 1 个任务 )
                xSwitchRequired = pdTRUE;
        #endif

        /* 检查挂起的 yield */
        if( xYieldPending != pdFALSE )
            xSwitchRequired = pdTRUE;
    }
    else                                        /* 调度器挂起期间 */
    {
        ++xPendedTicks;                         /* 累积 tick，恢复时补处理 */
    }

    return xSwitchRequired;
}
```

**完整逻辑流**：

1. **SysTick 中断**触发
2. `xPortSysTickHandler()` 执行：
   - `portDISABLE_INTERRUPTS()`
   - `xTaskIncrementTick()`：
     1. `xTickCount++`
     2. 如果 tick 溢出 → 切换延时链表
     3. 处理到期任务：延时链表头部 → 移除 → 放回就绪链表
        - 超时也从事件链表移除（！）
        - 如果优先级 ≥ 当前 → 请求切换
     4. 时间片轮转：同一优先级 >1 任务 → 请求切换
     5. `xYieldPending` 检查
   - 如果 `xSwitchRequired` → 触发 PendSV（手工写 NVIC PENDSVSET）
   - `portENABLE_INTERRUPTS()`

**时间片轮转的实现**：每次 tick 中断无条件请求切换同一优先级的其他任务，`listGET_OWNER_OF_NEXT_ENTRY()` 内部的 `pxIndex` 自动推进到下一个任务，实现 round-robin。

### 4.8 `vTaskSwitchContext()` — 上下文切换决策

**位置**：`tasks.c:3021`

```c
void vTaskSwitchContext( void )
{
    if( uxSchedulerSuspended != pdFALSE )
    {
        xYieldPending = pdTRUE;   /* 挂起期间不允许切换，延迟处理 */
        return;
    }

    xYieldPending = pdFALSE;

    /* 统计当前任务的运行时间 */
    #if ( configGENERATE_RUN_TIME_STATS == 1 )
        pxCurrentTCB->ulRunTimeCounter += ( ulTotalRunTime - ulTaskSwitchedInTime );
        ulTaskSwitchedInTime = ulTotalRunTime;
    #endif

    taskCHECK_FOR_STACK_OVERFLOW();   /* 栈溢出检查（可选） */

    /* 保存当前任务的 errno / Newlib reent 结构 */
    #if ( configUSE_POSIX_ERRNO == 1 )
        pxCurrentTCB->iTaskErrno = FreeRTOS_errno;
    #endif

    /* 核心：选择下一个要运行的任务 */
    taskSELECT_HIGHEST_PRIORITY_TASK();   /* 见 §3.1 / §3.2 */

    /* 恢复新任务的 errno / Newlib reent 结构 */
    #if ( configUSE_POSIX_ERRNO == 1 )
        FreeRTOS_errno = pxCurrentTCB->iTaskErrno;
    #endif
}
```

**PendSV 中的调用链路**（ARM CM3）：

```asm
xPortPendSVHandler:
    mrs r0, psp                     ; 读取当前任务栈指针
    stmdb r0!, {r4-r11}            ; 保存 callee-saved 寄存器到当前任务栈
    str r0, [r2]                    ; 写入 pxCurrentTCB->pxTopOfStack
    bl vTaskSwitchContext            ; ← C 函数选择下一个任务
    ldr r1, [r3]                    ; 新 pxCurrentTCB
    ldr r0, [r1]                    ; 新任务的 pxTopOfStack
    ldmia r0!, {r4-r11}            ; 恢复 callee-saved 寄存器
    msr psp, r0                     ; 更新 PSP
    bx r14                          ; 异常返回，硬件自动恢复 R0-R3,R12,LR,PC,xPSR
```

**中断模型**：

- PendSV 是 Cortex-M 上**最低优先级**的可悬起中断，在所有其他中断完成后才执行。
- SysTick 中检测到需要切换时，仅**悬起 PendSV** 而非直接切换，确保中断响应延迟最小化。
- PendSV 实际执行 `vTaskSwitchContext()`，选择下一个任务，并在 `bx r14` 时硬件自动完成栈切换。

### 4.9 `portYIELD()` / `taskYIELD()` — 发起上下文切换

**位置**：`portmacro.h:81`（ARM CM3）

```c
#define portYIELD()
    portNVIC_INT_CTRL_REG = portNVIC_PENDSVSET_BIT;  /* 悬起 PendSV */
    __asm volatile ( "dsb" ::: "memory" );
    __asm volatile ( "isb" );
```

- 通过向 NVIC 的 `ICSR` 寄存器（地址 `0xE000ED04`）的 bit 28 写 1，触发 PendSV 异常。
- `dsb` / `isb` 确保指令执行顺序和内存访问可见性。

### 4.10 `vTaskSuspendAll()` / `xTaskResumeAll()` — 调度器挂起机制

**挂起**（`vTaskSuspendAll`，`tasks.c:2136`）：

```c
void vTaskSuspendAll( void )
{
    portSOFTWARE_BARRIER();
    ++uxSchedulerSuspended;       /* 嵌套计数 */
    portMEMORY_BARRIER();
}
```

- 不支持嵌套（每次恢复会递减计数，直到 0 才真正恢复）。
- 挂起期间 ISR 仍然可以解除任务阻塞，但解锁的任务放入 `xPendingReadyList` 而非就绪链表。
- 挂起期间的 tick 中断累积到 `xPendedTicks`。

**恢复**（`xTaskResumeAll`，`tasks.c:2220`）：

```c
BaseType_t xTaskResumeAll( void )
{
    taskENTER_CRITICAL();
    --uxSchedulerSuspended;

    if( uxSchedulerSuspended == 0 )
    {
        /* 1. 处理 xPendingReadyList：所有任务移入就绪链表 */
        while( xPendingReadyList 非空 )
            listREMOVE_ITEM → prvAddTaskToReadyList();

        /* 2. 处理 pend tick：补执行缺失的 xTaskIncrementTick */
        while( xPendedTicks-- > 0 )
            xTaskIncrementTick();

        /* 3. 如果有 yield 挂起 */
        if( xYieldPending != pdFALSE )
            portYIELD_WITHIN_API();
    }
    taskEXIT_CRITICAL();
    return xAlreadyYielded;
}
```

## 七、设计要点总结

1. **pxTopOfStack 必须是 TCB 第一个成员** — 汇编代码通过固定偏移访问。
2. **双向链表 + 哨兵节点** — 所有调度队列统一使用，简化链表操作边界条件。
3. **两个延时链表处理 tick 溢出** — `pxDelayedTaskList` 和 `pxOverflowDelayedTaskList` 在 tick 计数器溢出时交换，避免 32 位 tick 包裹问题。
4. **优先级位图优化** — ARM CM3 上利用 CLZ 指令实现 O(1) 最高优先级查找。
5. **xNextTaskUnblockTime 缓存** — 避免每次 tick 扫描整个延时链表。
6. **调度器挂起嵌套计数** — `uxSchedulerSuspended` 支持嵌套，ISR 在挂起期间仍可操作，但通过 `xPendingReadyList` 和 `xPendedTicks` 延迟处理。
7. **PendSV 最低优先级** — 上下文切换延迟到所有中断处理完成后执行，保证中断响应实时性。
8. **自删除任务的内存回收** — 由空闲任务负责，避免任务自己释放自己的栈。
9. **列表项双重用途** — 任何列表项通过 `pvOwner` 回指 TCB，实现从列表到对象的反向查找。
10. **条件编译粒度极细** — 每个功能点都有配置宏，允许针对 MCU 资源裁剪。
