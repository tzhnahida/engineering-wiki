# FreeRTOS 流缓冲区与消息缓冲区

## 概述

FreeRTOS 提供两种基于字节流的轻量级任务间通信机制：

- **流缓冲区（Stream Buffer）**：连续的字节流——写入 N 字节，读回 N 字节，没有消息边界
- **消息缓冲区（Message Buffer）**：离散的消息——按可变长度消息收发，在流缓冲区之上叠加长度前缀实现

它们都只支持 **单一写入者 + 单一读取者**（single writer / single reader）。这是有意为之的设计约束，使其实现比队列更轻量。

## 与队列（Queue）的关键区别

| 特性 | 队列 (Queue) | 流/消息缓冲区 |
|------|-------------|--------------|
| 数据单元 | 固定长度 item | 字节流/可变长度消息 |
| 写入者/读取者 | 多对多 | 单写入者 + 单读取者（设计约束） |
| 数据拷贝 | item 整体 memcpy | 字节级别的 memcpy |
| 阻塞机制 | Event List（链表） | Task Notification（直接任务通知） |
| 触发阈值 | — | ✅ Trigger Level 批量唤醒 |
| 内存分配 | 结构与存储分开 | 一次性 `pvPortMalloc` 分配 |
| 消息边界 | 每个 item 自带边界 | 消息缓冲区通过长度前缀模拟边界 |

## 数据结构

```c
typedef struct StreamBufferDef_t
{
    volatile size_t xTail;                    /* 读取指针（指向下一个可读字节） */
    volatile size_t xHead;                    /* 写入指针（指向下一个可写位置） */
    size_t xLength;                           /* 缓冲区总长度（xLength 字节） */
    size_t xTriggerLevelBytes;                /* 触发阈值（读端批量唤醒条件） */
    volatile TaskHandle_t xTaskWaitingToReceive;  /* 等待读取的任务句柄（NULL 表示无等待者） */
    volatile TaskHandle_t xTaskWaitingToSend;     /* 等待写入的任务句柄（NULL 表示无等待者） */
    uint8_t *pucBuffer;                       /* 指向实际数据缓冲区的指针 */
    uint8_t ucFlags;                          /* 标记位：消息缓冲区标记 + 静态分配标记 */
    
    #if (configUSE_TRACE_FACILITY == 1)
        UBaseType_t uxStreamBufferNumber;
    #endif
} StreamBuffer_t;
```

### 标记位

```c
#define sbFLAGS_IS_MESSAGE_BUFFER       ((uint8_t)1)  /* 标记为消息缓冲区 */
#define sbFLAGS_IS_STATICALLY_ALLOCATED ((uint8_t)2)  /* 标记为静态分配 */
```

### 消息缓冲区长度前缀尺寸

```c
#define sbBYTES_TO_STORE_MESSAGE_LENGTH (sizeof(configMESSAGE_BUFFER_LENGTH_TYPE))
```

`configMESSAGE_BUFFER_LENGTH_TYPE` 默认为 `size_t`（32 位系统上为 4 字节）。

### 循环缓冲区结构

```
        xTail              xHead
         |                  |
         v                  v
+--------+------------------+-------------------+
|        |  已写入的数据     |     空余空间       |
|        |  (可读取)        |  (可写入)          |
+--------+------------------+-------------------+
         ^                  ^
         可读区域            可写区域
         
         总容量 = xLength - 1 (实际可用空间)
```

缓冲区是一个标准循环缓冲区（circular buffer），`xHead` 和 `xTail` 在达到 `xLength` 时回绕。

### 容量计算

- **实际可用容量**：`xLength - 1` 字节（始终保留一个字节的间隔以区分满和空）
- **`prvBytesInBuffer`**（可读字节数）：`(xLength + xHead - xTail) % xLength`
- **`xStreamBufferSpacesAvailable`**（可写字节数）：`xLength - 1 - prvBytesInBuffer()`

## 创建与初始化

### xStreamBufferCreate — 动态分配

```c
#define xStreamBufferCreate(xBufferSizeBytes, xTriggerLevelBytes)
    xStreamBufferGenericCreate(xBufferSizeBytes, xTriggerLevelBytes, pdFALSE)
```

内部实现 `xStreamBufferGenericCreate`：

1. 调用 `pvPortMalloc` 一次性分配 `sizeof(StreamBuffer_t) + xBufferSizeBytes + 1`
   - 结构体放在分配内存的开头
   - 实际数据缓冲区紧随其后
   - `+1` 是因为内部用 'full when head+1 == tail' 策略
2. 调用 `prvInitialiseNewStreamBuffer` 初始化
3. 触发级别为 0 时强制设为 1

### xStreamBufferCreateStatic — 静态分配

```c
#define xStreamBufferCreateStatic(xBufferSizeBytes, xTriggerLevelBytes,
                                   pucStreamBufferStorageArea, pxStaticStreamBuffer)
    xStreamBufferGenericCreateStatic(xBufferSizeBytes, xTriggerLevelBytes, pdFALSE,
                                     pucStreamBufferStorageArea, pxStaticStreamBuffer)
```

用户需提供存储缓冲区（`uint8_t[]`）和 `StaticStreamBuffer_t` 结构体。

### prvInitialiseNewStreamBuffer

```c
static void prvInitialiseNewStreamBuffer(StreamBuffer_t *pxStreamBuffer,
                                          uint8_t *pucBuffer,
                                          size_t xBufferSizeBytes,
                                          size_t xTriggerLevelBytes,
                                          uint8_t ucFlags)
{
    memset(pxStreamBuffer, 0x00, sizeof(StreamBuffer_t));
    pxStreamBuffer->pucBuffer = pucBuffer;
    pxStreamBuffer->xLength = xBufferSizeBytes;
    pxStreamBuffer->xTriggerLevelBytes = xTriggerLevelBytes;
    pxStreamBuffer->ucFlags = ucFlags;
}
```

- 初始化将整个结构体清零（`xTail=0, xHead=0, xTaskWaitingToReceive=NULL, xTaskWaitingToSend=NULL`）
- 断言模式下用 `0x55` 填充数据缓冲区以辅助调试

## 流缓冲区 API

### xStreamBufferSend — 发送字节流

```c
size_t xStreamBufferSend(StreamBufferHandle_t xStreamBuffer,
                          const void *pvTxData, size_t xDataLengthBytes,
                          TickType_t xTicksToWait);
```

**流程**：

1. 如果是消息缓冲区，所需空间增加 `sbBYTES_TO_STORE_MESSAGE_LENGTH`
   - 消息缓冲区要求全部消息一次性写入，放入不下时不等待
   - 流缓冲区则截断到最大可用空间
2. 如果 `xTicksToWait > 0` 且空间不足，进入阻塞循环：
   ```
   do {
       临界区保护 {
           xSpace = xStreamBufferSpacesAvailable();
           if (xSpace < xRequiredSpace) {
               xTaskNotifyStateClear(NULL);                       // 清除通知状态
               pxStreamBuffer->xTaskWaitingToSend = currentTask;  // 注册为等待发送者
           } else {
               break;                                             // 空间够了
           }
       }
       xTaskNotifyWait(0, 0, NULL, xTicksToWait);                 // 阻塞等待通知
       pxStreamBuffer->xTaskWaitingToSend = NULL;
   } while (!xTaskCheckForTimeOut(&xTimeOut, &xTicksToWait));
   ```
3. 调用 `prvWriteMessageToBuffer` 实际写入数据
4. 如果写入后缓冲区字节数 >= 触发阈值，调用 `sbSEND_COMPLETED` 宏唤醒等待读取的任务

**返回值**：实际写入的字节数。流缓冲区返回可能小于请求长度；消息缓冲区要么全写要么返回 0。

### xStreamBufferReceive — 接收字节流

```c
size_t xStreamBufferReceive(StreamBufferHandle_t xStreamBuffer,
                             void *pvRxData, size_t xBufferLengthBytes,
                             TickType_t xTicksToWait);
```

**流程**：

1. 确定 `xBytesToStoreMessageLength`（消息缓冲区为 4，流缓冲区为 0）
2. 如果 `xTicksToWait > 0` 且可用字节 <= 长度前缀尺寸，进入阻塞：
   ```
   临界区保护 {
       if (xBytesAvailable <= xBytesToStoreMessageLength) {
           xTaskNotifyStateClear(NULL);
           pxStreamBuffer->xTaskWaitingToReceive = currentTask;
       }
   }
   xTaskNotifyWait(0, 0, NULL, xTicksToWait);
   pxStreamBuffer->xTaskWaitingToReceive = NULL;
   xBytesAvailable = prvBytesInBuffer(); // 重新检查
   ```
3. 如果有数据，调用 `prvReadMessageFromBuffer` 读取
4. 读取后调用 `sbRECEIVE_COMPLETED` 宏唤醒等待写入的任务

**返回值**：实际读取的字节数。

### xStreamBufferReset

```c
BaseType_t xStreamBufferReset(StreamBufferHandle_t xStreamBuffer);
```

- 仅在 **没有任务阻塞等待发送或接收时** 才能重置
- 内存中检查 `xTaskWaitingToReceive == NULL && xTaskWaitingToSend == NULL`
- 成功后调用 `prvInitialiseNewStreamBuffer` 重新初始化

## ISR 安全 API

### xStreamBufferSendFromISR

```c
size_t xStreamBufferSendFromISR(StreamBufferHandle_t xStreamBuffer,
                                 const void *pvTxData, size_t xDataLengthBytes,
                                 BaseType_t *const pxHigherPriorityTaskWoken);
```

- **非阻塞**：检查空闲空间，立即尝试写入
- 使用 `sbSEND_COMPLETE_FROM_ISR` 宏唤醒等待读取的任务
- 如果写入了数据且触发级别满足，通过 `xTaskNotifyFromISR` 通知读取者
- `pxHigherPriorityTaskWoken` 用于向调用者指示是否需要上下文切换

### xStreamBufferReceiveFromISR

```c
size_t xStreamBufferReceiveFromISR(StreamBufferHandle_t xStreamBuffer,
                                    void *pvRxData, size_t xBufferLengthBytes,
                                    BaseType_t *const pxHigherPriorityTaskWoken);
```

- 非阻塞读取可用数据
- 使用 `sbRECEIVE_COMPLETED_FROM_ISR` 宏唤醒等待写入的任务

## 底层字节操作

### prvWriteBytesToBuffer — 带回绕的写入

```c
static size_t prvWriteBytesToBuffer(StreamBuffer_t *pxStreamBuffer,
                                     const uint8_t *pucData,
                                     size_t xCount, size_t xHead)
```

1. 计算第一部分长度：`xFirstLength = min(xLength - xHead, xCount)`
2. `memcpy(&pucBuffer[xHead], pucData, xFirstLength)` — 写入到尾部
3. 如果 `xCount > xFirstLength`：
   `memcpy(pucBuffer, &pucData[xFirstLength], xCount - xFirstLength)` — 回绕到头部
4. `xHead += xCount; if (xHead >= xLength) xHead -= xLength;`
5. 返回新的 `xHead`

### prvReadBytesFromBuffer — 带回绕的读取

```c
static size_t prvReadBytesFromBuffer(StreamBuffer_t *pxStreamBuffer,
                                      uint8_t *pucData,
                                      size_t xCount, size_t xTail)
```

- 结构对称于 `prvWriteBytesToBuffer`
- 最多需要两次 `memcpy`（处理回绕）
- 返回新的 `xTail`

**关键设计**：这两个函数接受自定义的 `xHead` 或 `xTail` 参数（而非直接操作结构体的 `xHead`/`xTail`），这是为了支持消息缓冲区的 **链式原子操作**：

```
消息写入流程:
  1. prvWriteBytesToBuffer(buf, &msg_len, 4, xHead) → xNextHead  // 写入长度前缀
  2. prvWriteBytesToBuffer(buf, msg_data, len, xNextHead) → xNextHead  // 写入数据体
  3. pxStreamBuffer->xHead = xNextHead  // 原子提交，读取者才能看到数据
```

这种设计使得长度前缀和数据体的写入在读取者看来是 **原子不可分割的**。

## 消息缓冲区（Message Buffer）实现机制

消息缓冲区本质上就是带有 `sbFLAGS_IS_MESSAGE_BUFFER` 标志位的流缓冲区。所有 API 都通过宏直接映射到流缓冲区 API。

### 创建映射

```c
#define xMessageBufferCreate(xBufferSizeBytes)
    (MessageBufferHandle_t)xStreamBufferGenericCreate(xBufferSizeBytes, 0, pdTRUE)
```

- 触发级别默认为 0（内部转换为 1）
- `xIsMessageBuffer = pdTRUE`

### 发送/接收映射

```c
#define xMessageBufferSend(xMessageBuffer, pvTxData, xDataLengthBytes, xTicksToWait)
    xStreamBufferSend((StreamBufferHandle_t)xMessageBuffer, pvTxData, xDataLengthBytes, xTicksToWait)

#define xMessageBufferReceive(xMessageBuffer, pvRxData, xBufferLengthBytes, xTicksToWait)
    xStreamBufferReceive((StreamBufferHandle_t)xMessageBuffer, pvRxData, xBufferLengthBytes, xTicksToWait)
```

ALL 消息缓冲区 API（包括 `FromISR`、`Delete`、`Reset`、`IsEmpty`、`IsFull` 等）都是类似的单行宏。

### 消息长度前缀机制

消息缓冲区通过向每条消息数据前添加 **长度前缀** 来实现消息边界：

```
缓冲区内容（消息缓冲区）:
+---------+------------------+---------+------------------+
| msg_len | 消息数据 (N 字节) | msg_len | 消息数据 (M 字节) |
+---------+------------------+---------+------------------+
  ↑                       ↑                    ↑
  4 字节                  N 字节               下一个消息...
```

- **写入时**（`prvWriteMessageToBuffer`）：
  1. 检查 `xSpace >= xRequiredSpace`（`xRequiredSpace = xDataLengthBytes + sbBYTES_TO_STORE_MESSAGE_LENGTH`）
  2. 先写入 `xDataLengthBytes`（长度前缀）
  3. 再写入实际数据
  4. `xHead` 在两步写入后一次性更新

- **读取时**（`prvReadMessageFromBuffer`）：
  1. 先读取 `sbBYTES_TO_STORE_MESSAGE_LENGTH` 字节得到 `xNextMessageLength`
  2. 如果用户缓冲区太小（`xNextMessageLength > xBufferLengthBytes`）→ 放弃读取，返回 0（消息 **保留在缓冲区中** 不丢失）
  3. 否则读取 `xNextMessageLength` 字节的数据
  4. `xTail` 在两步读取后一次性更新

### 消息的原子性

消息缓冲区保证消息的 **整体写入/整体读取** 语义：

- 空间不够时 **完全拒绝**（不部分写入）
- 用户缓冲区太小放不下整条消息时 **不消耗消息**（保留在缓冲区中等待更大缓冲区）
- 底层 `prvWriteBytesToBuffer` / `prvReadBytesFromBuffer` 的自定义 `xHead`/`xTail` 参数配合手动提交保证了 **写入者和读取者对彼此操作的原子可见性**

## 阻塞/唤醒机制

流缓冲区使用 **任务通知（Task Notification）** 而非传统的事件链表（Event List）实现阻塞：

### sbSEND_COMPLETED（写入完成 → 唤醒读取者）

```c
#define sbSEND_COMPLETED(pxStreamBuffer)
    vTaskSuspendAll(); {
        if ((pxStreamBuffer)->xTaskWaitingToReceive != NULL) {
            (void)xTaskNotify((pxStreamBuffer)->xTaskWaitingToReceive,
                              (uint32_t)0, eNoAction);
            (pxStreamBuffer)->xTaskWaitingToReceive = NULL;
        }
    }
    (void)xTaskResumeAll();
```

### sbRECEIVE_COMPLETED（读取完成 → 唤醒发送者）

```c
#define sbRECEIVE_COMPLETED(pxStreamBuffer)
    vTaskSuspendAll(); {
        if ((pxStreamBuffer)->xTaskWaitingToSend != NULL) {
            (void)xTaskNotify((pxStreamBuffer)->xTaskWaitingToSend,
                              (uint32_t)0, eNoAction);
            (pxStreamBuffer)->xTaskWaitingToSend = NULL;
        }
    }
    (void)xTaskResumeAll();
```

ISR 版本使用 `xTaskNotifyFromISR` 和 `portSET_INTERRUPT_MASK_FROM_ISR` 保护。

### 单任务等待的特殊性

由于只支持单写入者 + 单读取者，等待句柄直接使用指针而非链表：

```c
volatile TaskHandle_t xTaskWaitingToReceive;   // 指向等待读取的任务（或 NULL）
volatile TaskHandle_t xTaskWaitingToSend;      // 指向等待发送的任务（或 NULL）
```

每次只有**一个**任务可以阻塞在发送或接收上，通过 `configASSERT` 确保不会有第二个任务注册等待。这也是流缓冲区比队列更轻量的关键原因。

### 触发级别（Trigger Level）

触发级别是读取侧的批量唤醒阈值：

- 创建时指定，可在运行时通过 `xStreamBufferSetTriggerLevel` 修改
- 写入完成后，仅当 `prvBytesInBuffer >= xTriggerLevelBytes` 时才唤醒读取者
- 典型应用：接收方希望在累积到一定数据量后统一处理，提高效率
- 超时退回：即使未达到触发级别，阻塞时间到期后读取者仍会获得已积累的数据

## xStreamBufferReset — 重置

```c
BaseType_t xStreamBufferReset(StreamBufferHandle_t xStreamBuffer);
```

- 临界区保护
- 仅当 `xTaskWaitingToReceive == NULL && xTaskWaitingToSend == NULL` 时才能重置
- 成功则调用 `prvInitialiseNewStreamBuffer` 重新初始化

## 使用模式与约束

### 流缓冲区的典型场景

```c
/* 创建 */
StreamBufferHandle_t xStreamBuffer = xStreamBufferCreate(100, 10);

/* 写入者任务 */
xStreamBufferSend(xStreamBuffer, data, len, portMAX_DELAY);

/* 读取者任务（每次至少 10 字节才唤醒） */
xStreamBufferReceive(xStreamBuffer, buf, sizeof(buf), portMAX_DELAY);
```

### 消息缓冲区的典型场景

```c
/* 创建 */
MessageBufferHandle_t xMsgBuf = xMessageBufferCreate(256);

/* 发送可变长度消息 */
xMessageBufferSend(xMsgBuf, "Hello", 6, portMAX_DELAY);

/* 接收消息（最多 64 字节缓冲区） */
uint8_t buf[64];
size_t len = xMessageBufferReceive(xMsgBuf, buf, sizeof(buf), portMAX_DELAY);
```

### ISR → 任务通信

```c
/* ISR 侧 */
xStreamBufferSendFromISR(xStreamBuffer, data, len, &xHigherPriorityTaskWoken);
portYIELD_FROM_ISR(xHigherPriorityTaskWoken);

/* 任务侧 */
xStreamBufferReceive(xStreamBuffer, buf, sizeof(buf), portMAX_DELAY);
```

### 重要约束

- **单写入者 / 单读取者**：多写入者需要在每次调用外包裹临界区，且必须设 block time 为 0
- **数据拷贝**：所有数据通过 `memcpy` 拷贝进出缓冲区 —— **没有零拷贝机制**
- **长度前缀开销**：消息缓冲区每条消息额外消耗 `sizeof(configMESSAGE_BUFFER_LENGTH_TYPE)` 字节（通常 4 字节）
- **不支持广播**：阻塞机制基于任务通知，只能通知一个任务
- **`configUSE_TASK_NOTIFICATIONS`** 必须为 1 才能编译 `stream_buffer.c`

## 设计要点

- **轻量级**：使用单个任务句柄而不是链表管理等待者，节省内存和遍历时间
- **原子链式操作**：`prvWriteBytesToBuffer` / `prvReadBytesFromBuffer` 支持分批操作后原子提交（通过更新 `xHead`/`xTail`），这是消息缓冲区长度前缀机制的基础
- **通知分离**：`sbSEND_COMPLETED` 和 `sbRECEIVE_COMPLETED` 定义为可重写的宏，允许应用程序插入自定义行为（例如跨核通信的 MPCore 中断）
- **触发级别批量唤醒**：区别于队列的每次入队都唤醒，流缓冲区允许累积一定量的数据后再通知读取者
