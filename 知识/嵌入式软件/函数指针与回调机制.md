# 函数指针与回调机制

## 一句话

**函数指针的威力不在于语法，而在于调用方和实现方在编译时解耦、在运行时组合——这是从「写代码」到「设计代码」的分水岭。**

## 声明、赋值与调用

### 口诀

把函数声明中的函数名换成 `(*p)`：

```c
// 函数声明
void delay_ms(uint32_t ms);

// 函数指针声明 — 把 delay_ms 换成 (*pFunc)
void (*pFunc)(uint32_t ms);
```

`(*pFunc)` 是一个指针指向函数——返回值 `void`，参数 `uint32_t`。

### 赋值（三种等价）

```c
pFunc = delay_ms;       // 最常用：函数名就是地址
pFunc = &delay_ms;      // 显式取地址
```

### 调用（两种等价）

```c
pFunc(100);             // 推荐：隐式解引用，简洁
(*pFunc)(100);          // 显式解引用
```

## typedef 简化

函数指针类型写多了很冗长，`typedef` 让声明像普通变量一样自然：

```c
// 定义类型
typedef void (*TIM_CallbackFunc)(TIM_HandleTypeDef *htim);

// 用法 — 像声明 int 一样
TIM_CallbackFunc onPeriodElapsed = TIM_ElapsedCallback;
TIM_CallbackFunc onCaptureComplete = TIM_CaptureCallback;

onPeriodElapsed(&htim2);
```

> [!tip] 始终用 typedef 定义统一的回调类型
> 避免裸函数指针声明到处出现——可读性差且无类型安全检查。

## HAL 库回调机制

### 方式一：weak 弱符号（STM32 HAL 默认方式）

```c
// HAL 库提供 weak 默认实现
__weak void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    // 默认什么都不做
}

// 用户在 main.c 中覆盖
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM2)
        led_toggle();
}
```

> 限制：只能有一个全局实现。多个定时器要不同行为时不够用。

### 方式二：函数指针注册表（灵活方案）

```c
#define MAX_TIM_CALLBACKS 8

typedef struct {
    TIM_HandleTypeDef *htim;
    void (*callback)(void *arg);
    void *arg;                         // 自定义参数
} TIM_CallbackEntry;

static TIM_CallbackEntry s_callbacks[MAX_TIM_CALLBACKS];
static uint8_t s_cb_count = 0;

int TIM_RegisterCallback(TIM_HandleTypeDef *htim,
                         void (*cb)(void *), void *arg) {
    if (s_cb_count >= MAX_TIM_CALLBACKS) return -1;
    s_callbacks[s_cb_count].htim = htim;
    s_callbacks[s_cb_count].callback = cb;
    s_callbacks[s_cb_count].arg = arg;
    s_cb_count++;
    return 0;
}

// 不同定时器注册不同回调 + 自定义参数
TIM_RegisterCallback(&htim2, button_check, (void *)GPIO_PIN_0);
TIM_RegisterCallback(&htim3, button_check, (void *)GPIO_PIN_1);
```

> 核心思想：把一个函数「借」给底层驱动，让底层在恰当的时候执行你的逻辑。

## 函数指针表状态机

这是函数指针最强大的应用——**用查表替代 switch-case**。

### 场景

MCU 通过 UART 接收数据帧：`STX(0xAA) + LEN + DATA[N] + CRC`

### 状态定义

```c
typedef enum {
    ST_IDLE = 0,   // 等待帧头 STX
    ST_STX,        // 收到 STX，准备收长度
    ST_LEN,        // 收到长度，准备收数据
    ST_DATA,       // 收数据载荷
    ST_CRC,        // 收 CRC 校验字节
    ST_DONE        // 完整帧已收到
} FrameState_t;
```

### 统一处理函数接口

```c
typedef FrameState_t (*StateHandler)(uint8_t byte, FrameCtx *ctx);

FrameState_t state_idle(uint8_t byte, FrameCtx *ctx) {
    if (byte == 0xAA) {
        ctx->crc = 0;
        ctx->crc ^= byte;
        return ST_STX;
    }
    return ST_IDLE;
}

FrameState_t state_stx(uint8_t byte, FrameCtx *ctx) {
    if (byte == 0 || byte > MAX_FRAME_LEN)
        return ST_IDLE;          // 非法长度 → 复位
    ctx->len = byte;
    ctx->idx = 0;
    ctx->crc ^= byte;
    return ST_LEN;
}

FrameState_t state_data(uint8_t byte, FrameCtx *ctx) {
    ctx->data[ctx->idx++] = byte;
    ctx->crc ^= byte;
    if (ctx->idx >= ctx->len) return ST_CRC;
    return ST_DATA;
}
```

### 函数指针表 — 状态机的核心

```c
// ⚡ 必须加 const — 运行时不变，放 Flash 而非 RAM
static const StateHandler s_state_table[] = {
    [ST_IDLE] = state_idle,
    [ST_STX]  = state_stx,
    [ST_LEN]  = state_len,
    [ST_DATA] = state_data,
    [ST_CRC]  = state_crc,
};
```

### 运行调度 — 核心只有一行

```c
FrameCtx g_ctx = {.state = ST_IDLE};

void UART_RxByte_Handler(uint8_t byte) {
    // 查表 → 调用 → 更新状态
    g_ctx.state = s_state_table[g_ctx.state](byte, &g_ctx);

    if (g_ctx.state == ST_DONE) {
        ProcessFrame(&g_ctx);
        g_ctx.state = ST_IDLE;
    }
}
```

> [!important] 整台状态机核心逻辑就一条语句
> `state = table[state](byte, &ctx);` — 找到当前状态对应的函数 → 调用 → 用返回值更新状态。没有 switch-case，没有 if-else。

### 对比

| | switch-case | 函数指针表 |
|------|-------------|-----------|
| 添加新状态 | 在 switch 里加 case | 加函数 + 表里加一行 |
| 编译后体积 | switch 可能展开成大 jump table | 就是 jump table |
| 可读性 | 状态多时 switch 很长 | 表一眼看清所有状态 |
| 扩展性 | 需改调度主体 | 只改表，不动调度 |

## 四个坑

### 1. 中断回调里做耗时操作

```c
// ❌ 回调在中断上下文中执行——HAL_Delay 依赖 SysTick 中断，死锁
void TIM_ElapsedCallback(TIM_HandleTypeDef *htim) {
    HAL_Delay(100);
}

// ✅ 回调只设标志，耗时操作放主循环
volatile uint8_t g_tick_flag = 0;
void TIM_ElapsedCallback(TIM_HandleTypeDef *htim) {
    g_tick_flag = 1;
}
```

> [!warning] 黄金法则
> 中断回调只做「传递」不做「处理」——设标志、放队列、触发 DMA，绝不阻塞或做复杂计算。

### 2. 函数指针强制类型转换

```c
void (*p)(void) = (void (*)(void))add;  // 强制转型
p();  // 栈帧错乱 → HardFault
```

> 永远用 typedef 统一类型，永远不要强制转换函数指针。

### 3. 函数指针表不加 const

```c
// ❌ 不加 const → 表放 .data 段，占用 RAM
static StateHandler s_state_table[] = {...};

// ✅ 加 const → 表放 Flash，省 RAM
static const StateHandler s_state_table[] = {...};
```

### 4. 函数指针大小平台相关

| 架构 | 大小 | 说明 |
|------|------|------|
| Cortex-M0/M0+ | 2 B | Thumb 指令，16 位地址 |
| Cortex-M3/M4/M7 | 4 B | 32 位地址空间 |
| Cortex-A (32-bit) | 4 B | 标准 ARM 32 位 |
| Cortex-A (64-bit) | 8 B | AArch64 模式 |

移植代码时结构体布局可能因函数指针大小变化而出错。

## 速查

| 概念 | 一句话 |
|------|--------|
| 声明 | `void (*p)(int)` — 把函数名换成 `(*p)` |
| typedef | `typedef void (*Handler)(int);` — 定义统一回调类型 |
| 赋值 | `p = func;` — 函数名就是地址 |
| 调用 | `p(100);` — 隐式解引用，最简洁 |
| 回调注册 | 用户注册函数，底层在适当时机调用 |
| 函数指针表 | 用枚举索引替代 switch-case |
| const | 运行时不变的表必须加 `const`（放 Flash） |
| 中断安全 | 回调只做标记，不做处理 |
