# 固件静态逆向方法

> 面向 Cortex-M 裸机/RTOS 固件的纯静态逆向方法论:无调试器、无原理图也能做到字节级/算术级实锤。核心纪律是**证据分级**——把"已确认(字节与算术证据)""推测(有依据未验证)""存疑(无法确认)"严格分开。

> [!note] 本文的方法沉淀自两次完整逆向战役(详见 [2026-08-28 - RD2005P-M-BT 电池包 BMS 固件逆向](../../来源/2026-08-28%20-%20RD2005P-M-BT%20电池包%20BMS%20固件逆向.md) 与 [2026-08-28 - STM32L4 双存储固件逆向](../../来源/2026-08-28%20-%20STM32L4%20双存储固件逆向.md)),两次战役均达到 50%+ 字节覆盖与关键机制数值级实锤。

## 1. 证据分级纪律

| 等级 | 标准 | 例子 |
|------|------|------|
| **已确认** | 字节级/算术级证据(反汇编指令序列、常量池字面量、dump 交叉验证) | `movw r0,#0x8005` 循环 + RBIT = CRC 算法 |
| **推测** | 有依据但未动态验证(上下文推断、不变量推理) | 阈值浮点常量的单位归属 |
| **存疑** | 无法确认,须实测 | 精确芯片型号 |

逆向报告如不强制分级,结论会被误读为"这就是真相"。建议每份报告附存疑清单(编号列表)。

## 2. 分析管道(Capstone 自研管道模式)

1. **线性反汇编**:`scripts/` 用 Capstone 全量反汇编,存为 asm/txt 以便 grep 与注释
2. **函数恢复**:跟踪 BL/BLX 与 PC 相对分支重建函数边界,建 `funcmap.txt`(地址/大小/调用/被调/字面量引用)+ `funcs.json`(机器可读)+ `calls.tsv`(调用边表)
3. **常量普查**:movw/movt + PC 相对寻址即字面量池;导出 `consts.tsv`、`floats.txt`(浮点常量及引用位置)、`pools.txt`(外设/信息块/RAM 引用统计)
4. **覆盖率评估**:已恢复函数字节数 ÷ 镜像字节数,剩余多为数据池、跳转表、运行时回调静态不可达

## 3. 识别策略(无符号固件的上手路径)

| 证据 | 用途 | 说明 |
|------|------|------|
| 外设基址字面量池 | 芯片家族判定 | RCU 0x40021000 / FMC 0x40022000 / CAN0 0x40006400 等;FMC 解锁序列 `0x45670123`+`0xCDEF89AB` 是 STM32F1/GD32F10x 指纹 |
| 家族排除法 | 芯片判定 | RCC+0x4C = AHB2ENR → 排除 F1/GD32F10x;RCC+0x58 APB1ENR1 bit25 = CAN1EN → L4 专属;bxCAN@0x40006400 排除 G4(FDCAN@0x4000A400) |
| 浮点常量池 | 阈值提取 | BMS 保护阈值(电压/温度/电流/容量)、校准系数(-0.5 级偏置 + 微修正 = ADC 出厂标定) |
| 字符串区 | 身份识别 | 固件 ID/版本/序列号记录(如 `DBT1.1.0 HW1.1.1`);全镜像无字符串 = 剥离符号或纯数值协议 |
| 段落标记 | 结构确认 | `A5A5` magic、镜像尾 `AA 55 ...`、`0xAAAAAAAA` 数据块尾 |

## 4. Bootloader 分析要点

- **向量表读取**:`VT[0]=SP, VT[1]=Reset`;跳转校验常见规则 = `SP & 0x2FFE0000 == 0x20000000` 且 Reset ∈ (app 基址, 镜像尾]
- **启动链**:SystemInit 写 CPACR(FPU)、清 CICR、PLLCFGR 复位值、VTOR 设置;`.data` 拷贝(常含 RAM 向量表副本)+ `.bss` 清零
- **FMC 编程驱动**:解锁(查 LOCK 位→写 KEY)→ 字编程(CTL bit0 PG)→ 锁定(bit7);`str r1,[r0]` 直写即字编程
- **升级协议**:常见三种原语链 = 擦页(2KB/4KB)→ 从传输介质复制 → 重算校验(CRC)→ 比对;接收侧多用中断+状态机

## 5. CRC 指纹识别(重要坑)

反射实现的 CRC 用 **RBIT/位反转** 显式编码时,与标准 MSB-first 形式表面不同:

```
输入:逐字节 RBIT(位序反转) → 异或入高位 → MSB-first 位循环
输出:16 位 RBIT
```

识别线索:常量池 `0x8005` (poly) + `0xFFFF` (init) + 明显反射操作 → **MODBUS CRC16**(反射 poly 0xA001)。验证方法:对 dump 重算并与存储值比对(实测 0xBDD5 吻合)。已知教训:不认识 RBIT 语义时易误判为标准 MSB CRC,导致"CRC 语义难还原"的假象。

## 6. 自研 RTOS 识别

- 调度器指纹:SysTick handler 调 `msr basepri` 关中断 + 写 ICSR bit28 触发 PendSV + 恢复 basepri;PendSV 上下文切换;SVC 启动首个任务(xPSR 构造初始栈帧)
- 任务表:28 字节描述符 {ptr, func, prio, _, stack, _, _} 连续数组;栈大小与 RAM 总量对得上 → 置信度高
- 临界区:basepri 阈值 + 嵌套计数

## 7. 外置存储记录格式分析

- 周期记录:固定长度(如 256B)顺序追加,含序列号(u16)+ 出厂常量(u32,跨 dump 不变)+ 运行累计量(同 dump 内恒定、跨 dump 跳变)+ 未知状态量
- 快速日志:尾部追加 `{u32 seq, u32 counter, u32 value}`,速率与测量任务周期吻合
- 记录生命周期:写回(PP)→ 滚动 → 扇区擦除(SE 0x20);擦除后全 FF = "全新记录"初始化路径
