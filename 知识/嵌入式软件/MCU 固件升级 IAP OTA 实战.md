# MCU 固件升级 IAP OTA 实战

## 一句话

**固件升级不是代码搬运，而是覆盖分区设计、数据校验、堆栈管理、异常回滚的完整安全体系——漏掉一个细节就可能导致整批设备变砖。**

## 术语定义

| 术语 | 含义 |
|------|------|
| **IAP** (In-Application Programming) | 本地协议直连升级：串口、I2C、SPI、CAN |
| **OTA** (Over-The-Air) | 无线远程升级：WiFi、蓝牙、4G、NB-IoT |
| **Bootloader** | 引导程序，负责跳转调度、Flash 擦写、异常恢复 |

## 五种升级架构

核心差异就两个问题：**谁来收固件**、**谁来擦写搬运**。

### 架构全景对比

| # | 架构 | 收固件 | 擦写搬运 | 安全性 | 量产推荐 |
|---|------|--------|----------|--------|----------|
| 一 | Boot 全包 | Boot | Boot | ❌ 断电变砖 | 仅产线调试 |
| 二 | Boot 收+备份区搬 | Boot | Boot | ✅ 备份区保护 | 串口 IAP |
| 三 | A/B 双分区 | Boot | Boot | ✅ 无损回滚 | 工业/车载首选 |
| 四 | APP 收+Boot 搬 | APP | Boot | ✅ 职责分离 | **全场景最主流** |
| 五 | APP 直写 A/B | APP | APP | ✅ 引导极简 | Flash 充足时首选 |

### 架构一：Boot 全包（最简但最危险）

业务程序收到升级指令 → 复位/跳转进入 Boot → Boot 直接擦除业务程序 → Boot 接收新固件并写入运行区 → 跳转执行

> [!warning] 升级中途断电 = 变砖
> 擦除后、写完前断电→只剩 Boot，无法恢复。**严禁用于量产产品。**

### 架构二：Boot 收+备份区搬（经典 IAP）

Boot 接收新固件 → 写入独立备份区（不擦运行区）→ 整包接收完成 + 校验通过 → 擦除运行区 → 搬运到运行区 → 跳转执行

搬运中途断电也不影响原有程序，设备可正常恢复。

### 架构三：A/B 双分区（最高可靠性）

当前运行 A 分区 → 收到升级 → Boot 擦除 B 分区 → 写入 B 分区 → 校验通过 → 修改标志位 → 下次上电跳转 B 分区 → 下次升级反向操作（B→A）

> [!important] 量产首选
> 始终保留一份完整可用固件，断电、固件异常均可无损回滚。工业设备、车载设备、高端 IoT 首选。

### 架构四：APP 收+Boot 搬（最主流）

业务程序接收新固件 → 写入备份区 → 整包校验通过 → 复位进入 Boot → Boot 再次校验 → 擦除运行区 → 搬运 → 跳转

职责拆分清晰：**Boot 极简稳定、长期无需改动**；升级逻辑随业务工程迭代。

### 架构五：APP 直写 A/B（引导最简）

A 分区运行 → 接收新固件 → 写入 B 分区 → 校验 → 改标志位 → 复位 → Boot 仅读取标志位 → 跳转对应分区

Boot 代码量极小、几乎无改动。Flash 充足的设备推荐优先选用。

## 传输协议选型

### 本地 IAP

| 协议 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| **串口 + Ymodem** | 上位机原生支持，零开发成本，支持断点续传 | 需物理连接 | **产线烧录首选** |
| I2C | 引脚少，布线简洁 | 速率低，无标准文件协议 | 板内从机升级 |
| SPI | 速率远高于 I2C | 无标准协议，需自研帧格式 | 外挂 SPI Flash 升级 |
| CAN | 抗干扰极强，支持多设备组网 | 单帧数据量小，需精细分包 | 工业/车载批量升级 |

> [!tip] I2C/SPI/CAN 不用强套通用文件协议
> 按需自研简易帧格式，配齐分包、重传、校验逻辑即可满足量产需求。

### 远程 OTA

无线类（WiFi/蓝牙/BLE/4G/NB-IoT）+ 有线类（以太网），全部使用**自定义应用层协议 + 加密 + 校验 + 断点续传**。

### 选型总结

- **产线调试/人机直连** → 串口 Ymodem
- **板内短距多设备** → I2C / SPI
- **工业车载组网** → CAN 总线
- **远程运维/迭代** → 无线 + 私有加密协议

## 三层校验体系

> [!important] 分包传输成功 ≠ 固件可用
> 每包校验通过 ≠ 整包完整。必须配齐**三层校验**：包级实时拦截 → 整包全局兜底 → 合法性签名。

### 第一层：数据包级实时校验

| 算法 | 特点 | 适用 |
|------|------|------|
| 累加和 SUM | 极简、低算力 | 低端 MCU、基础防护 |
| **CRC16/CRC32** | 抗干扰强、量产标配 | 全场景首选 |

每帧数据附带 CRC，接收校验失败直接请求重传——从源头拦截错误数据。

### 第二层：整固件完整性校验

接收完成后必须做全局二次校验：
1. 魔数校验 — 首尾固定标识（如 0xAA55AA55）
2. 全局长度比对 — 实际接收字节 vs 固件头部声明的长度
3. 全局 CRC32 — 上位机写入，设备端遍历全量数据比对

差分升级场景：补丁包校验 + 固件合成后再做一次全局 CRC，双重兜底。

### 第三层：固件合法性校验（防篡改）

| 级别 | 方案 | 适用 |
|------|------|------|
| 基础 | 版本号 + 设备 ID 绑定 | 禁止跨设备/降级刷机 |
| 中级 | 对称加密 | 中小型商用设备 |
| **高级** | **RSA 非对称签名验签** | 车载、安防、公网 OTA |

**RSA 验签流程**：云端用私钥对固件摘要签名 → 设备固化公钥验签。私钥不泄露，第三方无法伪造合法固件。公钥应固化在 Boot 只读区域。

## 分区规划

以市面最常用的 512KB 片内 Flash 为基准，可按实际芯片等比例缩放。**所有分区必须按 Flash 扇区大小对齐，内部 Flash 写入需 4 字节对齐。**

### 方案一：单备份区（思路二/四，IAP+OTA 通用）

| Boot (32KB) | APP (416KB) | Backup (32KB) | Flag (8KB) | DCD (8KB) |
|---|---|---|---|---|
| 0x08000000 | 0x08008000 | ... | ... | 0x08080000 |

### 方案二：A/B 双分区（思路三/五，高端量产）

| Boot (32KB) | APP_A (192KB) | APP_B (192KB) | Flag (16KB) | DCD (8KB) |
|---|---|---|---|---|
| 0x08000000 | 0x08008000 | 0x08038000 | ... | ... |

### 方案三：差分升级（弱网 OTA 首选）

基于 A/B 双分区，额外划分独立补丁缓存区存放新旧固件差异数据。极少用于串口 IAP。

## 链接脚本修改

核心作用：限定程序编译后的存储范围，**禁止代码越界占用备份区/标志区**。

```ld
/* Boot 脚本（固定不变） */
FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 32K

/* 单备份区 - 业务程序 */
FLASH (rx) : ORIGIN = 0x08008000, LENGTH = 416K

/* A/B 分区 - 两套工程分别配置 */
/* A 分区 */
FLASH (rx) : ORIGIN = 0x08008000, LENGTH = 192K
/* B 分区 */
FLASH (rx) : ORIGIN = 0x08038000, LENGTH = 192K
```

业务程序必须在初始化第一行重定向向量表：

```c
SCB->VTOR = FLASH_BASE | 0x8000;  // 解决升级后中断失效的核心
```

## 跳转方式

### 三种方式对比

| 方式 | 稳定性 | 风险 | 推荐度 |
|------|--------|------|--------|
| **系统复位** `NVIC_SystemReset()` | 最稳定 | 无残留 | ⭐⭐⭐⭐⭐ 通用推荐 |
| 内核复位 `SCB->AIRCR` | 中 | DMA/定时器残留 | ⭐⭐ 特殊场景 |
| 直接地址跳转 | 最低 | 需手动清全部环境 | ⭐ 不推荐量产 |

### Boot → APP 跳转（双编译器版本）

**ARM-CC 版本**：

```c
typedef void (*iapfun)(void);
iapfun jump2app;

__asm void MSR_MSP(uint32_t addr) {
    MSR MSP, r0
    BX r14
}

void iap_load_app(uint32_t appxaddr) {
    // 1. 校验 Flash 区间合法性
    // 2. 校验栈顶是否在 SRAM 区间 (0x2000xxxx)
    if ((appxaddr >= FLASH_BASE) && (appxaddr < FLASH_END) &&
        (((*(vu32*)appxaddr) & 0xF0000000) == 0x20000000))
    {
        MSR_MSP(*(vu32*)appxaddr);             // 1. 先切堆栈
        jump2app = (iapfun)*(vu32*)(appxaddr+4); // 2. 取复位入口
        jump2app();                              // 3. 跳转
    }
}
```

**GCC 版本**：

```c
void MSR_MSP(uint32_t addr) {
    __asm__ volatile (
        "MSR MSP, %[addr] \n\t"
        "BX LR \n\t"
        : : [addr]"r"(addr)
    );
}
// iap_load_app 逻辑同上
```

> [!warning] 跳转三步顺序不可颠倒
> ①先切 MSP 堆栈 → ②再取复位入口 → ③最后跳转。顺序错 = HardFault。

## DCD 设备配置区

传统做法把时钟、串口引脚、波特率、Flash 分区硬编码在 Boot 里，硬件改版就要重编译 Boot。

**优化**：将所有硬件配置从 Boot 剥离，由业务程序写入独立 Flash 配置区（DCD）。Boot 上电读取 DCD 动态初始化硬件 → **一套 Boot 兼容多款硬件板卡**。

## 差分升级全流程

核心优势：只传差异数据，节省 70%~90% 流量。弱网蜂窝 OTA 的最优解。

1. **云端**: 旧固件 + 新固件 → bsdiff/hdiff → patch.bin → 加密下发
2. **设备 APP**: 分片接收 → 逐包 CRC → 写入补丁区 → 校验通过 → 复位进 Boot
3. **Boot**: 加载旧固件 + 解析 patch → 合成新固件 → 写入空闲分区
4. **二次校验**: 全量 CRC/SHA256 → 校验失败则清标记/删补丁/放弃升级
5. **分区切换**: 清除补丁数据 → 更新分区标记 → 跳转新固件

### 异常回滚

| 异常 | 行为 |
|------|------|
| 补丁接收中断/断电 | 无有效升级标记，下次上电正常运行旧固件 |
| 固件合成失败 | 自动放弃，保留原有可用分区 |
| 新固件启动异常 | Boot 检测启动状态，自动切回上一稳定版本 |

## 防变砖核心准则

1. **禁止边接收边擦写正在运行的业务分区**——必须接收完成+双重校验通过后再擦除
2. **APP 校验 + Boot 二次校验** 双层兜底
3. **升级状态、版本、CRC 存入独立 Flash 扇区**——不参与任何固件擦写，断电不丢失
4. **高可靠产品优先 A/B 双分区**——永久保留可用固件，故障自动回滚
5. **差分升级三步验证**——补丁合法 → 合成成功 → 固件校验全部通过，才切换分区

## 常见问题排查

### 内核复位后跳转跑飞

**根因**：内核复位不复位外设，DMA/定时器/UART 仍在运行篡改 RAM；指令缓存未关闭残留旧指令；Boot 与 APP 的时钟/编译选项不一致。

**解决**：跳转前关闭总中断、SysTick/DMA/外设、指令缓存、清空 NVIC 中断标志、重新配置向量表与堆栈。**保证 Boot 与 APP 的时钟配置、编译选项完全统一。**

### RTOS 下跳转崩溃

RTOS 使用 PSP（进程堆栈），Bootloader 使用 MSP（主堆栈），直接跳转必崩。

```c
// 标准步骤
停止所有任务 → 关闭调度器 → 关闭全局中断
  → __set_CONTROL(0);  // 切回 MSP
  → 清理外设/中断环境 → 执行跳转/复位
```

### Flash 擦写期间误触发看门狗

长时间升级过程中必须**定期喂狗**，避免独立看门狗/窗口看门狗误触发复位打断升级。

## 架构选型决策树

**Flash 容量是否充足？**
- 充足（≥512KB）→ A/B 双分区（思路三/五）
  - 还要低流量 OTA？→ A/B + 差分升级
- 紧张 → 单备份区（思路四：APP 收+Boot 搬）
  - 仅产线调试？→ 思路一（最简但禁用量产）

**通信方式？**
- 本地有线 → 串口 Ymodem / I2C / SPI / CAN
- 远程无线 → 私有协议 + 加密 + 断点续传

**安全等级？**
- 消费级 → CRC32 + 魔数 + 版本绑定
- 工业/车载 → +RSA 签名验签 + Flash 读写保护
