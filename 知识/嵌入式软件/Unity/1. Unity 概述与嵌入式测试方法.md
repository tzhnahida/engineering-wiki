# 1. Unity 概述与嵌入式测试方法

## 定位

Unity 是 ThrowTheSwitch 维护的纯 C 单元测试框架，设计目标就是嵌入式。三文件（`unity.h` + `unity_internals.h` + `unity.c`），零动态内存分配，全部状态一个全局结构体。

| 指标 | 值 |
|------|-----|
| 核心文件 | 3 files, ~300KB 源码 |
| 编译后 ROM | ~5-10KB（不含 float/double） |
| 全局状态 RAM | ~40-80 bytes |
| malloc | 0（零堆分配） |
| 断言数量 | 200+ 宏 |
| 协议 | MIT |

## 测试模型

```
main()
 ├── setUp()      ← 每个测试前
 ├── test_func()  ← 被测函数
 ├── tearDown()   ← 每个测试后
 └── UNITY_END()  ← 打印摘要：X Tests Y Failures Z Ignored
```

### setjmp 保护

```c
void UnityDefaultTestRun(UnityTestFunction Func, const char* Name, int Line) {
    if (TEST_PROTECT()) { setUp(); Func(); }
    if (TEST_PROTECT()) { tearDown(); }
    UnityConcludeTest();
}
```

`TEST_PROTECT()` = `setjmp(Unity.AbortFrame) == 0`。断言失败时 `longjmp` 跳出当前测试但不影响 tearDown——第二个 `PROTECT` 保证 tearDown 总执行。相当于 C++ RAII 的 C 语言等价。

## 断言家族总览

### 基本断言

```c
TEST_ASSERT(condition);           // 条件为真
TEST_ASSERT_TRUE(condition);      // 同上，语义化
TEST_ASSERT_FALSE(condition);
TEST_ASSERT_NULL(ptr);            // 指针为 NULL
TEST_ASSERT_NOT_NULL(ptr);
```

### 整数比较（全尺寸覆盖）

```c
TEST_ASSERT_EQUAL_INT(expected, actual);
TEST_ASSERT_EQUAL_INT8/16/32/64(expected, actual);
TEST_ASSERT_EQUAL_UINT/UINT8/16/32/64(expected, actual);
TEST_ASSERT_EQUAL_HEX/HEX8/16/32/64(expected, actual);
TEST_ASSERT_BITS(mask, expected, actual);   // 位掩码比较
TEST_ASSERT_BIT_HIGH(mask, actual);          // mask 位全为 1
TEST_ASSERT_BIT_LOW(mask, actual);           // mask 位全为 0
```

### 比较与范围

```c
TEST_ASSERT_GREATER_THAN(threshold, actual);
TEST_ASSERT_LESS_THAN(threshold, actual);
TEST_ASSERT_INT_WITHIN(delta, expected, actual);  // 容忍 ±delta 误差
```

### 浮点

```c
TEST_ASSERT_EQUAL_FLOAT(expected, actual);
TEST_ASSERT_FLOAT_WITHIN(delta, expected, actual);
TEST_ASSERT_FLOAT_IS_NAN(val);
TEST_ASSERT_FLOAT_IS_INF(val);
```

### 字符串与内存

```c
TEST_ASSERT_EQUAL_STRING(expected, actual);
TEST_ASSERT_EQUAL_STRING_LEN(expected, actual, len);
TEST_ASSERT_EQUAL_MEMORY(expected, actual, len);
```

### 数组

```c
TEST_ASSERT_EQUAL_INT_ARRAY(expected, actual, num_elements);
TEST_ASSERT_EACH_EQUAL_INT(expected, actual, num_elements);  // 每个元素 == expected
TEST_ASSERT_INT_ARRAY_WITHIN(delta, expected, actual, elements);
```

### 附加消息

每个断言都有 `_MESSAGE` 变体：
```c
TEST_ASSERT_EQUAL_INT_MESSAGE(a, b, "After reset, counter should be 0");
// 失败输出: FAIL: expected 5 was 3 - After reset, counter should be 0
```

## 嵌入式集成

### 输出抽象（关键）

Unity 不使用 `printf`，所有输出通过一个宏：

```c
#define UNITY_OUTPUT_CHAR(a)    /* 你的单字符输出函数 */
```

STM32 上的几种方式：

| 方式 | 宏定义 |
|------|--------|
| UART | `#define UNITY_OUTPUT_CHAR(a) HAL_UART_Transmit(&huart2, &(a), 1, 100)` |
| SWO/ITM | `#define UNITY_OUTPUT_CHAR(a) ITM_SendChar((uint32_t)(a))` |
| SEGGER RTT | `#define UNITY_OUTPUT_CHAR(a) SEGGER_RTT_WriteChar(0, (a))` |
| 无输出（仅计数） | `#define UNITY_OUTPUT_CHAR(a) ((void)0)` |

### ROM 裁剪

| 宏 | 效果 |
|----|------|
| `UNITY_EXCLUDE_FLOAT` | 移除全部浮点断言和打印代码 |
| `UNITY_EXCLUDE_DOUBLE` | 移除全部双精度断言 |
| `UNITY_EXCLUDE_FLOAT_PRINT` | 移除浮点打印代码（保留断言） |
| `UNITY_EXCLUDE_SETJMP_H` | 禁用 longjmp（测试失败不中断当前测试） |

### 靶机测试流程

```c
int main(void) {
    HAL_Init();
    SystemClock_Config();
    uart_init();  // 初始化 UNITY_OUTPUT_CHAR 所需的硬件
    
    UNITY_BEGIN();
    RUN_TEST(test_adc_read_voltage);
    RUN_TEST(test_pwm_frequency);
    RUN_TEST(test_uart_baudrate);
    return UNITY_END();  // 返回失败数，0=全部通过
}
```

## 与 printf 调试的本质区别

| | printf 调试 | Unity 测试 |
|--|------------|-----------|
| 执行 | 手动运行+肉眼检查输出 | 自动运行+机器判断 pass/fail |
| 回归 | 无——每次改代码都要重测 | 一键跑全部已有测试 |
| 文档 | 代码即文档……直到注释过时 | 测试即规格，不会过时 |
| CI 集成 | 不可行 | 退出码即可集成 |
| 时间 | 编译-烧录-手动操作 | 编译-跑-0.1秒结果 |

**核心价值**：测试让"改完代码不知道坏了什么"变成"改完代码立即知道什么坏了"。在嵌入式这种"烧一次固件慢如登天"的场景，测试的复利效应更大。
