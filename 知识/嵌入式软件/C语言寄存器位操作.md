# C语言寄存器位操作

位操作是嵌入式 C 语言中最频繁的操作模式——MCU 寄存器往往多位复用，配置一个外设需要精确控制：哪些位置 1、哪些位置 0、哪些位保持不变。本文从掩码的工程语义出发，覆盖基本操作、多位字段、读改写风险、原子操作和常见坑点。

## 掩码：修改范围的描述

位操作的核心不是 `&` `|` `^` `~` 四个符号，而是**掩码（mask）**——一个用二进制描述"修改哪些位"的数。

### 为什么直接赋值会出错

假设一个 8 位控制寄存器 CTRL：

```
bit 7      bit 6:4     bit 3       bit 2:0
ENABLE     MODE        IRQ_EN      CLOCK_DIV
```

只想打开 IRQ_EN（bit 3），写成：

```c
CTRL = 0x08U;  /* ❌ 错误：其他位全部被清零 */
```

0x08 = `0000 1000`，bit 3 确实变成了 1，但 bit 7–4 和 bit 2–0 也全部变成 0——原来的 MODE、CLOCK_DIV、ENABLE 全部丢失。

正确做法是用掩码做**读改写**：

```c
CTRL |= (1U << 3);  /* ✅ 只将 bit 3 置 1，其他位不变 */
```

### 掩码的生成：左移

```c
1U << 3   /* 0000 0001 → 0000 1000 */
1U << n   /* 通用：将 1 左移 n 位，选中第 n 位 */
```

| 要点 | 说明 |
|------|------|
| 显式 `U` 后缀 | 保证无符号，避免有符号移位的不确定行为 |
| 移位范围 | `n` 必须在 `0` 到 `位宽-1` 之间；超出范围是未定义行为 |
| 类型宽度 | `(uint32_t)1U << n` 显式指定 32 位掩码 |

### 十六进制与具名掩码

工程中优先使用芯片头文件提供的具名掩码：

```c
#define TIMER_CTRL_ENABLE  ((uint32_t)1U << 0)
#define TIMER_CTRL_IRQ_EN  ((uint32_t)1U << 3)
```

`TIMER_CTRL_IRQ_EN` 比 `0x08U` 直接表意，也不容易写错偏移量。

## 四种基本操作

设 `reg` 为可读写的 32 位寄存器，`mask` 已选中目标位：

| 操作 | 写法 | 效果 |
|------|------|------|
| **置位** (Set) | `reg \|= mask` | 目标位变为 1 |
| **清零** (Clear) | `reg &= ~mask` | 目标位变为 0 |
| **翻转** (Toggle) | `reg ^= mask` | 目标位 0↔1 互换 |
| **读取** (Test) | `if ((reg & mask) != 0U)` | 检测目标位是否为 1 |

### 清零为什么要取反

```c
原值    1010 1011
mask    0000 1000
~mask   1111 0111
& 后    1010 0011   /* 目标位 (bit 3) 变为 0，其他位不变 */
```

### 读取时的常见错误

```c
/* ❌ 错误：bit 7 置位时结果为 0x80 (128)，不是 1 */
if ((reg & (1U << 7)) == 1U) { ... }

/* ✅ 正确 */
if ((reg & (1U << 7)) != 0U) { ... }

/* ✅ 如果确实需要 0/1 值 */
uint32_t bit_value = (reg >> bit) & 1U;
```

### 多位组合掩码

```c
uint32_t mask = TIMER_STATUS_READY | TIMER_STATUS_ACTIVE;

/* 至少有一位为 1 */
if ((TIMER->STATUS & mask) != 0U) { ... }

/* 所有位都为 1 */
if ((TIMER->STATUS & mask) == mask) { ... }
```

## 多位字段操作

寄存器中常有多位组成的配置字段（如 MODE 占 bit 4–6），不能直接用 `|=`。

### 写入：先清后写

```c
#define CTRL_MODE_Pos  4U
#define CTRL_MODE_Msk  ((uint32_t)0x7U << CTRL_MODE_Pos)  /* 3-bit 字段 */

uint32_t mode = 2U;

/* 先清除旧字段，再放入新值 */
reg = (reg & ~CTRL_MODE_Msk)               /* 清旧值 */
    | ((mode & 0x7U) << CTRL_MODE_Pos);    /* 放新值（先限宽再移位） */

/* ⚠️ 为什么不能直接用 |= */
reg |= (2U << 4);  /* 旧值 111 | 010 = 111，旧 1 不会被清除 */
```

三步口诀：**屏蔽旧字段 → 限制新值宽度 → 左移到目标位**

### 读取：先掩后移

```c
uint32_t mode = (reg & CTRL_MODE_Msk) >> CTRL_MODE_Pos;
```

## STM32F103 实例：配置 PC13

STM32F103 的 GPIO 配置寄存器中，每个引脚占 4 位（高 2 位 CNF + 低 2 位 MODE）。GPIOx_CRL 管理引脚 0–7，GPIOx_CRH 管理引脚 8–15。PC13 位于 GPIOC->CRH。

```c
#define GPIO_PIN         13U
#define GPIO_FIELD_WIDTH 4U
#define GPIO_FIELD_MASK  0xFU

/* PC13 在 CRH 中的偏移：第 5 个字段，即 bit 20–23 */
uint32_t position = (GPIO_PIN - 8U) * GPIO_FIELD_WIDTH;  /* = 20 */

/* 配置为 2MHz 通用推挽输出：CNF=00, MODE=10 → 0010 = 0x2 */
uint32_t crh = GPIOC->CRH;
crh &= ~(GPIO_FIELD_MASK << position);    /* 清除 PC13 的 4 位 */
crh |=  (0x2U << position);               /* 放入新配置 */
GPIOC->CRH = crh;                         /* 一次写回 */

/* ⚠️ 前提：需要先使能 GPIOC 时钟 (RCC->APB2ENR) */
/* ⚠️ 前提：单任务独占配置，无并发访问 */
/* 💡 工程中优先使用 HAL/LL 库，此处仅为演示"先清后写"的硬件含义 */
```

## 读改写 (RMW) 的硬件风险

`REG |= mask` 在 CPU 层面展开为三步：

```
1. 读取寄存器当前值
2. 在 ALU 中 OR 上 mask
3. 将结果写回寄存器
```

这三步不是原子的，在以下场景会产生问题：

### W1C 状态位 (Write-One-to-Clear)

有些状态寄存器向某位写 1 会清除标志，写 0 保持不变。如果 STATUS 的 bit 0 和 bit 1 都已置位：

```c
STATUS |= STATUS_FLAG0_Msk;  
/* 读回 0b11 → OR 上 flag0 → 写回 0b11
   → bit 1 也被写回了 1 → bit 1 可能被意外清除！*/
```

W1C 寄存器通常应**直接写入目标掩码**而非 `|=`：

```c
STATUS = STATUS_FLAG0_Msk;  /* 只清除 flag0 */
```

### 中断/任务并发覆盖

```
时序：
  主程序: 读取 ODR (旧值)
  中断:   修改 ODR 并写回
  主程序: 基于旧值修改并写回        ← 覆盖了中断的修改！
```

`volatile` 只能保证每次读写真实发生，不能使 RMW 变成原子操作。

### STM32 的解决方案：BSRR

STM32F103 的 GPIOx_BSRR 寄存器提供了原子位操作能力：

```c
/* 置位 PC13 — 直接写，无需先读 */
GPIOC->BSRR = (1U << 13);            /* 低 16 位写 1 → 对应引脚置高 */

/* 复位 PC13 */
GPIOC->BSRR = (1U << (13 + 16));     /* 高 16 位写 1 → 对应引脚置低 */

/* 或使用头文件具名掩码 */
GPIOC->BSRR = GPIO_BSRR_BS13;        /* 置位 */
GPIOC->BSRR = GPIO_BSRR_BR13;        /* 复位 */
```

**原则**: 硬件提供原子置位/复位接口时，优先使用，不用普通寄存器 RMW 替代。

## 常见坑点

### 1. 按位运算 vs 逻辑运算

```c
uint8_t a = 0x02U, b = 0x01U;
a & b    /* = 0x00 — 按位与：没有共同的置位位 */
a && b   /* = 1 — 逻辑与：两者都非零 */

/* 位检查用 &，条件组合用 && */
if (((STATUS & READY_MASK) != 0U) && (timeout == 0U)) { ... }
```

### 2. 运算符优先级

```c
/* ❌ 错误：先算 mask == mask (恒为真 = 1)，再 STATUS & 1 */
if (STATUS & mask == mask) { ... }

/* ✅ 正确 */
if ((STATUS & mask) == mask) { ... }
```

### 3. 有符号数移位

```c
/* ❌ 不可移植：有符号数右移结果由实现定义 */
int x = -1; x >> 1;

/* ✅ 始终使用无符号类型 */
uint32_t mask = (uint32_t)1U << bit;  /* bit < 32 */
```

### 4. 小整数提升

`uint8_t`、`uint16_t` 参与 `~` 和移位时通常先提升为 `int`。需要严格控制宽度时，显式转换：

```c
uint16_t result = (uint16_t)((uint32_t)data & 0xFFFFU);
```

### 5. 宏陷阱

```c
#define SET_BIT(reg, bit) reg |= 1 << bit  /* ❌ 不推荐 */

/* 问题：SET_BIT(STATUS, 3) + 1 → 展开为 STATUS |= 1 << 3 + 1
   先算 3+1=4，选中了第 4 位而非第 3 位 */

/* 即使加了括号，宏也不知道寄存器是不是 W1C、只写或有副作用 */
```

### 6. C 位域不适合映射硬件寄存器

位域的布局、分配顺序和访问宽度由编译器实现定义，编译器还可能生成硬件不允许的读改写。除非工具链和 ABI 经过验证，否则优先使用芯片厂商定义的整型寄存器和具名掩码。

## 寄存器不生效的排查顺序

1. 时钟使能了没有（RCC 时钟门控）
2. 外设电源开了没有
3. 引脚复用功能配置了没有
4. 掩码和移位位置与参考手册是否一致
5. 多位字段是否先清了旧值
6. 寄存器是否需要特定的写访问时序（解锁序列等）
7. 是否有中断或 DMA 同时修改同一寄存器

> ⚠️ 使用调试器观察寄存器时，某些状态位可能因读取而清除；调试器刷新寄存器窗口的读取同样可能改变硬件状态。

## 工程原则总结

| 原则 | 说明 |
|------|------|
| **明确宽度** | 寄存器和协议字段使用 `uint32_t` 等明确宽度无符号类型 |
| **具名掩码** | 优先使用芯片头文件的位定义，不散落魔法数字 |
| **先清后写** | 多位字段操作：清旧 → 限宽 → 移位 → 写入 |
| **确认 RMW 语义** | 使用 `\|=` / `&=` 前，确认寄存器允许读改写 |
| **原子接口优先** | 硬件提供 BSRR / 置位寄存器 / 清零寄存器时直接用 |
| **volatile ≠ 原子** | 共享寄存器要有明确所有权，必要时用临界区或原子操作 |
| **查手册** | 芯片头文件告诉你名字，参考手册告诉你访问语义，两者都要看 |
