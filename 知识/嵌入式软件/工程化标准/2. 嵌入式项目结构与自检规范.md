# 2. 嵌入式项目结构与自检规范

> 对应工程化第 1 层（目录统一）+ 第 2 层（代码质检）。

## 统一目录结构

所有 STM32 项目遵守同样的顶层布局。无论 Keil 还是 Makefile 构建，源码树的结构不变：

```
project-name/
├── Makefile / CMakeLists.txt    # 构建入口（第 3 层才需要）
├── README.md                    # 项目说明：MCU 型号、板卡、接线、烧录方式
├── src/                         # 所有源代码
│   ├── main.c                   # 入口
│   ├── app/                     # 应用逻辑（跟硬件无关）
│   │   ├── controller.c         # PID/状态机/算法
│   │   └── protocol.c           # 通信协议解析
│   ├── bsp/                     # 板级支持包（跟具体板卡有关）
│   │   ├── bsp_led.c
│   │   ├── bsp_uart.c
│   │   └── bsp_imu.c
│   ├── hal/                     # STM32 HAL 库（CubeMX 生成，不动手改）
│   └── vendor/                  # 第三方库
│       ├── cJSON/
│       ├── CmBacktrace/
│       └── FreeRTOS/
├── inc/                         # 公共头文件（对等 src/ 的结构）
├── test/                        # 测试代码
│   ├── test_runner.c            # 自检入口（#ifdef SELF_TEST 启用）
│   └── test_cases.c             # 测试用例
├── tools/                        # 上位机脚本、烧录脚本、配置工具
│   └── flash.cmd                 # openocd 烧录命令
└── doc/                          # 文档（不是维基——维基放知识，这里放本项目特有说明）
    └── pinout.md                 # 引脚分配表
```

### 关键规则

1. **CubeMX 生成的代码放 `hal/`**，永远不要手改里面的文件——CubeMX 重新生成会覆盖。自己的代码放 `src/`，头文件放 `inc/`。
2. **第三方库放 `vendor/`**。不要拷到项目里再改——用 Git submodule 或者直接引用源文件。改了就没法跟上游同步。
3. **测试代码单独目录**——不污染生产代码。
4. **一个 `main.c` 不够**——`src/app/` 和 `src/bsp/` 必须拆开。应用逻辑（算法、状态机）不 import 任何 HAL 头文件，只调 BSP 层接口。

### 分层依赖规则

```
src/app/       # 纯逻辑——不 import "stm32f4xx_hal.h"
    ↓ 调用接口
src/bsp/       # 硬件适配——可以 import HAL，但封装成统一接口
    ↓ 调用 HAL API
src/hal/       # CubeMX 生成——只被 bsp 层包含，app 层不可见
```

**硬规则**：`src/app/` 里的文件如果出现了 `HAL_GPIO_WritePin`，分层就失败了。app 层应该写 `led_on()`，由 bsp 层实现 `led_on()` 内部调用 `HAL_GPIO_WritePin`。

## 自检规范

### 核心模式：`#ifdef SELF_TEST`

```c
// main.c
int main(void)
{
    HAL_Init();
    SystemClock_Config();

#ifdef SELF_TEST
    test_runner();      // 自检模式——跑完所有测试，打印结果，死循环
#else
    app_init();         // 正常模式——启动应用逻辑
    while (1) {
        app_loop();
    }
#endif
}
```

编译自检版本：

```bash
# GCC
arm-none-eabi-gcc -DSELF_TEST ...

# Keil
# 在 C/C++ → Preprocessor Symbols → Define 里加 SELF_TEST
```

### 自检函数编写规范

每个模块提供自己的自检函数：

```c
// test/test_cases.c
#include "bsp_led.h"
#include "bsp_imu.h"
#include <stdio.h>

static int test_led(void) {
    led_init();
    led_on();
    HAL_Delay(10);
    // 自检：读回引脚电平（配置为输入模式读取）
    if (HAL_GPIO_ReadPin(LED_GPIO_Port, LED_Pin) == GPIO_PIN_SET) {
        printf("[TEST] LED:PASS\n");
        return 1;
    }
    printf("[TEST] LED:FAIL (pin not high after set)\n");
    return 0;
}

static int test_imu(void) {
    if (imu_init() != 0) {
        printf("[TEST] IMU_INIT:FAIL\n");
        return 0;
    }
    uint8_t whoami = imu_read_id();
    if (whoami == 0xEA) {  // ICM-20948 WHO_AM_I 值
        printf("[TEST] IMU_WHOAMI:PASS\n");
        return 1;
    }
    printf("[TEST] IMU_WHOAMI:FAIL (read 0x%02X, expected 0xEA)\n", whoami);
    return 0;
}
```

### 统一日志格式

所有自检输出遵守同一个模板，方便脚本解析：

```
[TEST] <模块名>:<子测试> <PASS|FAIL> [可选：失败原因]
```

正确示例：

```
[TEST] LED:PASS
[TEST] IMU_INIT:PASS
[TEST] IMU_WHOAMI:PASS
[TEST] I2C_SCAN:PASS (3 devices found)
[TEST] SD_CARD:PASS (FAT32, 7.6GB free)
[TEST] MOTOR1:FAIL (no encoder feedback after 100ms)
```

错误示例：

```
LED 亮了
imu ok
❌ motor
```

**规则**：
- 前缀 `[TEST]` 固定，方便 grep
- 模块名大写，子测试名大写，下划线分隔
- PASS/FAIL 大写
- 失败时附带原因——不要只写 FAIL，要写"为什么失败、读到什么值、期望什么值"

### 自检入口

```c
// test/test_runner.c
void test_runner(void)
{
    int passed = 0, total = 0;

    printf("\n=== SELF TEST START ===\n");
    printf("Firmware: %s\n", FW_VERSION);
    printf("Build: %s %s\n", __DATE__, __TIME__);

    total++; if (test_led()) passed++;
    total++; if (test_uart_loopback()) passed++;
    total++; if (test_imu()) passed++;
    total++; if (test_sd_card()) passed++;
    // ... 更多测试

    printf("\n=== SELF TEST END ===\n");
    printf("[RESULT] %d/%d passed\n", passed, total);

    if (passed == total) {
        printf("[STATUS] ALL_PASS\n");
    } else {
        printf("[STATUS] %d FAILED\n", total - passed);
    }

    while (1) {
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
        HAL_Delay(passed == total ? 500 : 200);  // 全通过慢闪，有失败快闪
    }
}
```

以后 CI 只需要 `grep "\[STATUS\]"` 就能判断整体结果。

## Version 标记

每个固件必须有一个可读的版本号——不是 git hash（那东西没法给人看），是语义化版本：

```c
// inc/version.h —— 由构建脚本生成，不要手写
#define FW_VERSION "1.2.3"
#define FW_GIT_HASH "abc1234"
#define FW_BUILD_DATE __DATE__
```

`version.h` 由构建脚本在编译前自动生成——Makefile 或 CI 脚本执行 `git describe --tags` 写入。手写版本号早晚会忘。
