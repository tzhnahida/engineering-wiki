# TinyUSB 类驱动与 OS 抽象

## 类驱动统一接口

所有 TinyUSB 设备类驱动实现 `usbd_class_driver_t` 接口：

```c
typedef struct {
    void (*init)(void);
    void (*reset)(uint8_t rhport);
    uint16_t (*open)(uint8_t rhport, tusb_desc_interface_t const *itf_desc, uint16_t max_len);
    bool (*control_xfer_cb)(uint8_t rhport, uint8_t stage, tusb_control_request_t const *req);
    bool (*xfer_cb)(uint8_t rhport, uint8_t ep_addr, xfer_result_t result, uint32_t xferred);
    void (*sof)(uint8_t rhport, uint32_t frame_count);  // 帧同步
} usbd_class_driver_t;
```

**控制传输回调的阶段参数**：
- `CONTROL_STAGE_SETUP` — Setup 包到达；类驱动检查请求并准备响应
- `CONTROL_STAGE_DATA` — 数据已接收（OUT）或已提供（IN）
- `CONTROL_STAGE_ACK` — 控制传输完成

## 主要设备类驱动

### CDC (虚拟串口)
- **端点**：2 个批量 (IN+OUT) + 1 个中断 (通知)
- **缓冲**：`tu_edpt_stream_t` 环形缓冲区
- **控制请求**：`SET_LINE_CODING` (波特率/停止位/校验)、`SET_CONTROL_LINE_STATE` (DTR/RTS)
- **API**：`tud_cdc_write(buf, len)`, `tud_cdc_read(buf, len)`, `tud_cdc_available()`

### MSC (大容量存储)
- **端点**：2 个批量 (IN+OUT)
- **协议**：BOT (Bulk-Only Transport) + SCSI 命令集
- **回调**：`tud_msc_read10_cb(lba, offset, buf, count)`, `tud_msc_write10_cb(...)`, `tud_msc_capacity_cb(lun)`

### HID (人机接口设备)
- **端点**：1 个中断 IN，可选 1 个中断 OUT (Set_Report)
- **支持**：自定义报告描述符或预定义键盘/鼠标/游戏手柄
- **API**：`tud_hid_n_report(instance, report_id, buf, len)`, `tud_hid_n_keyboard_report(instance, report_id, modifier, keycode[6])`

### DFU (设备固件升级)
- **两种模式**：
  - DFU 运行时 (`CFG_TUD_DFU_RUNTIME`)：响应 `DFU_DETACH` 触发重启
  - DFU 模式 (`CFG_TUD_DFU`)：完整固件更新 — 下载/上传/状态/中止

### Audio / MIDI
- **传输**：等时端点（需精确时序和帧同步）
- **子类**：AudioControl、AudioStreaming、MIDIStreaming

## OSAL (操作系统抽象层)

TinyUSB 自带四种 OSAL 实现：

| 头文件 | 目标 OS |
|--------|--------|
| `osal_none.h` | 裸机（自旋锁/忙等待） |
| `osal_freertos.h` | FreeRTOS |
| `osal_rtthread.h` | RT-Thread |
| `osal_mynewt.h` | Apache Mynewt |

### FreeRTOS OSAL 映射

| TinyUSB | FreeRTOS |
|---------|----------|
| `osal_semaphore_create(def)` | `xSemaphoreCreateBinary()` |
| `osal_semaphore_post(sem, in_isr)` | `xSemaphoreGive()` 或 `xSemaphoreGiveFromISR()` + `portYIELD_FROM_ISR()` |
| `osal_semaphore_wait(sem, timeout)` | `xSemaphoreTake()` ; `OSAL_TIMEOUT_WAIT_FOREVER` → `portMAX_DELAY` |
| `osal_semaphore_reset(sem)` | `xQueueReset()` |
| `osal_mutex_create(def)` | `xSemaphoreCreateMutex()` |
| `osal_mutex_lock(mtx, timeout)` | `xSemaphoreTake()` |
| `osal_queue_create(def)` | `xQueueCreate(depth, item_sz)` |
| `osal_queue_receive(q, data, timeout)` | `xQueueReceive()` |
| `osal_queue_send(q, data, in_isr)` | `xQueueSendToBack()` / `FromISR` |

### 裸机模式 (osal_none)

无 RTOS 时，TinyUSB 使用简单轮询：
- 信号量实现为 ISR 中设置的 volatile 标志
- `osal_semaphore_wait()` 若标志未设置则立即返回 `false`（永不阻塞）
- 用户必须在主循环中高频调用 `tud_task()`

## 与 CANopenNode 的对比

用户已有的 CANopenNode 知识：

| 维度 | TinyUSB | CANopenNode |
|------|---------|-------------|
| 对象字典 / 描述符 | 编译时描述符宏 (ROM 字节数组) | 对象字典宏 (ROM 表) |
| 状态机 | USB 设备状态机 (5 状态) | NMT 状态机 (初始化→预操作→操作→停止) |
| 传输模型 | 端点中断 → 回调 | CAN 报文中断 → 回调 |
| OS 集成 | OSAL 层 (信号量/队列/互斥量) | CO_IF (类似，更简单) |
| 驱动注册 | `usbd_class_driver_t` 虚函数表 | `CO_OD_configure()` 函数指针 |

两者都是嵌入式协议栈设计的优秀范例 — 编译时配置、回调驱动、平台抽象层。
