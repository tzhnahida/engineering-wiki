# SoC FPGA 系统架构

## 一句话

**SoC FPGA 的意义不是把 CPU 和 FPGA 封装在一起，而是让软件控制与定制硬件成为同一套系统中的两种能力——用控制面做决策，用数据面做执行。**

## 传统方案 vs SoC FPGA

### 分立方案：CPU + FPGA 两颗芯片

```
CPU ←external bus→ FPGA (SPI/EMIF)
```

问题：两颗芯片的上电顺序？谁先启动？配置数据放哪里？通信协议？数据是否经过外部存储器？异常时从哪个芯片开始排查？

### SoC FPGA：HPS + FPGA Fabric 片上融合

```
SoC FPGA: HPS (硬处理器) ←bridge→ FPGA Fabric
```

## HPS — 不是软核 CPU

> [!important] 关键区分
> **软核处理器** = 用 FPGA 逻辑资源拼出的 CPU（灵活但占资源、频率低）
> **HPS (Hard Processor System)** = 固化在硅片中的完整处理器系统

HPS 包含：

| 组件 | 说明 |
|------|------|
| CPU 核心 | ARM Cortex-A 等应用处理器 |
| 存储控制器 | DDR、Flash 控制器 |
| 中断控制器 | GIC |
| 常用外设 | 定时器、串口、网口、USB、SPI、I2C |
| 引导 ROM | 片上启动代码 |

从软件视角看，它就是一套普通的嵌入式处理器平台——能启动 U-Boot、跑 Linux、加载驱动、执行应用程序。

## FPGA Fabric — 真正可重配置的硬件

包含：

- 逻辑单元（LUT + 触发器）
- 片上 Block RAM
- DSP 运算单元（乘法器/累加器）
- 时钟管理（PLL/MMCM）
- 可编程互连

可以在其中创建：状态机、自定义接口、控制寄存器、实时数据处理流水线。

> [!note] 两个世界，两种工作方式
> 处理器 = 按指令顺序执行软件
> FPGA = 按配置后的电路结构持续并行工作

## 片上桥：连接两个世界的桥梁

处理器通过内部总线访问 FPGA 中的寄存器——**存储器映射硬件**。

```c
// Software writes to a memory-mapped address → crosses processor bus
// → traverses on-chip bridge → arrives at FPGA register
*(volatile uint32_t *)0xFF200000 = 1;  // FPGA flip-flop state changes → LED on
```

> [!tip] 核心直觉
> FPGA 中的自定义组件 = 一组特殊的内存地址。对应用层来说就是写了一个数；对 FPGA 来说，真实电路中的触发器已经保存了新状态。

在 Linux 系统中，应用层不会直接拿物理地址访问——虚拟内存、内核权限、设备树、驱动程序会参与其中。但底层原理不变：**处理器与 FPGA 的连接最终落实为清楚的数据通路和地址关系。**

## 控制面 vs 数据面

面对复杂 SoC FPGA 系统，先分成控制面和数据面：

| | 控制面 (Control Plane) | 数据面 (Data Plane) |
|---|---|---|
| **入口** | 用户命令/参数/模式选择 | 实时业务数据流 |
| **处理路径** | Linux 驱动 → 片上桥 → FPGA 控制寄存器 → (改变电路行为) | 接口接收 → 缓冲/FIFO → 处理流水线 (DSP) → 接口输出 |
| **特点** | 灵活、低频、可维护 | 高吞吐、确定性、低延迟 |

### 各领域应用

| 领域 | 控制面（CPU） | 数据面（FPGA） |
|------|-------------|---------------|
| 音频 | 选效果、调参数 | 采样→滤波→FFT 流水线 |
| 网络 | 配置规则、路由表 | 逐包处理高速数据 |
| 工业 | 设置控制参数 | 严格周期采集和输出 |
| 视觉 | 流程管理、结果分析 | 像素流预处理 |

## 片上集成的三个核心优势

### 1. 缩短物理距离

通信不经过板级接口，使用芯片内部互连。减少外部芯片数量，降低板级设计复杂度。

### 2. 软硬件边界可重划分

1. **项目早期** → 软件验证功能
2. **性能瓶颈 / 需要更稳定的实时行为** → 迁移到 FPGA（定制硬件加速）
3. **需要频繁改变** → 保留在处理器侧（软件灵活修改）

**不需要一开始就决定什么用硬件、什么用软件。**

### 3. 控制 + 加速在同一系统

处理器负责：网络协议栈、文件系统、用户界面、系统管理、远程升级、诊断  
FPGA 负责：专用接口协议、实时数据通路、并行加速

> 很多产品需要的不是一个孤立的高速算法，而是一套**能启动、能配置、能升级、能诊断**的完整系统。

## 四个边界问题

把两个世界放进一颗芯片，也把两个世界的问题带到一起：

### 1. 时钟域不同

处理器总线和 FPGA 数据通路工作在不同时钟域。信号跨越时钟域不能简单拉一根线——需要同步器、异步 FIFO 或握手协议。

### 2. 启动与复位顺序

- **Scenario A**: Processor starts executing software before FPGA configuration completes
- **Scenario B**: FPGA is already working before the driver establishes correct control state

需要在设计中定义清楚：谁先启动、谁等谁、复位后默认状态是什么。

### 3. 带宽不是无限的

虽然在同一颗芯片中，片上桥和存储器仍有容量限制。**把每个采样点都交给 CPU 搬运**——浪费了本应由硬件直接完成的数据流优势。

### 4. 调试跨越多个层次

一次错误可能来自：

- Application parameter → Driver address → Bus connection → Register logic → Clock domain → External interface

没有分层验证，很容易在错误的地方浪费时间。

## 设计方法论

> [!important] 先画两条线，再开始设计

**第一条：控制线**

用户命令从哪里产生 → 经过哪些软件层 → 最终写到哪个硬件寄存器？

**第二条：数据线**

真实数据从哪个接口进入 → 经过哪些缓冲和运算 → 从哪里输出？

如果这两条线无法清楚画出来，系统结构通常还没真正想明白。当两条线都清楚之后，设计选择会自然出现：

- 哪些寄存器暴露给软件？
- 哪些数据留在 FPGA 内部？
- 哪里需要缓存？
- 哪里需要跨时钟域？
- 哪些异常由硬件处理？
- 哪些状态交给驱动程序？
