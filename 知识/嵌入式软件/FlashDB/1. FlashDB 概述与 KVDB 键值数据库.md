# 1. FlashDB 概述与 KVDB 键值数据库

## 定位

FlashDB 是 armink 开发的超轻量嵌入式数据库。两个独立模式：

| 模式 | 用途 | 典型场景 |
|------|------|---------|
| KVDB | 键值存储 | 设备配置、校准参数、用户设置 |
| TSDB | 时序日志 | 传感器数据记录、事件日志 |

资源占用（STM32F4 IAR 编译）：

| 模块 | Code (RO) | Data (RO) | Data (RW) |
|------|-----------|-----------|-----------|
| fdb.o | 276 | 232 | 1 |
| fdb_kvdb.o | 4,584 | 356 | 1 |
| fdb_utils.o | 418 | 1,024 | — |
| **合计** | **~6.4KB** | **~1.8KB** | **~2 bytes** |

## 扇区存储模型

Flash 被切分为固定大小扇区（`sec_size`，必须是 2 的幂，对齐 Flash 块大小）。每个数据库至少 2 个扇区。

### KVDB 扇区头

```
[status_table. store] [status_table. dirty] [magic "FDB0"] [combined] [reserved]
```

- `store` 状态：UNUSED → EMPTY → USING → FULL
- `dirty` 状态：UNUSED → FALSE → TRUE → GC

### 状态表技术（核心创新）

状态不是枚举值，而是通过**逐位/逐字节写入**实现。例如：

| 写粒度 | 状态0 | 状态1 | 状态2 |
|--------|-------|-------|-------|
| 1-bit (NOR) | 0xFF | 0x7F | 0x3F |
| 8-bit (F4) | 0xFFFFFF | 0x00FFFF | 0x0000FF |

这天然支持掉电恢复——中断后读到的中间状态可以判断操作进行到哪一步。

## KV 节点结构

```
[KV Header] [Key Name (对齐)] [Value Data (对齐)]
```

Header（`struct kv_hdr_data`）：

| 字段 | 大小 | 说明 |
|------|------|------|
| status_table | 变长 | PRE_WRITE→WRITE→PRE_DELETE→DELETED |
| magic | 4B | `0x3030564B` = "KV00" |
| len | 4B | 总长度 |
| crc32 | 4B | (name_len+value_len+name+value) 的 CRC32 |
| name_len | 1B | 键名长度（最大 `FDB_KV_NAME_MAX`=64） |
| value_len | 4B | 值数据长度 |

## 键查找

两级策略：

1. **缓存查找**（`FDB_KV_USING_CACHE`）：KV 缓存表（64 条目）存储 key CRC16 → 地址映射，LRU 淘汰。扇区缓存表（8 条目）避免重复读扇区头。
2. **扇区遍历**：缓存未命中时按扇区链扫描，读取每个 USING/FULL 扇区中的所有 KV。

## 写入流程

`fdb_kv_set("key", value)` → `fdb_kv_set_blob()`:

1. **空间分配**：优先现有扇区剩余空间，否则使用新 EMPTY 扇区，都不足则触发 GC
2. **旧值删除**：若 key 已存在，标记 PRE_DELETE
3. **新值写入**：PRE_WRITE → 写 magic+metadata+name+value → WRITE（提交）
4. **完成删除**：旧值标记 DELETED
5. **GC**：若扇区变 FULL，触发 GC

## 两阶段操作（掉电保护）

**两阶段删除**：PRE_DELETE → DELETED。断电在 PRE_DELETE 后，重启时恢复逻辑通过 `move_kv()` 完成或回退。

**两阶段写入**：PRE_WRITE → WRITE。断电在 PRE_WRITE 后，KV 标记为 ERR_HDR。

## GC（垃圾回收）

触发条件：空闲扇区数 ≤ `FDB_GC_EMPTY_SEC_THRESHOLD`（默认 1）。

1. 遍历所有 DIRTY 扇区
2. 标记 DIRTY_GC
3. 将扇区内存活 KV **移动到**新扇区
4. **擦除并格式化**旧扇区
5. 更新 `oldest_addr` 指针

## 与 LittleFS 对比

| | FlashDB KVDB | LittleFS |
|--|-------------|----------|
| 操作 | `fdb_kv_set/get/del` | `fopen/fwrite/fread` |
| 配置存储 | ✅ 天然映射 | 需要文件/路径管理 |
| RAM | ~0 | ~4KB+ |
| 写放大 | 低（状态位就地更新） | 较高（COW 元数据块） |
| 传感器日志 | ✅ TSDB 原生支持 | ❌ 无时序支持 |

**结论**：配置参数用 FlashDB，文件/固件存储用 LittleFS——互补关系。
