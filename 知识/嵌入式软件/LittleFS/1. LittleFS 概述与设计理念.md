# LittleFS 概述与设计理念

## 定位

LittleFS 是 ARM Mbed 团队为 NOR Flash 设计的现代嵌入式文件系统。核心承诺：**任何时刻断电不损坏文件系统**、**内置磨损均衡**、**RAM 不随存储容量增长**。

## 三大核心需求

| 需求 | 设计后果 |
|------|---------|
| **断电韧性** | 原子提交、COW、CRC 校验 — 没有"写了一半"的状态 |
| **磨损均衡** | COW 自然分散写入 + 元数据对交替 + 块迁移机制 |
| **有界 RAM** | 无 RAM 索引、扫描式分配、固定大小 lookahead 位图 |

## NOR Flash 特性

LittleFS 专为 NOR Flash 设计（不是 NAND）：

| 特性 | NOR Flash | 对 LittleFS 的意义 |
|------|-----------|-------------------|
| 字节级随机读 | 极快 | 元数据标签可紧凑存储 |
| 字节级编程 (prog) | 支持 | 细粒度追加写入 |
| 块级擦除 | 大块 (4KB-64KB) | 元数据对在两个块间交替 |
| 擦除寿命 | ~100,000 次/块 | 必须均匀分布写入 |

## CObW vs 日志结构 vs COW

| 方法 | LittleFS 的做法 |
|------|----------------|
| **日志结构** (JFFS, SPIFFS) | 将日志限制在 2 块元数据对内（避免 O(n²) GC） |
| **写时复制** (btrfs) | 使用 **有界 COW** — 连锁反应止于一个元数据对 |

## 核心数据结构

```c
// 文件系统上下文（源码验证 ✅ lfs.h:436-471）
typedef struct lfs {
    lfs_cache_t rcache;          // 读缓存
    lfs_cache_t pcache;          // 编程缓存
    lfs_block_t root[2];         // 根目录元数据对 (块0, 块1)
    lfs_gstate_t gstate;         // 进行中的已提交状态
    lfs_gstate_t gdisk;          // 磁盘上持久化状态
    lfs_gstate_t gdelta;         // 当前提交周期的 XOR 增量
    struct lfs_mlist *mlist;     // 打开目录/文件链表（孤儿管理）
    uint32_t seed;               // 伪随机种子（来自 CRC）
    lfs_lookahead_t lookahead;   // 前瞻分配位图
    lfs_size_t block_count;      // 当前块数（可能不同于 cfg）
    const struct lfs_config *cfg;
} lfs_t;

// 全局状态（lfs_gstate_t）通过 XOR 组合使用：
// gstate = gdisk ^ gdelta —— 用于原子移动/删除操作的跨元数据对状态传播

// 块设备配置 + 操作
struct lfs_config {
    int (*read)(const struct lfs_config *c, lfs_block_t block,
                lfs_off_t off, void *buffer, lfs_size_t size);
    int (*prog)(const struct lfs_config *c, lfs_block_t block,
                lfs_off_t off, const void *buffer, lfs_size_t size);
    int (*erase)(const struct lfs_config *c, lfs_block_t block);
    int (*sync)(const struct lfs_config *c);

    lfs_size_t read_size;        // 最小读单元
    lfs_size_t prog_size;        // 最小编程单元
    lfs_size_t block_size;       // 擦除块大小
    lfs_size_t block_count;      // 总块数
    lfs_size_t cache_size;       // 缓存大小
    lfs_size_t lookahead_size;   // 前瞻位图 (字节)
    int32_t block_cycles;        // 块迁移频率 (-1 = 禁用)
};
```

> [!note] `read_size` 与 `prog_size` 可以不同
> NOR Flash 读可以是 1 字节，但写可能需要页对齐（如 256 字节）。FatFS 假设扇区读写对称，LittleFS 显式区分这两个参数。

## 磁盘标签格式

所有元数据使用 32 位标签：

```
位: [1|---- 11 ----|---- 10 ----|---- 10 ----]
     ^    ^            ^            ^
     |    type         id           length
     valid (总是1)
```

标签类型核心表：

| 类型 | 值 | 含义 |
|------|-----|------|
| `LFS_TYPE_CRC` | `0x5xx` | 提交结束标记，数据为 CRC-32 |
| `LFS_TYPE_NAME` | `0x0xx` | 文件 ID 关联文件名 (chunk: REG=0x001, DIR=0x002) |
| `LFS_TYPE_DIRSTRUCT` | `0x200` | 目录指针 (8 字节元数据对地址) |
| `LFS_TYPE_INLINESTRUCT` | `0x201` | 内联文件数据 |
| `LFS_TYPE_CTZSTRUCT` | `0x202` | CTZ skip-list 头 + 文件大小 |
| `LFS_TYPE_SOFTTAIL` | `0x600` | 软尾 — 下一个元数据对属于不同目录 |
| `LFS_TYPE_HARDTAIL` | `0x601` | 硬尾 — 同目录继续 |
