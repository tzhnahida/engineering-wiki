# 2. CmBacktrace 集成与配置

## 集成步骤

### 1. 添加源文件

| 文件 | 作用 | 必须 |
|------|------|------|
| `cm_backtrace.c` | 核心诊断 | ✅ |
| `cm_backtrace.h` | 公共 API | ✅ |
| `cmb_cfg.h` | 用户配置 | ✅ |
| `cmb_def.h` | 定义/寄存器 | ✅ |
| `cmb_fault.S` | 汇编跳板 | ✅ 或手动在 HardFault_Handler 中调用 |

### 2. 配置 `cmb_cfg.h`

最小配置（STM32F4 + FreeRTOS）：

```c
#define cmb_println(...)               printf(__VA_ARGS__); printf("\r\n")
#define CMB_USING_OS_PLATFORM
#define CMB_OS_PLATFORM_TYPE           CMB_OS_PLATFORM_FREERTOS
#define CMB_CPU_PLATFORM_TYPE          CMB_CPU_ARM_CORTEX_M4
#define CMB_USING_DUMP_STACK_INFO
#define CMB_PRINT_LANGUAGE             CMB_PRINT_LANGUAGE_ENGLISH
```

裸机版本：

```c
#define cmb_println(...)               printf(__VA_ARGS__); printf("\r\n")
#define CMB_USING_BARE_METAL_PLATFORM
#define CMB_CPU_PLATFORM_TYPE          CMB_CPU_ARM_CORTEX_M4
#define CMB_PRINT_LANGUAGE             CMB_PRINT_LANGUAGE_ENGLISH
```

### 3. 连接器符号（GCC）

连接脚本需定义：
- `_sstack` / `_estack` — 主栈起止
- `_stext` / `_etext` — 代码段起止

若使用自定义符号名，覆盖宏：
- `CMB_CSTACK_BLOCK_START` / `CMB_CSTACK_BLOCK_END`
- `CMB_CODE_SECTION_START` / `CMB_CODE_SECTION_END`

### 4. 初始化

```c
int main() {
    HAL_Init();
    cm_backtrace_init("MyFirmware", "HW_V1.0", "SW_V0.1");
    // ... 应用代码 ...
}
```

### 5. 移除原有 HardFault_Handler

如果使用汇编跳板（推荐），必须注释掉 `stm32f4xx_it.c` 或其他地方的原有 `HardFault_Handler`，否则链接器报告重复符号。

### 6. 用 addr2line 解析地址

故障输出示例：
```
Show more call stack info by run: addr2line -e MyFirmware.elf -afpiC 08002422 0800243f
```

在 PC 上运行：
```bash
arm-none-eabi-addr2line -e build/MyFirmware.elf -afpiC 08002422 0800243f
```

## FreeRTOS 集成注意事项

需要在 `tasks.c` 中增加三个辅助函数暴露 TCB 内部字段：

```c
uint32_t *vTaskStackAddr(void) { return pxCurrentTCB->pxStack; }
uint32_t  vTaskStackSize(void) { return pxCurrentTCB->uxStackDepth; }
char     *vTaskName(void)       { return pcTaskGetName(NULL); }
```

## API 速查

| 函数 | 说明 |
|------|------|
| `cm_backtrace_init(name, hw, sw)` | 一次性初始化，获取栈/代码段地址 |
| `cm_backtrace_firmware_info()` | 打印版本信息 |
| `cm_backtrace_assert(sp)` | 断言失败时调用，dump 当前上下文 |
| `cm_backtrace_call_stack(buf, size, sp)` | 重建调用栈，返回地址数量 |
| `cm_backtrace_fault(lr, sp)` | 故障入口（由跳板调用） |

## 与 printf 调试的对比

| 场景 | printf | CmBacktrace |
|------|--------|-------------|
| HardFault 定位 | ❌ MCU 已死，printf 无效 | ✅ 自动捕获全部状态 |
| 调用栈回溯 | ❌ 完全不可见 | ✅ 扫描栈+BL/BLX验证 |
| BusFault 地址 | ❌ 未知 | ✅ BFAR 直接给出违规地址 |
| MPU 违规 | ❌ 未知 | ✅ MFSR + MMAR 精确报告 |

**原则上每个 STM32 项目都应该集成 CmBacktrace**，成本极低（一个文件+几行配置），收益是"再也不用盲猜 HardFault 原因"。
