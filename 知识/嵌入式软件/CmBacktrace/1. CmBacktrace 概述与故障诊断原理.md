# 1. CmBacktrace 概述与故障诊断原理

## 定位

CmBacktrace 是 ARM Cortex-M 系列 MCU 的自动 HardFault 诊断库。当 MCU 发生硬件故障时，它自动：
1. 捕获全部故障寄存器和异常栈帧
2. 解码每个 SCB 寄存器 bit 为可读原因文本
3. 重建函数调用栈
4. 输出到串口/日志

支持 Cortex-M0/M3/M4/M7/M33，裸机/FreeRTOS/RT-Thread/uCOS/RTX5/ThreadX。

| 指标 | 值 |
|------|-----|
| 核心文件 | `cm_backtrace.c` (726行) + 汇编跳板 |
| 依赖 | 仅需 `cmb_println` 输出宏 |
| 协议 | MIT |
| 作者 | armink (朱天龙) |

## 故障诊断原理

### 三个层次

```
HardFault_Handler 汇编跳板
    ↓ 捕获 LR (EXC_RETURN) + SP
cm_backtrace_fault() C 诊断层
    ↓ 解析异常栈帧 → 读取 SCB 故障寄存器 → 解码 bit → 调用栈重建
输出 → 串口/日志 → addr2line 工具解析地址
```

### 第一层：汇编跳板

四个编译器版本（GCC/IAR/Keil/GHS），功能完全一致：

```asm
HardFault_Handler:
    MOV  r0, lr        ; 传 EXC_RETURN 给 C 函数
    MOV  r1, sp        ; 传 MSP 给 C 函数
    BL   cm_backtrace_fault
Fault_Loop:
    BL   Fault_Loop    ; 死循环，阻止返回
```

关键点：跳板在故障瞬间执行，此时 MSP 指向异常栈帧。将 LR（包含 EXC_RETURN）和 SP 作为参数传给 C 函数。

### 第二层：C 诊断

`cm_backtrace_fault()` 的执行流程：

1. **线程/ISR 判定** — 检查 `EXC_RETURN` bit2：
   - bit2=1 → 故障发生在线程模式，栈帧在 PSP
   - bit2=0 → 故障发生在 Handler 模式，栈帧在 MSP
2. **异常栈帧提取** — 读取硬件自动压栈的 R0-R3, R12, LR, PC, xPSR
3. **FPU 寄存器调整** — M4/M7/M33 检查 bit4，若无 FPU 上下文则跳过 18 字 S0-S15
4. **8 字节对齐修正** — 检查 xPSR bit9，跳过对齐填充
5. **故障寄存器 dump** — 读取全部 SCB 故障状态寄存器
6. **故障原因解码** — 逐 bit 解析为文本
7. **调用栈重建** — 扫描栈内存找 BL/BLX 返回地址

### SCB 故障寄存器全集

| 寄存器 | 地址 | 内容 |
|--------|------|------|
| SHCSR | 0xE000ED24 | 各故障 handler 的 active/pended/enable 状态 |
| MFSR | 0xE000ED28 | MemManage 故障状态（MPU 违规、XD 违规等） |
| BFSR | 0xE000ED29 | Bus 故障状态（精确/不精确数据访问错等） |
| UFSR | 0xE000ED2A | Usage 故障状态（未定义指令、除零、对齐等） |
| HFSR | 0xE000ED2C | HardFault 状态（FORCED、VECTTBL 等） |
| DFSR | 0xE000ED30 | Debug 故障状态 |
| MMAR | 0xE000ED34 | MemManage 故障地址 |
| BFAR | 0xE000ED38 | Bus 故障地址 |
| AFSR | 0xE000ED3C | 辅助故障状态（实现定义） |

## 调用栈重建算法

**不是 DWARF 展开，是启发式栈扫描：**

1. 遍历 `[sp, stack_top)` 每个对齐字
2. 候选值必须在代码段范围 `[text_start, text_end)` 内
3. 必须为奇数（Thumb bit）
4. 候选地址 - 4 处的指令必须为 BL 或 BLX（通过解码两个 16bit 半字验证）
   - BL: `ins2 & 0xF800 == 0xF800` 且 `ins1 & 0xF800 == 0xF000`
   - BLX: `ins2 & 0xFF00 == 0x4700`
5. 去重：第二项与捕获的 LR 值重复则跳过

**局限**：不能展开叶子函数、不能确定嵌套深度、不能展开函数指针间接调用。输出为一组 8 位十六进制地址，需配合 `addr2line` 命令行工具解析源码位置。

## 线程感知

OS 感知模式下，`get_cur_thread_stack_info()` 通过 OS API 获取当前任务栈边界：

| RTOS | 获取方式 |
|------|---------|
| FreeRTOS | `pxCurrentTCB->pxStack`, `->uxStackDepth`（需在 tasks.c 中加辅助函数） |
| RT-Thread | `rt_thread_self()->stack_addr`, `->stack_size`, `->sp` |
| uC/OS-II | `OSTCBCur->OSTCBStkBottom`, `->OSTCBStkSize` |
