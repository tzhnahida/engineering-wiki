# 1. Zephyr 架构与构建系统

## 定位

Zephyr 是 Linux 基金会维护的可扩展安全 RTOS（Apache 2.0，版本 4.4.99-dev）。与 FreeRTOS 的"轻量内核+外挂库"模式不同，Zephyr 是一站式应用平台。

| 指标 | 值 |
|------|-----|
| 架构支持 | ARM (Cortex-A/R/M) / x86 / ARC / RISC-V / Xtensa / SPARC / MIPS |
| STM32 系列 | 29 个（F0→H7→MP2） |
| STM32 板卡 | 129 块 |
| 驱动类别 | 99 类 |
| 子系统 | 45 个 |
| 内核 API 面 | 7,331 行 `kernel.h` |

## 三级构建系统

Zephyr 的构建是它最显著的差异化设计——不同于 FreeRTOS 的一个 `FreeRTOSConfig.h` 配简单 Makefile，Zephyr 用**三层叠加**实现了 Linux 级配置能力：

```
Device Tree (.dts + .yaml bindings)
    ↓  描述硬件（引脚、外设、总线、DMA 通道…）
Kconfig
    ↓  编译时配置（功能开关、参数调节）
CMake
    ↓  构建逻辑（源文件选择、链接、生成镜像）
```

### 第一层：Device Tree——硬件描述

`dts/` 目录包含 ARM、RISC-V、x86 等架构的 devicetree 绑定文件。每块板卡有 `.dts` 源文件和 `.yaml` 元数据。

DT 数据**自动生成**为两类符号：
- **Kconfig 符号**：用于 CMake 条件编译（如 `CONFIG_HAS_GPIO`）
- **C 宏**：用于驱动代码引用（如 `DT_N_S_led0_P_gpios`）

**覆盖链**：shield 默认 → board 默认 → SoC 默认 → Kconfig 回退。这让你在不同板卡上只需改一个 board 目录，不需要动一行 C 代码。

### 第二层：Kconfig——配置系统

Kconfig 链：

```
Kconfig → Kconfig.zephyr → Kconfig.constants → dts/Kconfig
       → boards/*/Kconfig.defconfig → soc/Kconfig → arch/Kconfig
       → kernel/Kconfig → drivers/Kconfig → lib/Kconfig → subsys/Kconfig
```

`kernel/Kconfig` 可配参数示例：
- `CONFIG_MULTITHREADING`：是否启用多线程
- `CONFIG_NUM_COOP_PRIORITIES`：协作优先级数量（0-128）
- `CONFIG_NUM_PREEMPT_PRIORITIES`：抢占优先级数量（0-127）
- `CONFIG_TIMESLICING`：时间片轮转
- `CONFIG_SCHED_DEADLINE`：EDF 调度
- `CONFIG_SMP`：多核调度
- `CONFIG_DYNAMIC_THREAD`：运行时创建线程
- `CONFIG_USERSPACE`：用户态隔离

**覆盖优先级**：shield defaults > board defaults > SoC defaults。每层都可以 `default y if BOARD_xxx`。

### 第三层：CMake + west 工具

构建入口是 `west build`，而非直接调用 CMake。west 是一个 Python 元工具：

```bash
west init -m https://github.com/zephyrproject-rtos/zephyr
west update          # 拉取所有依赖模块
west build -b nucleo_f103rb samples/basic/blinky
west flash           # 烧录
```

**多阶段链接**是 Zephyr 构建的关键创新。链接分三阶段：

| 阶段 | 作用 |
|------|------|
| `zephyr_pre0` | 第一轮链接，收集设备依赖结构体 |
| `zephyr_pre1` | 第二轮，生成 ISR 向量表、内核对象表 |
| `zephyr_final` | 最终链接，所有符号解析 |

这允许**编译时反射**——内核知道系统中的每台设备、每个 ISR、每个内核对象，不需要运行时注册。

## 驱动模型

Zephyr 所有驱动统一为 `struct device`：

```c
struct device {
    const char *name;
    const void *config;    // 编译时常量（从 DT 生成）
    void *data;            // 运行时状态
    const void *api;       // 驱动操作函数表
    // ...
};
```

驱动不是手动实例化的——DT 节点自动映射到驱动实例：

```
/dts-v1/; / { soc { i2c@40005400 { compatible = "st,stm32-i2c-v2"; }; }; };
    ↓ DT 工具解析
DEVICE_DT_DEFINE(DT_NODELABEL(i2c1), &i2c_stm32_init, NULL, NULL, &i2c_cfg, ...)
    ↓ 驱动代码
const struct i2c_driver_api i2c_stm32_api = {
    .configure = i2c_stm32_configure,
    .transfer = i2c_stm32_transfer,
};
```

99 类驱动统一这个模式。驱动的电源状态由 PM 子系统管理，应用层不需要关心。

## 目录结构速览

```
zephyr/
├── arch/          # CPU 架构特定代码（启动、MMU、异常）
│   └── arm/core/  # Cortex-M 启动、异常向量、MPU
├── boards/        # 板卡定义（179 块，129 块 STM32）
├── soc/           # SoC 系列（29 个 STM32）
├── drivers/       # 设备驱动（99 类）
├── subsys/        # 子系统（45 个）
├── kernel/        # 内核源码（50+ 文件）
├── include/       # 公共头文件
├── dts/           # Devicetree 绑定
├── lib/           # 库（LVGL、CMSIS、libc 等）
└── cmake/         # CMake 模块
```
