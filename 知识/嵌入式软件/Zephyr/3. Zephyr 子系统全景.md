# 3. Zephyr 子系统全景

Zephyr 有 45 个子系统。以下是关键子系统的实际能力。

## 蓝牙——完整的 BLE 协议栈

`subsys/bluetooth/` 提供了开源世界最成熟的嵌入式 BLE 实现之一：

| 层 | 内容 |
|----|------|
| Controller | 自带 HCI 控制器，支持 LE 1M/2M/Coded PHY |
| Host | GAP、GATT、SMP（安全管理）、L2CAP |
| Mesh | 蓝牙 Mesh 网络（Provisioning、Model、Health） |
| Audio | LE Audio（LC3 编解码、CIS/BIS 音频流） |
| Services | BAS/DIS/HRS/HIDS 等标准 GATT 服务 |

**对比 FreeRTOS**：FreeRTOS 无 BLE 栈，只能依赖 Nordic SoftDevice 或 ESP-IDF 等厂商 SDK——每换一个芯片就要换一套 BLE API。Zephyr 提供统一 API 跨芯片。

## 网络——内置 TCP/IP 栈

`subsys/net/` 不依赖外部 LWIP：

| 层 | 支持 |
|----|------|
| L2 | Ethernet、WiFi、6LoWPAN、OpenThread、BLE IPSP |
| L3 | IPv4、IPv6、DHCPv4、DNS、mDNS |
| L4 | TCP、UDP |
| 应用 | MQTT、CoAP、HTTP(S)、WebSocket、TLS/DTLS（mbedTLS） |

**Socket API**：提供类 POSIX 的 `socket()/bind()/connect()/send()/recv()`，Linux 上开发的网络代码几乎不用改就能搬到 Zephyr。

**对比**：你的维基已有 LWIP（8 页完整分析）。Zephyr 的内置网络栈替代了"FreeRTOS + LWIP"组合——内核和网络栈来自同一供应商，集成度更高，不用处理 LWIP 的 `sys_arch` 移植层。

## 文件系统

`subsys/fs/` 集成 LittleFS 和 FatFS，与你的维基已有库互补：

- **LittleFS**：NOR/NAND Flash 原生文件系统，COW + 磨损均衡。Zephyr 的默认 FS。
- **FatFS**：兼容性文件系统（SD 卡、USB 存储），通过 ELM FatFS 集成。
- **VFS 抽象**：多个文件系统可同时挂载（`/lfs` 和 `/fat`），统一文件 API。

```c
#include <zephyr/fs/fs.h>
struct fs_file_t file;
fs_file_t_init(&file);
fs_open(&file, "/lfs/config.json", FS_O_READ);
fs_read(&file, buf, sizeof(buf));
fs_close(&file);
```

**对比**：FreeRTOS + FatFS + LittleFS（你在维基里分析的搭配）需要手动移植每个 FS。Zephyr 的 VFS + 内置 FS 驱动让挂载即用。

## USB

`subsys/usb/` 设备/主机双栈：

| 栈 | 支持的类 |
|----|---------|
| USB Device | CDC ACM（虚拟串口）、HID、Mass Storage、DFU（固件升级）、Audio、Video |
| USB Host | HID、Mass Storage、CDC |
| USB-C | Power Delivery |

**对比 TinyUSB**（你的维基 4 页）：Zephyr USB Device 栈功能上与 TinyUSB 重叠，但集成在驱动模型里——USB 端点从 DT 配置，不需要手动分配。TinyUSB 在裸机/FreeRTOS 场景更轻量；Zephyr USB 在 Zephyr 项目里更自然。

## 显示与 GUI

- `drivers/display/`：40+ 显示驱动（ILI9341、ST7789V、SSD1306、OTM8009A 等）
- `lib/gui/lvgl`：LVGL 作为库集成（你的维基已有 LVGL 分析）
- `subsys/fb/`：framebuffer 子系统，统一显示接口

## 传感器

`drivers/sensor/` 提供统一传感器驱动模型：

| 特性 | 说明 |
|------|------|
| 采样模式 | 轮询 `sensor_sample_fetch()` + `sensor_channel_get()` |
| 触发模式 | 配置阈值/数据就绪触发，回调通知 |
| 传感器类型 | 加速度计/陀螺仪/磁力计/环境/距离/光线 等数十种 |
| 相同 API | 不同传感器用同一套 API——换芯片不改应用代码 |

```c
const struct device *dev = DEVICE_DT_GET(DT_ALIAS(accel0));
struct sensor_value accel[3];
sensor_sample_fetch(dev);
sensor_channel_get(dev, SENSOR_CHAN_ACCEL_XYZ, accel);
```

## 电源管理

`subsys/pm/` 多层睡眠状态 + 设备级电源域：

- CPU 空闲时自动进入最深可用睡眠状态
- 设备可声明电源域——总线空闲时自动关设备电源
- 多状态：ACTIVE → IDLE → SLEEP_1 → SLEEP_2 → DEEP_SLEEP
- `CONFIG_PM_DEVICE` 启用设备级电源管理
- 外设从不使用时自动休眠

**对比 FreeRTOS**：tickless idle 只能让 CPU 在空闲时睡。Zephyr PM 框架同时管理 CPU 和设备的电源状态。

## 安全——用户态隔离

启用 `CONFIG_USERSPACE` 后：

- **用户线程**运行在非特权模式（MPU/MMU 隔离）
- 所有硬件访问必须通过 **syscall**（自动生成，类似 Linux 的 `SVC` 调用）
- **内存域**限定了线程可访问的内存范围
- 栈溢出由 MPU 边界检查硬件捕获

FreeRTOS 完全没有这个层——所有线程能访问所有内存。

## POSIX 可移植层

`subsys/portability/posix/` 为从 Linux 迁移的应用提供熟悉的 API：

| POSIX 组件 | Zephyr 支持 |
|------------|------------|
| pthread | ✅ `pthread_create/join/mutex/cond` |
| 信号量 | ✅ `sem_init/wait/post` |
| 时钟 | ✅ `clock_gettime` |
| 文件 I/O | ✅ `open/read/write/close`（通过 VFS） |
| 定时器 | ✅ `timer_create/settime` |
| eventfd | ✅ |

**意义**：Linux 上开发和测试应用逻辑，交叉编译到 Zephyr——源代码基本不改。

## 调试工具链

Zephyr 自带完整调试/诊断栈（你刚入库的 CmBacktrace/EasyLogger/letter-shell 是对 FreeRTOS 的补充，Zephyr 内置了等价功能）：

| 组件 | 功能 | FreeRTOS 等价 |
|------|------|--------------|
| Logging (`subsys/logging/`) | 多级别日志、过滤、多后端 | EasyLogger |
| Shell (`subsys/shell/`) | 交互式命令行、命令自动注册 | letter-shell |
| Tracing (`subsys/tracing/`) | CTF 追踪、性能分析 | 无 |
| Coredump (`subsys/debug/`) | 崩溃现场 dump | CmBacktrace |
| Twister (`scripts/twister`) | 测试框架、CI | Unity |
