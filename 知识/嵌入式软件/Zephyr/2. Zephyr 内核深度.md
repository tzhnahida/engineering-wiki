# 2. Zephyr 内核深度

## 调度器

### 双优先级体系

Zephyr 的优先级分**协作**和**抢占**两类，数量和范围独立配置：

```
优先级 0  ─── 最高（协作）
  ...
优先级 N  ─── 最低协作
优先级 N+1 ─── 最高抢占
  ...
优先级 N+M ─── 最低抢占
```

- **协作线程**：主动让出 CPU（`k_yield()`），否则一直运行。关键：协作线程不能被同优先级的其他协作线程抢占
- **抢占线程**：更高优先级的线程就绪时立即抢占
- **Meta-IRQ 优先级**：独立于协作/抢占，用于中断下半部——比所有线程优先级都高

配置项：
```kconfig
CONFIG_NUM_COOP_PRIORITIES=16     # 0-15 为协作
CONFIG_NUM_PREEMPT_PRIORITIES=32  # 16-47 为抢占
CONFIG_NUM_METAIRQ_PRIORITIES=4   # IRQ 后半部
```

### EDF 调度（可选）

启用 `CONFIG_SCHED_DEADLINE` 后，线程可声明截止时间。内核始终运行截止时间最近的线程。适合周期性实时任务。

### 原生 SMP

`CONFIG_SMP` 启用后：
- **per-CPU 运行队列**：每个核独立的就绪队列
- **IPI（核间中断）**：调度器用 IPI 通知其他核重新调度
- **CPU 亲和性**：线程可绑定到特定核
- 临界区用自旋锁，不是关全局中断

### 时间片轮转

`CONFIG_TIMESLICING` 启用后，同优先级抢占线程轮流运行。时间片长度可配（`CONFIG_TIMESLICE_SIZE`），单位毫秒。

## 线程管理

### 线程创建

```c
// 静态定义（编译时，零运行时开销）
K_THREAD_DEFINE(my_tid, 1024,
    my_thread_func, NULL, NULL, NULL,
    5, 0, 0);  // priority=5, options=0, delay=0

// 动态创建（需 CONFIG_DYNAMIC_THREAD）
k_tid_t tid = k_thread_create(&thread_data, stack, stack_size,
    my_thread_func, arg1, arg2, arg3,
    priority, options, K_NO_WAIT);
```

### 线程生命周期

```
---→ [创建] → [就绪] ⇄ [运行] → [挂起] → [终止]
                    ↑         ↓
                    └──── [等待]（信号量/队列/超时）
```

关键 API：

| API | 作用 |
|-----|------|
| `k_thread_start(tid)` | 启动线程 |
| `k_thread_suspend(tid)` | 挂起 |
| `k_thread_resume(tid)` | 恢复 |
| `k_thread_abort(tid)` | 终止（不可恢复） |
| `k_thread_join(tid, timeout)` | 等待线程结束 |
| `k_sleep(ms)` | 睡眠 |
| `k_yield()` | 让出 CPU |
| `k_busy_wait(us)` | 忙等待（微秒） |

### 线程栈

- 栈大小由用户指定，可静态分配或动态分配
- `CONFIG_THREAD_STACK_INFO` 启用后可通过 `k_thread_stack_space_get()` 查询剩余栈空间
- 栈溢出检测：MPU 保护或软件哨兵（`CONFIG_STACK_CANARIES`）

## IPC 完备度对比

| 原语 | Zephyr | FreeRTOS |
|------|--------|----------|
| 信号量 | `k_sem_take/give/reset` | `xSemaphoreTake/Give` |
| 互斥锁 | `k_mutex_lock/unlock`（优先级继承） | `xSemaphoreTake/Give`（Mutex 类型） |
| 消息队列 | `k_msgq_put/get`（固定大小消息） | `xQueueSend/Receive` |
| FIFO | `k_fifo_put/get`（任意大小数据） | 无直接等价（需队列包装） |
| LIFO | `k_lifo_put/get` | 无 |
| 管道 | `k_pipe_put/get`（字节流，可部分读写） | `xStreamBuffer*`（简化版） |
| 邮箱 | `k_mbox_put/get/async_put`（异步投递+消息池） | 无 |
| 栈 | `k_stack_push/pop`（后进先出，定大小） | 无 |
| 事件 | `k_event_set/wait`（多事件位，逻辑操作） | `xEventGroup*` |
| 队列 | `k_queue_append/prepend/get`（通用链表队列） | 无直接等价 |
| 条件变量 | `k_condvar_wait/signal/broadcast` | 无 |
| 轮询 | `k_poll(events, n, timeout)`（同时等多事件） | 无 |

### 互斥锁与优先级继承

```c
K_MUTEX_DEFINE(my_mutex);

k_mutex_lock(&my_mutex, K_FOREVER);   // 阻塞等待
// 临界区
k_mutex_unlock(&my_mutex);

// 假设低优先级线程持有锁，高优先级线程等待：
// Zephyr 自动提升锁持有者的优先级到等待者中最高优先级
// → 防止优先级反转
```

与 FreeRTOS 互斥锁相同的优先级继承策略，但 Zephyr 的互斥锁不能用于 ISR。

### 消息队列

```c
struct data_item { int id; float val; };
K_MSGQ_DEFINE(my_msgq, sizeof(struct data_item), 10, 4);

struct data_item tx = {1, 3.14f};
k_msgq_put(&my_msgq, &tx, K_NO_WAIT);  // 非阻塞发送

struct data_item rx;
k_msgq_get(&my_msgq, &rx, K_FOREVER);  // 阻塞接收
```

消息是**按值拷贝**的——发送方和接收方不共享内存。这避免了所有权问题。

### 管道（Pipe）

管道处理字节流而非固定大小消息：

```c
#define PIPE_SIZE 256
K_PIPE_DEFINE(my_pipe, PIPE_SIZE, 4);  // 256 字节缓冲区，4 字节对齐

// 部分读写：发送 100 字节，接收可能一次拿到 30 字节
size_t written, read;
k_pipe_put(&my_pipe, data, 100, &written, 10, K_FOREVER);
k_pipe_get(&my_pipe, buf, 50, &read, 1, K_MSEC(100));
```

适合流式数据传输（传感器流、UART 转发）。

### 轮询（k_poll）

**Zephyr 独有的特性**：同时等待多种 IPC 对象：

```c
struct k_poll_event events[3] = {
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_SEM_AVAILABLE, ...),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_FIFO_DATA_AVAILABLE, ...),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_SIGNAL, ...),
};
k_poll(events, 3, K_MSEC(100));

if (events[0].state == K_POLL_STATE_SEM_AVAILABLE) { /* 信号量就绪 */ }
if (events[1].state == K_POLL_STATE_FIFO_DATA_AVAILABLE) { /* FIFO 有数据 */ }
```

这对应 FreeRTOS 的队列集（Queue Set），但设计更通用——支持信号量/FIFO/信号等多种事件类型。

## 工作队列

Zephyr 内置工作队列子系统（Linux workqueue 风格），FreeRTOS 无等价物。

```c
struct k_work my_work;
void my_work_handler(struct k_work *work) {
    // 在工作队列线程上下文中执行
}

k_work_init(&my_work, my_work_handler);
k_work_submit(&my_work);                    // 提交到系统工作队列
k_work_submit_to_queue(&my_queue, &my_work); // 提交到专用队列

// 延迟工作
struct k_work_delayable delayed;
k_work_init_delayable(&delayed, handler);
k_work_schedule(&delayed, K_MSEC(500));     // 500ms 后执行
```

典型用法：
- 从 ISR 推迟耗时处理（避免长时间关中断）
- 批量处理（攒一批数据统一处理）
- 定时触发维护任务

## 内存管理

| 机制 | API | 适用场景 |
|------|-----|---------|
| 内存板块 | `k_mem_slab_alloc/free` | 固定大小对象的快速分配（无碎片） |
| 堆 | `k_heap_alloc/free` | 可变大小分配 |
| 内存域 | `k_mem_domain_*` | MPU/MMU 线程隔离 |

### 内存板块 vs 堆

板块：预分配 N 个固定大小的 block。分配/释放 O(1)，零碎片。适合驱动控制块、网络包缓冲区。

```c
K_MEM_SLAB_DEFINE(pkt_slab, 256, 32, 4);  // 256B blocks, 32 个
void *pkt;
k_mem_slab_alloc(&pkt_slab, &pkt, K_NO_WAIT);
k_mem_slab_free(&pkt_slab, &pkt);
```

堆：`k_heap` 类似 `malloc`，支持可变大小分配。额外提供 `k_heap_aligned_alloc`。

## 定时器

```c
struct k_timer timer;
k_timer_init(&timer, my_expiry_fn, my_stop_fn);
k_timer_start(&timer, K_MSEC(100), K_MSEC(50));  // 初始 100ms，周期 50ms
k_timer_status_sync(&timer);  // 等待定时器到期（阻塞）
k_timer_remaining_get(&timer);  // 剩余时间
```
