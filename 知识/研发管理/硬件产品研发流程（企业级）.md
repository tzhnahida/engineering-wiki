## 1. 设计流程 vs 产品流程

两者不是「详细程度不同」，而是**对象不同**：

| | 设计流程 | 产品流程 |
|---|---|---|
| 起点 | 需求规格 | 市场 / 客户需求 |
| 终点 | 板子能工作 | **持续、稳定、合规地批量制造** |
| 主体 | 单个工程师 | 跨职能组织 |
| 约束 | 技术可行 | 技术 + 成本 + 交期 + 法规 + 供应链 |
| 门槛性质 | **自觉**（"ERC 不通我不往下走"） | **制度**（评审记录、签字、问题挂账） |
| 产物 | 设计文件 | 设计文件 + **可追溯的证据链** |

> 关键区别在最后一行的反面：**设计流程的约束对人，产品流程的约束对组织。** 人换了，制度还在。

## 2. 阶段门（Phase-Gate）

### 2.1 方法来源：Stage-Gate

**A/B 级** — Cooper, R. G. (2008), *Journal of Product Innovation Management* **25(3), 213–232**, DOI `10.1111/j.1540-5885.2008.00296.x`。

| 概念 | 含义 |
|------|------|
| **阶段 (stage)** | 跨职能团队做信息收集与开发的工作段 |
| **门 (gate)** | Go / Kill 决策点 |
| **gates with teeth** | 门必须有权重——明确 gatekeeper 与议事规则，否则门形同虚设 |

Cooper 在该文中主要**纠正误解**：Stage-Gate 不是线性流程、不是刚性体系、不是职能式分阶段评审。失败模式主要是**治理问题**——过度官僚化，或把精益/六西格玛的成本削减逻辑误用到产品创新上。

> ⚠️ B 级：以上为检索摘要转述，未核对 JPIM 原文。

### 2.2 方法来源：汽车业的 APQP 五阶段

**B 级** — AIAG *APQP* 手册（第 3 版，2024-03-01 生效），上位标准 **IATF 16949**（将 AIAG 核心工具列为参考手册）。

| 阶段 | 名称 | 关键产出 |
|------|------|---------|
| 1 | Plan and Define Program | 可靠性/质量目标、初版特殊特性清单、初版过程流程图 |
| 2 | Product Design and Development | **DFMEA**、DFM/DFA、设计验证、原型控制计划 |
| 3 | Process Design and Development | **PFMEA**、试生产控制计划、MSA 计划、过程能力研究计划 |
| 4 | Product and Process Validation | 试生产、SPC、**Run-at-Rate**、**PPAP 提交** |
| 5 | Feedback, Assessment, Corrective Actions | 用生产数据与客户反馈持续改进 |

配套的 **PPAP**（生产件批准）要点：试生产需**连续 300 件以上**、**1–8 生产小时**、使用**生产用工装/设备/材料**、在标称节拍下运行；默认提交等级 Level 3；审批状态分 APPROVED / INTERIM / REJECTED；停产超 12 个月须重新提交。

> ⚠️ B 级：同上，来自检索摘要。

### 2.3 硬件研发的阶段门映射（C 级 — 编者综合）

> [!warning] 下表是**编者把门禁概念映射到硬件研发**的构造，**不是任何来源给出的编号**。Cooper 未编号，APQP 用五阶段而非 G0–G7。仅作讨论框架。

```mermaid
graph LR
    G0[G0 概念<br/>立项] --> G1[G1 方案<br/>系统架构]
    G1 --> G2[G2 详细设计<br/>原理图/BOM]
    G2 --> G3[G3 布局布线<br/>叠层/SI]
    G3 --> G4[G4 投板<br/>Gerber/DFM]
    G4 --> EVT[EVT<br/>工程验证]
    EVT --> G5[G5 样机评审]
    G5 --> DVT[DVT<br/>设计验证]
    DVT --> G6[G6 设计验证结论]
    G6 --> PVT[PVT<br/>生产验证]
    PVT --> G7[G7 量产评审]
    G7 --> MP[MP<br/>量产]
```

每个门应有**准入条件**与**退出条件**；未过不得进入下一阶段——这正是「硬门槛」思想，只是从个人自觉升级为组织制度。

## 3. 样机三轮：EVT / DVT / PVT

**A 级** — 三阶段的定义、数量区间、验证内容均已回原文逐段核对（见 [2026-09-30 - EVT-DVT-PVT 产业化流程（Kickmaker）](../../来源/2026-09-30%20-%20EVT-DVT-PVT%20产业化流程（Kickmaker）.md)）。

| | **EVT** | **DVT** | **PVT** |
|---|---|---|---|
| 全称 | Engineering Verification Test | Design Verification Test | Production Verification Test |
| 验证对象 | **技术方案可行性** | **产品设计** | **产线（制程）** |
| 样件形态 | "looks like" + "works like" 演示样机 | **真实量产模具/工装**，材料接近最终料 | 与量产件高度一致，**仍手工装配** |
| 用件 | 临时件：硅胶复模、3D 打印软模、PCBA 原型 | 真实模具件 | 试产线件 |
| 测试内容 | 全部 PRD 功能是否实现 | 跌落、耐热、磨损；**认证** | 工艺速度、质量、控制点、测试设备、校准、人员培训、包装、物流 |
| **典型数量** | **3 – 10 台** | **50 – 100 台** | **100 – 1000 台** |
| 出口 | 设计可行性确认 | 测试**正式归档**、设计规格冻结 | 试产线无失效 → 转量产 (MP) |

> [!note] 三者的差别是「验证什么」，不是「验证多少」
> EVT 验**设计能不能工作**，DVT 验**设计在真实条件下还成不成立**，PVT 验**工厂做不做得出来**。
> 原文对 PVT 的定性：*"more operationally focused than developmentally"*（比开发更偏运营）。

### 3.1 各阶段的现代约束

**B 级** — 来自 [2026-09-30 - NPI 流程 2025（Intretech）](../../来源/2026-09-30%20-%20NPI%20流程%202025（Intretech）.md)（厂商内容，结论段含推销；引用者须自行判断）。

| 阶段 | 新增压力 | 应对 |
|------|---------|------|
| EVT | 关键器件交期不可预测 | **把 EVT 同时当作供应链风险评估**；采购提前介入，识别高风险料与备选源 |
| DVT | 法规收紧（RoHS 3 / REACH 等） | 提前对全部目标市场做法规风险分析；**设计冻结前完成采购与合规检查** |
| PVT | 熟练工短缺 | **试产前**就开始培训与 SOP 准备；实时直通率与产线平衡数据 |
| MP | 物流中断；数字可追溯性要求 | 物流冗余；ERP 追溯批次与元器件批号 |

## 4. 各部门的介入点（C 级 — 编者综合）

> 来源只给出零散线索（原文明确提到「采购在 EVT 阶段提前介入」），完整介入表为编者构造。

| 部门 | 典型介入点 | 交付物 | 晚介入的代价 |
|------|-----------|--------|-------------|
| 市场 / 产品 | 立项前 | PRD、竞品、目标成本 | 做出来的东西没有市场 |
| 系统 / 架构 | 方案阶段 | 系统方案、板间接口定义 | 子系统之间对不上 |
| 结构 | 方案阶段起 | 外壳、装配、散热 | 板子放不进壳 |
| **采购 / 供应链** | **详细设计阶段** | AVL、长周期物料、替代料 | 长交期物料导致项目延期 |
| **制造 / NPI** | **布局评审起** | DFM/DFA 反馈、治具规划 | DFM 到最后才发现 → 返工 |
| 软件 / 固件 | 方案阶段起全程 | 固件、驱动 | 硬件回来了软件没准备好 |
| 质量 | 投板评审起 | 测试计划、可靠性方案 | 没有可复现的验收依据 |
| 认证 | 投板后 | CE / FCC / 3C / UL 报告 | 拿不到证不能卖 |
| 测试工程 | EVT 起 | ICT / FCT 治具 | 量产无法测试 |

> 两个最容易被低估的：**采购**（长交期物料的提前量）与**制造**（DFM 是**设计输入**，不是最后一道检查）。

## 5. 跨阶段的常设机制

### 5.1 设计输入 / 输出与追溯

两套体系的条款结构均已逐条核对（**A 级**）。

**ISO 9001:2015 §8.3** —— 六个子条款（见 [2026-09-30 - ISO 9001 设计开发子条款 8.3.1-8.3.6](../../来源/2026-09-30%20-%20ISO%209001%20设计开发子条款%208.3.1-8.3.6.md)）：

| 条款 | 名称 | 条目数 |
|------|------|--------|
| 8.3.1 | General（总则） | — |
| 8.3.2 | 设计和开发策划 | a)–j)，**10 条** |
| 8.3.3 | 设计和开发输入 | a)–e)，**5 条** |
| 8.3.4 | 设计和开发控制 | a)–f)，**6 条** |
| 8.3.5 | 设计和开发输出 | a)–d)，**4 条** |
| 8.3.6 | 设计和开发更改 | ⚠️ 标准正文无条目枚举 |

**ISO 13485:2016 §7.3** —— 十个子条款（见 [2026-09-30 - 设计控制与追溯（MedDeviceGuide）](../../来源/2026-09-30%20-%20设计控制与追溯（MedDeviceGuide）.md)）：

| 条款 | 名称 | 条款 | 名称 |
|------|------|------|------|
| 7.3.1 | General | 7.3.6 | 验证 (verification) |
| 7.3.2 | 策划 (planning) | 7.3.7 | 确认 (validation) |
| 7.3.3 | 输入 (inputs) | **7.3.8** | **设计转移 (transfer)** |
| 7.3.4 | 输出 (outputs) | 7.3.9 | 设计变更控制 |
| 7.3.5 | 评审 (review) | 7.3.10 | 设计文件 |

> **ISO 9001 §8.3.6 没有 a)–f) 式的条目清单**，正文是散文式要求（确定、评审、控制更改，防止对符合性产生不利影响）。某些解读文章会给出 a/b/c 分类，那是解读者的归纳，**不是标准条文**。
> 另：**若组织不从事设计，可在 QMS 范围中说明理由后声明 §8.3 不适用**（但过程验证、文件控制、变更管理仍归其他条款）。

#### 评审 / 验证 / 确认 —— 最容易混的一组

**A 级**（§8.3.4，含来源给出的可操作例子）：

| | 回答的问题 | 对象 | 落地做法示例 |
|---|---|---|---|
| **评审 Review** | 设计结果**能不能**满足要求？ | 阶段成果 | 复杂度高 → 正式评审会 + 纪要；复杂度低 → 计划上签注 + 签名 + 日期 |
| **验证 Verification** | 输出**是否满足**输入要求？ | 图纸 / 计算 / 模型 | 替代计算 · 与已验证的类似设计对比 · 试验与演示 · 放行前查文件 |
| **确认 Validation** | 最终产品在**预期使用条件下**是否满足需求？ | 实物 / 原型 | 营销或运营试验 · 使用条件下仿真 · 局部仿真（如抗震） · 客户试用反馈 |

> 三者**可以作为一个统一过程完成，也可以分开做**。

**追溯矩阵**：串起「需求 → 设计输出 → 验证/确认证据」。ISO 13485 §7.3.10 要求每条输入可追溯到输出与验证证据；**追溯链缺口是最常见的审计发现**。

> [!warning] 条款号不可跨行业套用
> ISO 9001 §8.3 / ISO 13485 §7.3 / IATF 16949 **条款号在同一脉络下，但要求深度不同**——医疗器械有 10 个子条款，汽车另走 APQP。
> 另：ISO 9001 中**日常制造过程控制归 §8.5，不归 §8.3**。

### 5.2 风险管理：FMEA

**B 级** — IEC 60812:2018 *Failure modes and effects analysis (FMEA and FMECA)*（首版 1985）；汽车业用 **AIAG & VDA FMEA Handbook**（2019-06 第 1 版，取代 AIAG FMEA 4th + VDA4）。

- 分类：**DFMEA**（设计）/ **PFMEA**（过程）/ **FMEA-MSR**（监测与系统响应）
- **七步法**：策划与准备（5T）→ 结构分析 → 功能分析 → 失效分析 → 风险分析 → 优化 → 结果文件化
- 关键变化：**AP（Action Priority，高/中/低）取代 RPN**——因为不同 S/O/D 组合可能算出相同 RPN 而实际风险不同
- 手册是**参考手册，非强制标准**；除客户特定要求（CSR）外不强制采用
- ISO 13485 §7.3.3 明确要求**风险管理输出作为设计输入**（引用 ISO 14971）

### 5.3 设计转移（Design Transfer）

ISO 13485 **§7.3.8** 是 **ISO 9001 没有对应条款**的一节：设计输出须被验证**适合制造**，且生产能力须被证明**能满足要求**，之后才能成为正式生产规格。转移内容通常包括装配图、采购规格、作业标准、制造指导书、检验/测试规格。

## 6. 与「设计流程」的对照（C 级 — 编者综合）

一条纯设计流程（需求 → 方案 → 原理图 → 布局 → 布线 → 出图 → 回板调试）在产品流程中的位置：

```mermaid
graph LR
    A[立项/PRD] --> B[方案评审]
    B --> C["详细设计<br/>（原理图·选型·仿真·布局·布线·Gerber）"]
    C --> D[投板评审]
    D --> E["回板调试<br/>= EVT 的开始"]
    E --> F[DVT]
    F --> G[PVT]
    G --> H[认证]
    H --> I[量产 MP]
    style C fill:#2d4a5a,color:#fff
    style E fill:#5a4a2d,color:#fff
```

**设计流程 ≈ 图中深色那一段**（详细设计），加上「回板调试」——而回板调试在完整流程里是 **EVT 的开端，不是终点**。

## 7. 按风险选配（C 级 — 编者综合）

流程完整度应与**产量 × 风险**成正比，不是全都要做：

| 场景 | 建议启用 |
|------|---------|
| 自用、非商用、年产几十片 | 设计流程 + 正式测试记录 + BOM 版本管理 |
| 消费电子、批量出货 | + 阶段门（方案/布局/投板三个）+ EVT/DVT/PVT + 认证 + DFM/DFA |
| 工业 / 车载 / 医疗 | + 全阶段门 + DFMEA + 全追溯 + IATF 16949 / ISO 13485 + 可靠性全套 + NPI |
| 汽车关键件 / 医疗三类 | + ASPICE + 功能安全（ISO 26262 / IEC 62304）+ 全生命周期可追溯 |

**投入产出比最高的三个增量**（编者判断）：

1. **加「投板评审」一道门** —— 成本最低，拦住的问题最多
2. **把「回板调试」拆成 EVT / DVT** —— 哪怕 DVT 只做温度循环 + 电压拉偏，也能拦住一批「常温能用、低温不复位」的板子
3. **让采购在设计阶段介入** —— 长交期物料是最容易导致延期、又最容易提前规避的风险
