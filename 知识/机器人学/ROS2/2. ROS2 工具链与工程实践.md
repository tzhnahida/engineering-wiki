# ROS2 工具链与工程实践

> [!note] 页面定位
> ROS2 基础闭卷考点速记（第 2 部分：CLI 工具、工作空间、launch、tf、常用工具与 ROS1 差异）。核心概念见 [1. ROS2 核心概念与通信机制](1.%20ROS2%20核心概念与通信机制.md)。

## 1. CLI 命令速查（填空/选择高频）

| 对象 | 查看 | 操作 |
|------|------|------|
| 节点 | `ros2 node list` / `info` | `ros2 run <包> <节点>` |
| 话题 | `ros2 topic list` / `echo` / `info` / `hz` / `bw` | `ros2 topic pub <话题> <类型> '<数据>'` |
| 服务 | `ros2 service list` / `type` | `ros2 service call <服务> <类型> '<请求>'` |
| 动作 | `ros2 action list` / `info` | `ros2 action send_goal <动作> <类型> '<目标>'` |
| 参数 | `ros2 param list` / `get` / `describe` | `ros2 param set <节点> <参数名> <值>` |
| 包 | `ros2 pkg list` / `create` / `executables` | — |
| 接口 | `ros2 interface show <类型>` | `ros2 interface package` |

- `ros2 topic hz`：话题发布频率；`ros2 topic bw`：**带宽占用**（统计消息尺寸与频率）
- `ros2 topic pub /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.5}, angular: {z: 0.2}}'`：发布速度指令的标准示例

## 2. 工作空间与功能包

**工作空间**（教材：机器人开发的大本营）：

```text
ros2_ws/
  src/            # 源码（功能包）
  build/          # 中间产物
  install/        # 安装目录
  log/            # 日志
```

- 创建与构建流程：`mkdir -p ros2_ws/src` → 放入功能包 → 根目录 `colcon build` → `source install/setup.bash`

**功能包**（教材：机器人功能分类）——ROS2 中功能的最小组织单元：

- 构建类型：`ament_cmake`（C++）、`ament_python`（Python）、`cmake` 混合
- 关键文件：`package.xml`（包清单：依赖声明）+ `CMakeLists.txt`（构建规则，C++ 包）+ `setup.py`（Python 包）
- 创建：`ros2 pkg create <包名> --build-type ament_cmake --dependencies rclcpp std_msgs`
- 自定义接口包：`ros2 pkg create <包名>_interfaces`，在 `CMakeLists.txt` 中配置 `rosidl_generate_interfaces`，接口文件放 `msg/`、`srv/`、`action/` 目录

## 3. Launch、命名空间与参数注入

- **Launch 文件三种写法**：XML / YAML / **Python**（最灵活，官方推荐）
- 功能：**一键启动多个节点**，同时可配置参数、重映射、命名空间
- 运行：`ros2 launch <包> <launch文件>`
- 参数注入三途径：YAML 文件、CLI（`--ros-args -p`）、节点代码内声明
- 重映射：`-r 原名称:=新名称`；命名空间：`-n /robot1`

## 4. tf 与坐标系管理

- **tf**：机器人**坐标系管理系统**——维护坐标变换树（TF tree），实现任意两坐标系间变换查询
- 静态变换（固定安装关系）vs 动态变换（随时间变化，如轮式里程计 odom→base_link）
- 高频概念对：`map`（全局地图系）、`odom`（里程计系，随漂移累积误差）、`base_link`（车体系）、`laser`/`base_scan`（传感器系）
- 查看：`ros2 run tf2_ros tf2_echo <父系> <子系>`；`view_frames` 生成变换树 PDF

## 5. 常用工具（教材第 3 章范围）

| 工具 | 用途 |
|------|------|
| Gazebo（新版 gz） | 机器人**仿真**平台（物理引擎 + 传感器仿真） |
| RViz2 | **可视化**工具（话题数据、TF、地图叠加显示） |
| rosbag2 | 话题数据**录制与回放**（`ros2 bag record/play`） |
| rqt | 图形化工具箱（rqt_graph 看节点话题关系图） |
| rqt_graph | 计算图可视化：节点 → 话题 → 服务关系 |

⚠️ 高频细节：rosbag2 回放失败常见原因是 **QoS 不兼容**（录时与播时 QoS 策略不同）。

## 6. 上层应用框架（选择/判断题常识）

- **Nav2**：移动机器人**自主导航**框架（地图→定位→全局规划→局部规划→避障）；动作通信的典型用户（`NavigateToPose` 动作）
- **MoveIt! / MoveIt2**：机械臂运动规划框架；配套语义描述文件 `.srdf`（RobotSemanticDescription）
- **URDF**（机器人模型描述，XML 格式）vs **SDF**（仿真描述格式）：URDF 用于描述机器人本体（连杆/关节/颜色 `<material>`），SDF 面向 Gazebo 场景；ROS2 常以 URDF + `robot_state_publisher` 发布 TF
- **micro-ROS**：面向 MCU 的 ROS2（仅支持 ROS2，不直接支持 ROS1）

## 7. ROS2 vs ROS1（简答高频）

| 维度 | ROS1 | ROS2 |
|------|------|------|
| 架构 | 有**主节点**（roscore，单点故障） | **无主节点**、去中心化 |
| 通信底层 | 自定义 TCP/UDP 协议 | **DDS**（工业标准，自带发现机制） |
| QoS | 无 | 完整 QoS 策略 |
| 实时性 | 弱 | 支持实时（配合 RT 内核） |
| 跨平台 | 仅 Ubuntu 主力 | Windows/macOS/Linux |
| 安全 | 弱 | 内置安全机制（DDS-Security） |
| 节点生命周期 | 简单 | 状态机化的生命周期节点 |

- 通信兼容性判断题：ROS1 与 ROS2 不能直接通信，但可通过 **ros1_bridge** 桥接（判断题陷阱："ROS1/ROS2 完全无法互通" = 错，存在桥接方案）
- DDS 解耦判断题陷阱："局域网发布话题必须知道对方 IP" = 错（DDS 自动发现）
- ROS2 典型发行版：Humble、Jazzy（以教材所用最新稳定版为准）

## 8. ROS2 与嵌入式/仿真的关系辨析（判断/选择高频）

> [!warning] 概念分层，勿混用
> - **DDS** = 底层通信**中间件**（Data Distribution Service，数据分发服务）
> - **ROS2** = 构建在 DDS 之上的**机器人软件开发框架**（通信模型抽象 + 工具链 + 生态库包）
> - **Gazebo** = 物理**仿真平台**
> - **RViz2** = **可视化**工具（不是仿真器）
> - **嵌入式固件** = 跑在 MCU 上的裸机/RTOS 程序

判断题速记：

- "ROS2 是机器人仿真软件" → **错**（仿真靠 Gazebo；"Gazebo + ROS2" 合起来才是仿真系统）
- "ROS2 是一个中间件" → 不严谨，考试填空标准答案是**机器人软件开发框架**；"ROS2 的底层通信中间件是 DDS" → 对
- "ROS2 是嵌入式固件" → 错（ROS2 运行在通用 OS 上，不跑 MCU 裸机）

嵌入式子系统接入 ROS2 的三种方式：

| 方式 | 说明 |
|------|------|
| 纯软件仿真 | MCU 控制逻辑直接写成 ROS2 节点 / Gazebo 插件 |
| 硬件在环 HIL | 真实 MCU 跑真实固件，经串口等桥接接入 |
| micro-ROS | MCU 上 RTOS 原生接入 ROS2 网络（仅支持 ROS2） |
