# ROS2 核心概念与通信机制

> [!note] 页面定位
> ROS2 基础闭卷考点速记（第 1 部分：核心概念与通信机制）。考点锚定胡春旭《ROS2智能机器人开发实践》第 2 章目录：工作空间、功能包、节点、话题、服务、通信接口、动作、参数、DDS、分布式通信。工具链见 [2. ROS2 工具链与工程实践](2.%20ROS2%20工具链与工程实践.md)。

## 1. 节点（Node）

**定义（填空题标准表述）**：执行具体任务的进程，独立运行的可执行文件，可使用不同编程语言，可分布式运行在不同主机，通过**节点名称**进行管理。

- 每个节点有唯一名称（重名自动加序号后缀）
- 多节点协作构成机器人系统；单进程多节点（组件）是 ROS2 特性之一
- 节点是 ROS2 中的最小执行单元

## 2. 话题（Topic）— 发布/订阅

- **模型**：发布者/订阅者（Publish/Subscribe），**异步**通信机制
- 发布者和订阅者都可以**不唯一**（多对多）
- **接口文件**：`.msg` 定义消息结构（如 `std_msgs/msg/String`、`geometry_msgs/msg/Twist`）
- 典型用法：传感器数据流（激光雷达 `/scan`）、速度指令 `/cmd_vel`、关节状态 `/joint_states`
- 高频判断/填空：**话题 = 发布/订阅 = 异步 = .msg 定义**

## 3. 服务（Service）— 请求/响应

- **模型**：客户端/服务器（C/S），**同步**通信机制
- **服务器唯一，客户端可不唯一**（一对多）
- **接口文件**：`.srv` 定义请求和应答两部分（`---` 分隔，上行 Request、下行 Response）
- 典型用法：一次性的查询与设置（开关灯、获取地图、保存参数）
- 与话题对比是简答高频题（见下表）

## 4. 动作（Action）— 带反馈的长任务

- **目的（教材原话口径）**：便于**对机器人某一完整行为的流程进行管理**——客户端发送目标（Goal），服务端执行并**周期反馈状态（Feedback）**，结束后反馈**结果（Result）**
- **并非新的底层通信机制**，而是**应用层机制**，底层基于话题和服务实现：
  - 发送运动目标 = 服务请求/响应（两个服务）
  - 反馈过程 = 一个话题的周期发布（服务端是发布者、客户端是订阅者）
- **接口文件**：`.action`，由三条横线（`---`）分隔为三部分：Goal / Result / Feedback
- 生命周期：客户端发 goal → 服务端接受/拒绝 → 执行并发布 feedback → 客户端等待 result 或发 cancel → 返回结果
- 典型用法：导航、机械臂运动等耗时任务
- ⚠️ 易错：某博客称动作是"同步通信"，与主流教材"动作 = 带反馈、可取消的长任务"表述不一致——**以教材为准**

## 5. 参数（Parameter）

- 教材比喻：**机器人系统的全局字典**——节点的配置项，可查询、可修改
- 属于特定节点；运行时通过服务机制读写
- 参数修改会产生 `/parameter_events` 事件
- 修改方式：启动时 `--ros-args -p name:=value` 覆盖，运行时 `ros2 param set` 修改

## 6. 通信接口（Interface）

| 通信方式 | 接口文件 | 分隔 | 内容 |
|----------|----------|------|------|
| 话题 | `.msg` | 无 | 消息结构 |
| 服务 | `.srv` | `---` | 上 Request / 下 Response |
| 动作 | `.action` | `---` ×2 | Goal / Result / Feedback |

- 接口需在 `CMakeLists.txt` 中配置 `rosidl_generate_interfaces` 自动生成代码
- 内置接口：`std_msgs`（基础类型）、`geometry_msgs`（Twist、Pose）、`sensor_msgs`（LaserScan、Image、Imu）、`nav_msgs`（Odometry、Path）

## 7. DDS 与 QoS

**DDS（Data Distribution Service，数据分发服务）**：ROS2 的底层通信内核——负责**节点发现、数据路由、可靠传输、QoS 策略**，实现**去中心化**的跨设备组网通信（无需主节点）。

**通信建立三条件**（高频考点）：最终名称相同 + 接口类型相同 + **QoS 兼容**。仅 `ros2 topic list` 能看到名称 ≠ 数据在流通。

**QoS 关键项**：

| 策略 | 取值 | 语义 |
|------|------|------|
| Reliability | RELIABLE / BEST_EFFORT | 可靠重传 vs 尽力而为 |
| Durability | VOLATILE / TRANSIENT_LOCAL | 新订阅者是否收到历史消息 |
| History | KEEP_LAST(n) / KEEP_ALL | 缓存条数 |
| Depth | n | 配合 KEEP_LAST |

- 传感器数据（数据量大、丢几帧无所谓）→ BEST_EFFORT；控制命令与关键状态 → RELIABLE
- 常用组合（⚠️ 存疑：来自期末速通文，未三票验证）：`/scan` = BEST_EFFORT + KEEP_LAST(5~10)；`/map` = RELIABLE + TRANSIENT_LOCAL（新订阅者能拿到已有地图）；`/cmd_vel` = RELIABLE + KEEP_LAST(1)

## 8. 四大通信机制对比（简答高频）

| 维度 | 话题 Topic | 服务 Service | 动作 Action | 参数 Parameter |
|------|-----------|-------------|-------------|----------------|
| 模型 | 发布/订阅 | C/S | C/S（应用层：2 服务+1 话题） | 节点配置字典 |
| 同步性 | 异步 | 同步 | 长任务 + 周期反馈 | — |
| 多方性 | 多对多 | 一对多（服务器唯一） | 一对多 | 节点私有 |
| 接口文件 | .msg | .srv | .action | — |
| 适用 | 持续数据流 | 一次性问答 | 可反馈可取消的长任务 | 配置与运行时调整 |

**场景选型**（选择题高频）：激光数据 → 话题；查询/开关 → 服务；导航/机械臂运动 → 动作；参数配置 → 参数。

## 9. 名称、命名空间与重映射

- 节点内部相对名称（如 `chatter`）+ 命名空间 → 最终名称（节点位于 `/robot1` 命名空间时，话题最终名为 `/robot1/chatter`）
- 以 `/` 开头的**绝对名称**不随命名空间变化
- **重映射（remap）**：启动时 `--ros-args -r 旧名:=新名`
- 多实例部署：相对名称 + 不同命名空间
