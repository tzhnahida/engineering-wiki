# UART 串行通信

> UART (Universal Asynchronous Receiver-Transmitter) 是最古老的数字通信接口之一，起源于 1960 年代的电传打字机 (Teletype)。它是**异步**串行协议——无需共享时钟线，收发双方约定好波特率即可通信。USART 是其同步增强版，多了可选的时钟线。

## 1. 与其他总线对比

| 特性 | UART | I²C | SPI |
|------|------|-----|-----|
| 时钟线 | ❌ 异步 | ✅ SCL | ✅ SCK |
| 线数 | 2 (TXD+RXD) + 可选流控 | 2 (SCL+SDA) | 4 + N×SS |
| 全双工 | ✅ | ❌ 半双工 | ✅ |
| 一对多 | ❌ 需总线驱动器 | ✅ 多从 | ✅ 多片选 |
| 最远距离 | ~15m (RS-232) / 1200m (RS-485) | <1m (板上) | <0.3m (板上) |
| 帧错误检测 | ✅ Parity | ❌ | ❌ |
| 标准 | ❌ (RS-232 仅物理层) | ✅ UM10204 | ❌ |

## 2. 物理层

### 2.1 信号定义

| 信号 | 方向 | 功能 |
|------|------|------|
| **TXD** | 发送端 → 接收端 | 发送数据 |
| **RXD** | 接收端 ← 发送端 | 接收数据 |
| **RTS** | 发送端 → 接收端 | 请求发送 (硬件流控) |
| **CTS** | 接收端 → 发送端 | 允许发送 (硬件流控) |
| **GND** | 共地 | 必须共地——异步 = 无时钟参考，靠地电平 |

### 2.2 电平标准

UART 本身只定义**协议**，不定义**电平**。常见物理层：

| 标准 | 逻辑 0 (Space) | 逻辑 1 (Mark) | 空闲状态 | 备注 |
|------|---------------|---------------|----------|------|
| **TTL/CMOS** | 0V | 3.3V/5V | 高 | MCU 引脚直连 |
| **RS-232** | +3V ~ +15V | −3V ~ −15V | 负 | 需 MAX232 电平转换 |
| **RS-485** | A−B > +200mV | A−B < −200mV | — | 差分，工业长距离 |
| **RS-422** | 类似 RS-485 | 类似 RS-485 | — | 全双工差分 |

> [!warning] TTL UART 与 RS-232 电平**反相**且电压范围不同，直接连接会损坏 MCU。必须用 MAX232/MAX3232/SP3232 等转换芯片。

### 2.3 交叉连接 (Null Modem)

两个 MCU 直连时，TXD ↔ RXD 交叉：

| MCU-A | 方向 | MCU-B |
|-------|------|-------|
| TXD | → | RXD |
| RXD | ← | TXD |
| GND | — | GND |
| RTS | → | CTS (可选) |
| CTS | ← | RTS (可选) |

## 3. 帧格式

UART 数据以**帧**为单位传输。一帧包含：

<!-- 图示缺失:原 SVG 未入库 -->

| 字段 | 位数 | 说明 |
|------|------|------|
| **Start Bit** | 1 | 必须为低电平（Space），同步帧的开始 |
| **Data Bits** | 5-9 | 先传 LSB (LSB-first)，数据长度可选 |
| **Parity Bit** | 0-1 | 可选的错误检测位 |
| **Stop Bit(s)** | 1/1.5/2 | 必须为高电平（Mark），确保下一帧 Start 有下降沿 |

### 3.1 奇偶校验

| 类型 | 算法 | 用途 |
|------|------|------|
| **None (N)** | 无校验位 | 最高效 |
| **Odd (O)** | Parity = ~(data XOR sum) 使 1 的总数为奇 | 一般 |
| **Even (E)** | Parity = data XOR sum 使 1 的总数为偶 | 一般 |
| **Mark (M)** | 校验位始终为 1 | 少见 |
| **Space (S)** | 校验位始终为 0 | 少见 |

### 3.2 常用配置

| 描述 | 缩写 | 位数 |
|------|------|------|
| 8 数据 + 无校验 + 1 停止 | **8N1** | 10 bits/byte |
| 8 数据 + 偶校验 + 1 停止 | **8E1** | 11 bits/byte |
| 7 数据 + 偶校验 + 1 停止 | **7E1** | 10 bits/byte |

> [!note] 8N1 是嵌入式开发中最常用的配置，效率最高 (80% payload ratio)。

## 4. 波特率与误差

**波特率 = 每秒传输的符号数**（对 UART 而言等于 bit rate）。

| 波特率 | 每 bit 时间 | 用途 |
|--------|------------|------|
| 9600 | 104 µs | 旧式设备、GPS 模块默认 |
| 115200 | 8.7 µs | 最常用的高速 UART |
| 921600 | 1.09 µs | MCU 间高速传输 |
| 1 Mbps+ | <1 µs | USB-UART 桥 (CP2102/FT232) |

### 4.1 时钟容差

异步通信的关键约束：**收发双方的波特率必须足够接近**。

- 接收方在 Start Bit 下降沿**同步**，随后以本地时钟 16× 过采样检测每个 bit 的中点
- 10-bit 帧 (8N1) 允许的累计误差约 ±5%
- 实际 MCU 波特率误差通常 < 2%（受限于晶振精度和分频器分辨率）

```
MCU 时钟 72 MHz → 波特率 115200 = 72000000 / (16 × 39.0625)
                               ≈ 39 (误差 0.16%) ✅
MCU 时钟 8 MHz  → 波特率 115200 = 8000000 / (16 × 4.34)
                               ≈ 4 (误差 8.5%) ❌ 超过容差
```

> [!warning] 非标准晶振频率可能导致某些波特率无法精确匹配。8 MHz 晶振无法实现 115200，但 7.3728 MHz (0% 误差) 和 11.0592 MHz (0% 误差) 是经典的 "UART 友好" 频率。

## 5. 流控

当接收方处理速度跟不上发送速率时，需要流控避免 FIFO 溢出和数据丢失。

### 5.1 硬件流控 (RTS/CTS)

```
发送方: 检查 CTS 是否为低 → 发送数据
        若 CTS 拉高 → 暂停发送
接收方: 接收 FIFO 快满时拉高 RTS → 通知对方暂停
        处理完后拉低 RTS → 恢复
```

- 需要额外 2 根信号线 (RTS + CTS)
- 反应速度快，适合高速传输

### 5.2 软件流控 (XON/XOFF)

| 字符 | 值 | 含义 |
|------|-----|------|
| XOFF | 0x13 (DC3) | 暂停发送 |
| XON | 0x11 (DC1) | 恢复发送 |

- 使用数据流中的带内信令——0x11 和 0x13 不能作为数据出现
- 无需额外信号线，但二进制数据传输会出错（因为数据可能恰好等于 XON/XOFF）

## 6. 常见问题

| 问题 | 原因 | 对策 |
|------|------|------|
| 乱码 | 波特率不匹配 | 两端确认波特率配置 |
| 帧错误 (FE) | Stop bit 不是高电平 | 波特率偏差过大 |
| 奇偶错误 (PE) | Parity 不匹配 | 确认校验设置 (N/O/E) |
| 溢出错误 (OE) | 接收 FIFO 溢出 | 开启硬件流控或提高处理优先级 |
| 数据漏字 | 未开流控，缓冲区过小 | 增大 FIFO 或开启 DMA |
| 电平不匹配 | TTL ↔ RS-232 直连 | 加 MAX3232 转换芯片 |
