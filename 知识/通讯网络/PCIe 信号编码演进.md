# PCIe 信号编码演进

## 一句话

**PCIe 6.0 不是 PCIe 5.0 的"两倍速"，而是从 NRZ 时代进入了 PAM4 + FLIT + FEC 的系统级容错时代。**

## 代际对比

| | PCIe 5.0 | PCIe 6.0 |
|---|---|---|
| 速率 | 32 GT/s | 64 GT/s |
| 信号编码 | NRZ（2 电平） | PAM4（4 电平） |
| 每 UI 比特 | 1 bit | 2 bit |
| 数据组织 | 传统 TLP | FLIT（固定大小单元） |
| 纠错机制 | 基本依赖物理层 | FEC 前向纠错 + CRC 兜底 |
| 设计哲学 | 让波形足够干净 | 接受波形更脆弱，用编码和纠错拉回来 |

## NRZ vs PAM4 核心差异

### NRZ（Non-Return-to-Zero）
- 两个电平：高 = 1，低 = 0
- 优点：电平间隔大、噪声裕量充足、判决简单
- 缺点：想翻倍速率就得让信号翻转更快，对通道高频损耗、抖动、反射要求更高

### PAM4（4-Level Pulse Amplitude Modulation）
- 四个电平：每个符号代表 2 bit（00/01/10/11）
- 优点：相同符号时间内传一倍信息，不必把电气带宽压力直接翻倍
- 代价：**电压裕量被压缩，噪声容忍度降低**——原来一个大眼睛变成三个小眼睛

> [!tip] 直觉理解
> NRZ 是两层楼，站在哪层很容易看清；PAM4 是四层楼，楼层间距更近，地板一晃、灯光一暗、标识一偏，就容易认错。

## 为什么必须配套 FEC + CRC + FLIT

PAM4 单独用是不够的。PCIe 6.0 不再把"原始链路必须非常干净"作为唯一前提，而是**接受 PAM4 带来更高原始误码风险，用纠错机制控制最终错误**。

### FEC（Forward Error Correction，前向纠错）
- 在数据层加入冗余信息
- 接收端发现有限错误时自行修正，不必立刻请求重传
- 类比：给链路配一个"实时纠错医生"

### CRC（Cyclic Redundancy Check）
- FEC 不是无限纠错——错误太多也扛不住
- CRC 负责兜底检测：FEC 修小错，CRC 发现修不了的大错

### FLIT（Fixed-size Transfer Unit）
- 固定大小传输单元
- FEC/CRC 在规则数据块上运行效率高
- 让 PCIe 6.0 的协议组织方式与 PCIe 5.0 明显不同

## 对 SI/PI 工程的实践影响

### 眼图分析升级
- PAM4 眼图是三个眼睛，不是看一个眼开不开
- 还要看：**RLM**（电平线性度）、**SNDR**、不同眼之间的 margin、接收端判决门限

### BER 不能只看物理层
- FEC 隔在中间：原始误码 ≠ 系统暴露的错误
- 要追问：错误发生在 FEC 前还是后？FEC 纠正了多少？有没有接近 FEC 能力边界？

### Debug 从波形指标扩展到系统指标
- 还要看 FLIT 错误、FEC correction count、uncorrectable error、重训练行为、Retimer 状态
- 示波器和 VNA 仍然重要，但**协议分析和状态计数也更加重要**

### PI（电源完整性）更敏感
- PAM4 电平间距小 → 电源噪声、参考电压扰动、PLL jitter 更容易压缩判决窗口
- PCIe 6.0 的问题不一定全是"通道太差"，也可能是电源噪声把本来就紧的 PAM4 窗口进一步压缩

## 比喻总结

> PCIe 5.0 是开高速——速度快，但要道路平、车道清楚、轮胎好。
> PCIe 6.0 是开赛车——更快但不稳定，必须配空气动力学、传感器、电子稳定系统、安全气囊。
> 工程语言：PAM4 负责高效率，FEC/CRC/FLIT 负责把风险收住。

## 对 DDR 工程师的启发

DDR 目前仍以 NRZ 为主，更关注低功耗、低延迟、DQS-DQ 相位、Vref margin。PCIe/SerDes 已经走向 PAM4 + FEC。这不是谁先进谁落后，而是**两类系统的约束不同**。

高速信号正在分叉：
- **并行存储路线**（DDR/LPDDR）：极低延迟、多线并行、严格时序
- **串行互连路线**（PCIe/SerDes）：高阶调制、纠错编码、协议容错
