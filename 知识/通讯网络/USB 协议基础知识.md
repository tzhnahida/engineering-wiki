# USB 协议基础知识

## 一句话

**USB 不是简单的串口线，而是一套由主机统一管理的分层通信协议——设备接入后先通过描述符"自我介绍"，主机枚举建档后，双方才通过端点进行真正的数据传输。**

## 基本角色

| 角色 | 职责 | 常见实例 |
|------|------|----------|
| **Host（主机）** | 总线管理者：供电、检测插入、发起通信、分配地址、加载驱动 | PC、工控机、手机 OTG、嵌入式 Linux |
| **Device（设备）** | 被管理的外设：按协议回答主机询问 | U盘、键盘、CDC 虚拟串口、摄像头 |

> [!important] 所有通信由主机发起
> 即使设备想发送数据，也必须等主机来询问或调度。这是 USB 与 UART 的根本区别。

## 物理端口 vs 逻辑端点

USB 有**两层"端口"**概念，初学者容易混淆：

| 概念 | 是什么 | 例子 |
|------|--------|------|
| **物理端口** | 看得见摸得着的 USB 接口 | USB-A、USB-C、Micro USB |
| **逻辑端点 (Endpoint)** | 设备内部用于数据传输的逻辑通道 | EP0、EP1 IN、EP2 OUT |

> [!tip] 办公楼比喻
> - USB 设备 = 整栋楼
> - Interface（接口）= 不同部门
> - Endpoint（端点）= 每个部门收发文件的窗口
>
> 电脑不是随便往设备写数据，而是往**某个端点**发送/读取数据。

### STM32F103 USB 引脚

```
PA11 = USB_DM (D-)
PA12 = USB_DP (D+)
```

全速设备通过 **D+ 上拉电阻** 告诉主机："有一个全速设备接入了"。

## 速度等级

| 等级 | 英文 | 速率 | 典型应用 |
|------|------|------|----------|
| 低速 | Low Speed | 1.5 Mbps | 鼠标、键盘 |
| **全速** | **Full Speed** | **12 Mbps** | CDC、HID、MCU USB |
| 高速 | High Speed | 480 Mbps | U盘、摄像头、网卡 |
| 超高速 | SuperSpeed | 5 Gbps+ | 高速存储、扩展坞 |

> [!warning] STM32F103 是 Full Speed（12 Mbps），不能做 High Speed

**USB 时钟必须精确 48 MHz**。STM32F103 常见配置：HSE 8 MHz → PLL 倍频到 72 MHz → USB 时钟 = PLL / 1.5 = 48 MHz。时钟不准会导致「无法识别」「设备描述符请求失败」「Code 43」。

## 枚举流程

枚举 = 主机对设备进行"身份调查和建档登记"。设备插入后不能马上通信，必须先完成枚举。

1. 主机检测 D+ 上拉 → 知道有设备接入
2. 主机复位 USB 总线
3. 设备进入默认地址 0
4. 主机读取设备描述符前 8 字节 → 知道 EP0 最大包长
5. 主机分配新 USB 地址
6. 主机读取完整设备描述符
7. 主机读取配置描述符
8. 主机读取接口、端点、字符串等描述符
9. 主机根据描述符加载对应驱动
10. 主机设置配置 → 设备进入可用状态

> [!warning] 任一步失败 = 枚举失败
> 常见 Windows 报错：代码 10（设备无法启动）、代码 43（已停止）、「请求 USB 设备描述符失败」。

## 描述符体系

描述符是 USB 设备给主机看的"说明书"。层级结构：

- **Device Descriptor** — 整个设备：USB版本、VID/PID、设备版本、多少配置
  - **Configuration** — 一个配置：电流需求、接口数量
    - **Interface** — 一个功能单元：USB Class、几个端点
      - **Endpoint** — 数据传输通道：方向、类型、最大包长

### 设备描述符

告诉主机"我是谁"：协议版本、设备类别、**VID/PID**、设备版本号、支持几个配置。

### 配置描述符

告诉主机"我需要什么资源"：配置总长度、接口数量、供电方式（Bus/Self Powered）、最大电流（如 100 mA）。

> 普通 MCU USB 设备通常只有一个配置。

### 接口描述符

告诉主机"我有什么功能"：第几个接口、USB Class（HID/CDC/MSC...）、几个端点、使用什么协议。**主机根据接口 Class 加载驱动。**

### 端点描述符

告诉主机"数据怎么传"：

| 字段 | 说明 |
|------|------|
| 端点地址 | 最高位 = 方向（0=OUT, 1=IN） |
| 传输类型 | Control/Bulk/Interrupt/Isochronous |
| 最大包长 | Full Speed: Bulk 最大 64B, Interrupt 最大 64B |
| 轮询间隔 | Interrupt/Isochronous 端点有效 |

### 字符串描述符

人类可读信息：厂商名、产品名、序列号。需以 **UTF-16LE** 格式返回。如果协议栈只按单字节 ASCII 转换而写了 UTF-8 中文→显示乱码。

## 端点 0 — 默认控制端点

**每个 USB 设备必须具备端点 0。** 枚举过程完全依赖它：

- 接收标准请求（GET_DESCRIPTOR / SET_ADDRESS / SET_CONFIGURATION）
- 返回设备描述符、配置描述符
- 处理类请求、厂商自定义请求

端点 0 是**双向控制端点**（既能 IN 也能 OUT）。端点 0 不正常 → 设备无法枚举。

## 端点地址命名

**IN/OUT 以主机为视角**——这是初学者最容易搞反的地方：

| 地址 | 方向（主机视角） | 实际数据流 |
|------|-----------------|-----------|
| `0x81` | IN — 主机读取 | 设备 → 主机 |
| `0x02` | OUT — 主机写出 | 主机 → 设备 |
| `0x83` | IN — 主机读取 | 设备 → 主机 |

```
地址最高位 = 1 表示 IN（设备→主机）
地址最高位 = 0 表示 OUT（主机→设备）
```

## 四种传输类型

| 类型 | 可靠性 | 延时保证 | 典型应用 |
|------|--------|----------|----------|
| **Control** | 高（有握手） | 无 | 枚举、设备管理 |
| **Bulk** | 高（有握手） | 无 | U盘、CDC 数据 |
| **Interrupt** | 高 | 有（周期性） | 键盘、鼠标、CDC 通知 |
| **Isochronous** | 低（弱重传） | 有（固定带宽） | 音频、视频 |

> [!note] Interrupt 传输不是 MCU 中断
> 这是 USB 协议的一种传输调度方式——主机周期性地查询设备端点。

## USB Class — 免驱的关键

| Class | 名称 | 常见设备 |
|-------|------|----------|
| **CDC** | 通信设备类 | 虚拟串口、调制解调器 |
| **HID** | 人机接口设备 | 键盘、鼠标、自定义 HID |
| **MSC** | 大容量存储 | U盘、读卡器 |
| **DFU** | 固件升级 | USB 升级设备 |
| Audio | 音频类 | USB 声卡、麦克风 |
| Video | 视频类 | USB 摄像头 |
| RNDIS/ECM/NCM | 网络类 | USB 网卡 |

使用标准 Class = Windows 已有驱动，开发者不需要自己写驱动。

## CDC ACM 实战拆解

CDC ACM 虚拟串口是 MCU 项目最常见的 USB 应用。一个 CDC ACM 设备的结构：

- **Device Descriptor**
  - **Configuration**
    - **Interface 0**: 通信控制接口（处理波特率/DTR/RTS）
      - EP 0x83 IN (Interrupt) — 通知串口状态
    - **Interface 1**: 数据接口（收发串口数据）
      - EP 0x02 OUT (Bulk) — 主机→设备
      - EP 0x81 IN (Bulk) — 设备→主机

当电脑串口助手发送数据 → 数据通过 **Bulk OUT 端点 (0x02)** 到达设备。  
当 MCU 回传数据 → 数据通过 **Bulk IN 端点 (0x81)** 发送给电脑。

> [!tip] CDC 的波特率是虚拟概念
> USB 传输本身不依赖 UART 波特率。波特率只是为了兼容传统串口软件——`SET_LINE_CODING` 请求设置波特率/停止位/校验位，但实际数据通过 USB Bulk 传输。

## USB 请求类型

通过端点 0 控制传输完成：

| 类型 | 用途 | 示例 |
|------|------|------|
| **标准请求** | 所有设备必须支持 | GET_DESCRIPTOR、SET_ADDRESS、SET_CONFIGURATION |
| **类请求** | 与 USB Class 相关 | CDC: SET_LINE_CODING（设置波特率）、SET_CONTROL_LINE_STATE（DTR/RTS） |
| **厂商自定义** | 开发者自定义 | 读版本号、进入升级模式、控制 LED |

## VID/PID

- **VID** = Vendor ID（厂商 ID）
- **PID** = Product ID（产品 ID）

电脑通过 VID/PID 识别不同厂商和产品。**正式量产必须使用合法申请的 VID/PID**。学习测试可用示例值，但不要用于商业量产。

> [!warning] 多个设备使用相同 VID/PID + 相同序列号 → Windows 可能把它们当成同一设备，导致驱动/COM 号/缓存混乱。

## USB Device 开发常见错误

| 错误 | 现象 | 解决 |
|------|------|------|
| USB 时钟 ≠ 48 MHz | 枚举失败 | HSE 8M → PLL 72M → USB = /1.5 |
| D+/D- 接反 | 无法识别 | PA11=D-, PA12=D+ |
| D+ 上拉缺失 | 主机检测不到设备 | 加入 1.5kΩ 上拉到 3.3V |
| 固定上拉 | 复位后无法重新枚举 | 软件模拟断开：初始化前拉低 PA12 20~100ms |
| 描述符长度不匹配 | 枚举失败或驱动加载异常 | 配置总长度/接口数/端点数必须一致 |
| 端点地址不一致 | 数据传输异常 | 代码与描述符中的地址必须一致 |
| 中断未进协议栈 | 设备无响应 | USB IRQ 中必须调用协议栈处理函数 |
| HAL 与第三方协议栈冲突 | 寄存器状态混乱 | 只能有一个操作 USB 外设 |
| 字符串编码错误 | 显示乱码 | 中文需 UTF-16LE，协议栈要能正确转换 |
| PMA 配置错误 | 描述符/数据异常 | STM32 FSDEV PMA 端点缓冲区分配需正确 |

## 学习路线

1. 理解 Host 和 Device
2. 理解枚举过程
3. 理解描述符（Device → Config → Interface → Endpoint）
4. 理解端点和 IN/OUT 方向
5. 理解四种传输类型
6. 动手做 CDC 虚拟串口 — 最推荐入门
7. 再做 HID 自定义设备
8. 最后学 MSC/DFU/Audio/Video

> [!tip] 推荐从 STM32F103 + CherryUSB CDC ACM 开始
> 它能同时覆盖：设备描述符、配置描述符、接口描述符、端点描述符、控制传输、Bulk 传输、类请求、驱动加载、数据收发——几乎涵盖 USB Device 开发所有核心概念。
